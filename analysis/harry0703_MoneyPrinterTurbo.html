1. 강점 (Strengths)

  1. 광범위한 LLM/TTS 통합: LiteLLM을 중심으로 OpenAI, DeepSeek, Gemini, Ollama, Qwen, Azure, Moonshot 등 15개 이상의 LLM 제공자를 단일 인터페이스로 지원. TTS도 Edge-TTS, Azure Cognitive Speech, OpenAI TTS, MiMo 등 다중 공급자를 지원하여 벤더 종속성 최소화.

  2. 명확한 MVC 계층 분리: controllers/(HTTP 처리) → services/(비즈니스 로직) → models/(Pydantic 스키마) 계층이 명확히 분리되어 있으며, Pydantic을 통한 강타입 요청/응답 검증이 이루어짐.

  3. 경로 순회 방어 구현: file_security.py에서 os.path.realpath + os.path.commonpath 조합으로 경로 순회 공격을 방어하는 화이트리스트 기반 경로 검증이 명시적으로 구현되어 있음.

  4. 이중 배포 전략 (CPU/GPU): 표준 Dockerfile 외에 Dockerfile.gpu와 별도 docker-compose.gpu.yml을 제공하여 GPU 가속 환경에서의 faster-whisper 활용을 지원. 미러 레지스트리(Aliyun, Tsinghua) 폴백 로직으로 중국 환경 가용성 확보.

  5. 확장 가능한 태스크 큐: InMemoryTaskManager와 RedisTaskManager를 동일 인터페이스(TaskManager 베이스 클래스)로 추상화하여 배포 규모에 따라 전환 가능한 아키텍처를 채택.

2. 위험/개선 필요 사항 (Risks & Improvement Areas)

  1. API 인증 부재 (Critical): FastAPI 백엔드에 인증/인가 미들웨어가 없음. 포트 8080이 외부에 노출될 경우 누구든 영상 생성 작업을 제출하고 API 키를 소비할 수 있음. Bearer 토큰 또는 API 키 헤더 검증이 필요함.

  2. API 키 평문 저장: config.toml에 Pexels, Pixabay, OpenAI 등의 API 키가 평문으로 저장됨. 환경 변수 오버라이드 지원이 일부 있으나, HashiCorp Vault, AWS Secrets Manager, 또는 최소한 .env 파일 분리 가이드가 없음.

  3. CI/CD 워크플로우 전무: .github/workflows/ 디렉터리에 워크플로우 파일이 없음. 코드 병합 시 자동화된 린팅, 테스트, 보안 스캔이 수행되지 않아 품질 게이트가 없음. 의존성 취약점 스캔(Dependabot/Snyk)도 미설정.

  4. 거대 단일 파일 (webui/Main.py, 1,368줄): Streamlit UI 전체 로직이 단일 파일에 집중되어 있어 유지보수성이 낮고 기능 단위 테스트가 불가능함. 페이지별 모듈 분리가 필요함.

  5. 영속적 스토리지 미비: 태스크 상태와 결과물이 로컬 파일시스템에만 저장됨. 컨테이너 재시작 시 데이터 유실 위험이 있으며, 볼륨 마운트 의존이 명시적이지 않음. DB(SQLite/PostgreSQL) 기반 태스크 상태 관리 도입이 필요함.

Step 4. 아키텍처 분석

진입점: - API 서버: main.py → uvicorn.run("app.asgi:app", port=8080) - Web UI: streamlit run webui/Main.py (포트 8501)

계층 구조:

[HTTP Request]
      ↓
[app/controllers/v1/video.py]  ← Pydantic 입력 검증
      ↓
[app/controllers/manager/]     ← 태스크 큐 (Memory/Redis)
      ↓
[app/services/task.py]         ← 파이프라인 오케스트레이션
      ↓
[app/services/{llm,voice,material,subtitle,video}.py]
      ↓
[외부 API / 로컬 파일시스템]

아키텍처 패턴: MVC (Model-View-Controller). 단, View는 별도 Streamlit 프로세스로 분리.

상태 관리: services/state.py의 BaseStateManager → InMemoryStateManager 또는 RedisStateManager. 태스크 ID(UUID) 기반으로 상태 추적.

컴포넌트 통신: Streamlit UI → FastAPI REST API (HTTP) → 서비스 레이어 (동기 함수 호출). 비동기 메시지 큐 없음, 태스크는 스레드풀 내 동기 실행.

의존성 주입: 없음. 서비스 레이어는 직접 임포트로 호출되며, sm.state 싱글톤으로 상태 매니저를 공유.
