3.2 알려진 위험 요소 / Known Risk Factors

1. API 인증 비활성화 (Critical)

app/controllers/v1/video.py 37~38행:

# 인증 의존항이 주석 처리되어 있음
# router = new_router(dependencies=[Depends(base.verify_token)])
router = new_router()

인증 코드는 구현되어 있으나 의도적으로 비활성화되어 있다. 기본 설정에서 API 엔드포인트(/api/v1/videos, /api/v1/tasks 등)는 인증 없이 누구나 접근 가능하다. LLM API Key 소모 및 태스크 큐 포화(DDoS) 위험이 있다.

2. CORS 와일드카드 허용 (High)

app/asgi.py 57행:

origins = cors_allowed_origins_str.split(",") if cors_allowed_origins_str else ["*"]

환경변수 CORS_ALLOWED_ORIGINS 미설정 시 모든 출처(*)가 허용된다. 프로덕션 환경에서는 반드시 명시적 출처 제한이 필요하다.

3. 파일 경로 탐색 공격 — 방어 구현됨 (Mitigated)

app/utils/file_security.py에 resolve_path_within_directory() 함수가 구현되어 있으며, 파일 다운로드·스트리밍·업로드 엔드포인트에서 모두 호출된다. Path Traversal 공격에 대한 방어가 코드 수준에서 적용되어 있다.

4. TLS 인증서 검증 — 기본 활성화 (OK)

config.example.toml의 tls_verify = true로 기본 설정되어 있다.

5. 비밀값 관리 — 설정 파일 기반 (Review Required)

모든 API Key(OpenAI, Pexels, Azure 등)는 config.toml 파일에 평문으로 저장된다. .gitignore에 config.toml이 포함되어 있어 소스 노출 방지는 되어 있으나, 환경 변수 기반(12-Factor) 또는 시크릿 관리 시스템(Vault, AWS SSM 등)으로의 전환이 상용 환경에서 권장된다.

6. 배경음악 업로드 — 파일 확장자 검증만 실시 (Review)

BGM 업로드는 확장자(.mp3)만 검증하며, MIME 타입 또는 파일 매직 바이트 검증은 없다.

시나리오 B — g4f 포함 배포 (위험) uv sync --extra g4f를 실행하여 g4f가 설치된 Docker 이미지를 고객에게 배포하거나 SaaS로 제공하는 경우, GPL-3.0 조건에 따라 전체 소프트웨어의 소스코드 공개 의무가 발생할 수 있다. 상용 배포 시 g4f를 완전히 제외해야 한다.

AGPL 전파 위험: 현재 주요 의존성에 AGPL 라이선스 패키지는 확인되지 않아 SaaS 배포에 따른 AGPL 소스 공개 의무는 없다.
