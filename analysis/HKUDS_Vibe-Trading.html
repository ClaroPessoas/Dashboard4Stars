Step 1. 목적 및 범위 (Purpose and Scope)

Vibe-Trading은 홍콩과학기술대학교 데이터사이언스 연구실(HKUDS)에서 오픈소스로 개발 중인 AI 기반 금융 리서치 및 트레이딩 플랫폼이다.

  • 해결하는 문제: 퀀트 연구자·트레이더가 AI 에이전트를 통해 시장 조사, 알파 팩터 검증, 백테스트, 라이브 트레이딩 감시를 단일 플랫폼에서 처리할 수 있도록 한다.
  • 대상 사용자: 퀀트 애널리스트, 개인 트레이더, 금융 리서처, AI 에이전트 연구자
  • 분류: 복합 플랫폼 — CLI 툴킷 + FastAPI 백엔드 + React 프론트엔드 + MCP 서버
  • 현재 버전: 0.1.10 (개발 상태: Beta)

강점 (Strengths)

  1. 극도로 넓은 기능 범위: 퀀트 리서치(452종 알파), 7종 백테스트 엔진, 10종 브로커 연동, 16종 IM 채널, 18종 데이터 소스를 단일 플랫폼에서 통합 — 업계에서 이 수준의 통합 오픈소스 플랫폼은 희귀하다.

  2. AST 기반 알파 안전 게이트: test_alpha_purity.py와 test_lookahead.py의 자동 정적 분석 테스트는 알파 팩터 기여 시 사이드이펙트 및 미래 정보 누출을 코드 레벨에서 차단하는 강력한 안전망이다.

  3. 프로덕션 수준 컨테이너화: 멀티스테이지 Dockerfile, 비루트 사용자, 헬스체크, named volume 분리까지 갖춘 Docker 구성은 즉시 배포 가능한 수준이다.

  4. 다중 LLM 프로바이더 지원: 13종 LLM 프로바이더를 추상화하여 벤더 종속 없이 교체 가능하며, 스트리밍 장애 복구 로직까지 포함되어 있다.

  5. 풍부한 문서화 및 다언어 지원: 113KB README + 4개 언어 번역 + SKILL.md 매니페스트 + AI 기여자 가이드 등, 오픈소스 프로젝트로서 매우 높은 문서화 수준이다.

위험 및 개선 필요 사항 (Risks & Improvements)

  1. 거대 단일 파일 문제: api_server.py (138KB), mcp_server.py (70.8KB), cli/_legacy.py (206KB), agent/src/agent/loop.py (62KB)는 유지보수성과 테스트 격리를 저해한다. 점진적 모듈 분리가 필요하다.

  2. 테스트 커버리지 불투명: CI 파이프라인에서 커버리지를 측정하지만 최소 목표치(e.g., 80%)를 강제하지 않으며, 전체 커버리지 수치가 공개되어 있지 않다. 핵심 에이전트 루프의 실제 커버리지가 불확실하다.

  3. 자동화된 의존성 취약점 스캔 부재: Dependabot, Renovate, Snyk 등의 자동 취약점 스캔 및 의존성 업데이트 봇 설정이 확인되지 않는다. 수십 개의 외부 라이브러리가 포함된 규모에서는 자동 스캔이 필수적이다.

  4. 라이브 트레이딩 리스크 관리: 10종 브로커 연동과 라이브 트레이딩 기능을 제공하지만 버전이 여전히 v0.1.10 베타다. PreTradeAdvisoryInterface와 킬 스위치가 추가되었으나, 금융 손실에 대한 책임 경계와 안전장치의 실전 검증 여부가 불명확하다.

  5. 단일 조직 의존도: HKUDS 연구실이 사실상 유일한 주도 조직으로 보이며, 외부 핵심 기여자 다양성이 낮을 가능성이 있다. 연구실 활동 변화 시 프로젝트 지속성이 위협받을 수 있다.
