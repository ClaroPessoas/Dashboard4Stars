상세 분석 (Detailed Analysis)

1. 목적 및 범위 (Purpose & Scope)

[한국어] OpenHuman은 커뮤니티 및 개인 사용자를 위한 오픈소스 AI 에이전트 하네스(harness)로, 로컬 퍼스트(local-first) 메모리 트리, 118개 이상의 OAuth 통합 서비스, TokenJuice 토큰 압축 엔진, 모델 라우팅, 음성 I/O를 갖춘 Human-in-the-loop 데스크탑 애플리케이션이다. Claude Code와(AI 코딩 도우미), OpenClaw, Hermes 등 경쟁 제품 대비 오픈소스 + 저비용 + 로컬 메모리 + 통합 생태계를 핵심 차별점으로 내세운다.

[English] OpenHuman is an open-source AI assistant/harness for communities and individuals. It ships as a Tauri v2 desktop app (Windows/macOS/Linux) with a Rust core, local-first SQLite memory tree (Obsidian-compatible), 118+ OAuth integrations, a token-compression engine (TokenJuice), model routing, voice I/O, and 80+ native tools. Positioned as a cost-effective alternative to cloud-only AI assistants.

  • 유형(Type): 데스크탑 애플리케이션 플랫폼 + AI 에이전트 런타임
  • 대상 사용자(Target Users): 개인 개발자, 소규모 팀, AI 에이전트 커뮤니티
  • 현재 상태(Status): Early Beta (v0.57.32)

강점 (Strengths)

  1. 엄격한 아키텍처 경계(Strict Architectural Boundaries) Rust 코어(비즈니스 로직) — Tauri 셸(오케스트레이션) — React(프레젠테이션) 간 계층이 컴파일 타임에 강제된다. 114개 도메인 모듈이 표준화된 6-파일 형태(mod.rs, types.rs, store.rs, ops.rs, schemas.rs, tools.rs)를 따르며, 새 도메인 추가 시 일관성이 자동 확보된다.

  2. 3중 테스트 레이어 + 커버리지 게이트(Triple Test Layer + Coverage Gate) Vitest(단위) + WDIO/Playwright(E2E) + cargo test(Rust)가 하나의 CI 파이프라인에 통합되고, diff-cover를 통해 변경된 라인의 80% 이상을 커버하지 않으면 PR이 머지되지 않는다. 실제 데스크탑 테스트(tauri-driver, Appium Mac2)가 플랫폼별로 분리되어 동작한다.

  3. 다계층 보안 모델(Multi-layer Security Model) 승인 게이트(Approval Gate) → 명령어 분류(CommandClass) → 자율성 티어(readonly/supervised/full) → 샌드박스(OS 수준 jail) → 경로 격리(action_dir/workspace_dir)로 이어지는 심층 방어(Defense-in-depth)가 체계적으로 구현되어 있다. 에이전트가 의도치 않게 시스템 자격 증명을 접근하는 경로가 컴파일 타임에 차단된다.

  4. 로컬 퍼스트 + 운영 투명성(Local-First + Operational Transparency) SQLite 기반 마크다운 메모리 트리가 로컬에 저장되고 Obsidian과 호환된다. TokenJuice 압축 엔진이 최대 80% 토큰 절약을 목표로 한다. 모든 설정이 TOML 파일 + 환경 변수로 오버라이드 가능하여 운영 투명성이 높다.

  5. 프로덕션급 i18n 및 커뮤니티 거버넌스(Production-grade i18n & Governance) 16개 언어 번역이 CI로 강제(키 누락/영어 플레이스홀더 탐지)되고, 6개 언어 README, 기여자 보상 자동화 시스템, Contributor Covenant 2.1, SECURITY.md Safe Harbor 조항까지 갖춘 거버넌스는 오픈소스 Early Beta 단계에서 보기 드문 성숙도다.

위험/개선 필요 사항 (Risks & Areas for Improvement)

  1. 벤더링된 Tauri CEF 빌드의 유지보수 부담 (Vendored Tauri-CEF Maintenance Risk) app/src-tauri/vendor/tauri-cef에 커스텀 빌드된 Tauri CLI와 Chromium이 포함되어 있다. 이는 공식 @tauri-apps/cli와 지속적으로 sync해야 하며, 보안 패치가 포함된 Tauri/Chromium 업스트림을 수동으로 병합해야 한다. 장기적으로 N-day 취약점이 데스크탑 번들에 잔류할 위험이 있다.

  2. macOS 코드 서명이 로컬 스크립트에 의존 (macOS Signing Dependency on Local Script) 프로덕션 릴리즈 워크플로우 중 macOS 서명이 build-macos-signed.sh 로컬 스크립트에 의존하며 CI 자동화에 완전히 통합되지 않은 것으로 보인다. 이는 릴리즈 프로세스의 재현성과 보안 감사 가능성을 낮춘다.

  3. 의존성 자동 취약점 관리 부재 (No Automated Dependency Vulnerability Management) Dependabot 또는 Renovate 설정 파일이 확인되지 않는다. 118개 이상의 외부 OAuth 통합과 대규모 Rust/npm 의존성 그래프를 고려하면, 취약한 의존성이 머지될 위험을 증가시킨다. 주간 code-review.yml이 부분적으로 보완하지만 자동화된 취약점 스캔과 업데이트 PR이 필요하다.

  4. 블록체인/Web3 통합의 공격 표면 확대 (Expanded Attack Surface via Blockchain/Wallet Integration) bitcoin 0.32, ed25519-dalek 2(Solana), ethers-core 2.0.14(EVM), XChaCha20-Poly1305 터널, BIP32/39 등 암호화폐 관련 코드가 데스크탑 앱에 포함되어 있다. 이 기능들은 에이전트가 자금을 직접 이동시킬 수 있는 경로를 만들며, x402(기계 결제) 도메인과 결합 시 에이전트 재정 자율성(financial autonomy)의 보안 리스크가 상당하다.

  5. CHANGELOG 및 ADR 부재 (No CHANGELOG or Architecture Decision Records) v0.57.32라는 높은 패치 번호에도 불구하고 독립된 CHANGELOG 파일이나 ADR(Architecture Decision Records)이 확인되지 않는다. 주요 아키텍처 결정(예: 사이드카 제거 PR #1061, QuickJS 제거 등)이 코드 주석과 PR 본문에 분산되어 있어, 신규 기여자의 의사결정 맥락 파악이 어렵다.
