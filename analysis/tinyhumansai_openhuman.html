세부 분석

1. 목적 및 범위

OpenHuman은 개인·암호화폐 커뮤니티를 위한 로컬-퍼스트 AI 에이전트 데스크톱 앱이다. 핵심 차별점은 세 가지다: (1) 메모리 트리 + 즉시 컨텍스트 — 콜드 스타트 없이 과거 대화·작업이 로컬 SQLite에 유지됨, (2) 118+ OAuth 통합을 통한 인박스·캘린더·GitHub·Slack·Notion 등 실시간 연동, (3) TokenJuice 압축으로 LLM 비용·지연 최대 80% 절감. 대상 사용자는 멀티툴 작업 전문가와 프라이버시 중시 사용자. 플랫폼 범위: macOS·Windows·Linux 데스크톱 전용(Android/iOS 미지원 명시).

4. 아키텍처

핵심 원칙: Rust 코어가 비즈니스 로직 전담 권위자, Tauri는 얇은 배달 수단.

레이어 구조:

React UI (UX 전용)
    ↕ Tauri IPC (invoke/core_rpc_relay)
Tauri 쉘 (CEF 관리, 프로세스 라이프사이클, CDP 스캐너)
    ↕ HTTP JSON-RPC :7788 (Bearer OPENHUMAN_CORE_TOKEN)
Rust 코어
├── src/core/     → 트랜스포트 레이어 (Axum, JSON-RPC dispatch, CLI, 이벤트버스)
└── src/openhuman/<domain>/  → 69개 도메인 (agent, memory, channels, cron, ...)
    ├── rpc.rs    → 컨트롤러 구현
    ├── schemas.rs → JSON-RPC 메타데이터 + 핸들러 라우팅
    ├── ops.rs    → 비즈니스 로직
    ├── store.rs  → SQLite 영속성
    └── bus.rs    → 이벤트 버스 구독자

이벤트 버스 (src/core/event_bus/): - Broadcast: publish_global / subscribe_global — 화재 후 망각 - Native req/res: register_native_global / request_native_global — 제로 직렬화 단방향

컨트롤러 레지스트리: src/core/all.rs에서 전체 도메인 핸들러 집중 연결. src/core/dispatch.rs / cli.rs에 도메인 분기 추가 금지(규칙).

CEF 웹뷰 보안 설계: 임베디드 서드파티 웹뷰(Telegram, WhatsApp, Slack 등)에 JS 주입 완전 금지. 모든 스크레이핑·관찰성은 CDP 네이티브 스캐너 모듈에서 처리.

6. 보안 및 공급망

보안 정책 (SECURITY.md): - 지원 버전: 최신·이전 마이너 버전만 패치 - 신고: 이메일(비공개), 5 영업일 내 응답 목표, 안전 항구(safe harbor) 명시 - 인-스코프: 인증 우회, 자격증명 유출, RCE, 의존성 체인, 플랫폼별 취약점

자격증명 보안: - macOS Keychain / Windows Credential Manager / Linux secret storage — 평문 없음 - JWT 세션 토큰은 in-process 코어에만 보관, redux-persist 제외 - 스킬 실행: Node.js 샌드박스 내 실행, 도구 브릿지 API로만 외부 접근 제한

공급망: - Cargo.lock (9,849줄) + pnpm-lock.yaml 커밋(재현 가능 빌드) - ⚠️ Dependabot/Renovate 미구성 — 의존성 업데이트 수동 - ⚠️ SBOM 없음, 명시적 라이선스 감사 도구 없음 - 라이선스: GPL-3.0 (카피레프트 — 링크된 파생 저작물도 GPL 요구)

플랫폼 서명: - macOS: 개발자 인증서 서명 + Apple 공증(Gatekeeper 통과) - Windows: 코드 서명 인증서 - Linux: SHA-256 무결성 검증

강점

  1. Rust 코어 + 얇은 Tauri 쉘 구조: 비즈니스 로직이 Rust에 집중되어 메모리 안전성·성능을 보장. Tauri 쉘은 배달 수단으로만 역할하여 레이어 경계가 명확.

  2. 이벤트 버스 + 컨트롤러 레지스트리 패턴: 69개 도메인이 타입-안전 이벤트 버스로 느슨하게 결합. JSON-RPC 컨트롤러가 src/core/all.rs에 집중 등록되어 전체 공개 API가 단일 소스에서 추적 가능.

  3. 강력한 테스트 인프라: 변경 줄 80% 커버리지 PR 블로킹, 1,000+ Vitest + 5,600+ Rust 테스트, 듀얼 플랫폼 E2E, 150+ 행 커버리지 매트릭스. AI 보조 개발에 최적화된 구조.

  4. 로컬-퍼스트 프라이버시 설계: 모든 메모리·자격증명을 OS 키체인·로컬 SQLite에 보관. JWT를 redux-persist 외부(in-process 코어)에만 유지하는 설계가 자격증명 유출 표면을 최소화.

  5. AI-native 문서화: CLAUDE.md, AGENTS.md, .claude/, .codex/, .agents/ 등 AI 에이전트 협업을 위한 체계적 규칙이 프로젝트에 내장. 원격 에이전트 PR 체크리스트, 디버그 로깅 의무, 기능 설계 워크플로우가 모두 문서화됨.

위험 / 개선 필요 사항

  1. 의존성 자동화 부재: Dependabot/Renovate 미설정. Cargo.lock 9,849줄, pnpm-lock.yaml — 수동 업데이트 프로세스는 CVE 대응 지연 위험. 즉시 Dependabot 활성화 권고.

  2. GPL-3.0 카피레프트 리스크: 기업 환경에서 상업적 임베딩·통합 시 GPL 전파 의무 발생. 의존성 라이선스 감사 도구(예: cargo-deny, license-checker) 미구성. SBOM도 부재.

  3. CEF 벤더 포크 유지 부담: app/src-tauri/vendor/tauri-cef가 서브모듈로 관리. 상류 Tauri 보안 패치를 수동으로 포크에 적용해야 하는 지속적 유지 비용과 뒤처짐 위험.

  4. CHANGELOG 부재: 버전 이력이 GitHub Releases에만 존재. CHANGELOG.md가 없어 의존 프로젝트가 변경사항을 추적하기 어렵고, 자동화 릴리스 노트 생성(예: semantic-release) 미도입.

  5. 테스트 매트릭스 공백: docs/TEST-COVERAGE-MATRIX.md에 20+ 행이 ❌(누락)로 표시됨(예: multi-provider 링킹, 토큰 갱신, 특정 OAuth 플로우). Early Beta 허용 범위이나 개선 우선순위 로드맵이 필요.
