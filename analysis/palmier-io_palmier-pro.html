상세 분석

1. 목적 및 범위

Palmier Pro는 macOS 전용 AI 네이티브 비디오 에디터다. Adobe Premiere를 북극성으로 삼되, AI 에이전트 통합에 집중한다. 주요 가치 제안:

  • 타임라인 내 AI 생성: Seedance, Kling, GPT-Image-2 등 SOTA 모델로 비디오·이미지·오디오를 타임라인에서 직접 생성
  • MCP 서버: 앱 실행 시 http://127.0.0.1:19789/mcp를 노출, Claude Code/Cursor/Codex가 타임라인을 직접 조작 가능
  • 온디바이스 시각 검색: SigLIP2 Core ML 임베딩으로 자연어로 미디어 검색
  • AI 에이전트 내장 채팅: 인앱 Claude 기반 채팅에서 타임라인 클립·타임레인지를 멘션으로 참조

비디오 에디터 자체는 GPLv3 완전 오픈소스, 생성 AI 처리 백엔드는 클로즈드 소스.

4. 아키텍처 분석

진입점

Sources/PalmierPro/App/main.swift → AppDelegate → HomeWindowController or EditorWindowController

핵심 패턴

  • MVVM: EditorViewModel이 타임라인 상태 전체를 소유. SwiftUI 뷰는 @Observable로 바인딩.
  • @MainActor 전역 적용: UI 관련 타입 모두 @MainActor로 격리, Swift 6 strict concurrency 준수.
  • 서비스 싱글턴: AppState.shared, AccountService.shared, ModelCatalog.shared — 의존성 주입 없이 전역 접근.
  • MCP 서버(이중 경로):
  • 외부 클라이언트 → MCPService(HTTP, 포트 19789) → ToolExecutor
  • 인앱 채팅 → AgentService → AnthropicClient/PalmierClient → ToolExecutor
  • 두 경로가 ToolDefinitions.all과 ToolExecutor를 공유 → 일관된 도구 동작 보장
  • 도구 분야별 extension: ToolExecutor+Captions, +Clips, +Folders 등 11개 파일로 책임 분산
  • 레이어 구조: UI (SwiftUI/AppKit) → ViewModel → Service → Domain Model → Persistence (Codable JSON) ↕ MCP HTTP Server (외부 에이전트 접근)
  • 상태 관리: @Observable 매크로 기반. Timeline, MediaManifest 등 값 타입(struct) 도메인 모델을 EditorViewModel(참조 타입)이 소유.

주목할 설계 결정

  • 부모/자식 레이아웃 내 드래그앤드롭: macOS 26 SwiftUI .onDrop 버그 회피를 위해 중첩 드롭 영역은 AppKit NSDraggingDestination 사용(MediaPanelDropArea). AGENTS.md에 명시적 규칙으로 문서화.
  • SigLIP2 Core ML 모델은 앱 번들에 미포함(다운로드 방식) → ModelDownloader로 지연 로드.
  • Clerk 공개키, Convex URL은 빌드 시 Info.plist에 주입, 소스코드에 하드코딩 없음.

강점

  1. MCP 이중 경로 설계의 일관성: 외부 에이전트(MCP HTTP)와 인앱 채팅 모두 동일한 ToolDefinitions + ToolExecutor를 공유하여, 두 인터페이스 간 동작 불일치가 구조적으로 불가능하다. MCP 도구 명세(30개 도구)의 설명 문자열 품질도 높아 에이전트가 올바르게 호출하기 쉽다.

  2. Swift 6 strict concurrency 전면 적용: @MainActor, Sendable, @Observable을 일관 적용하여 데이터 레이스를 컴파일 타임에 차단. isolated deinit, nonisolated(unsafe) 등 Swift 6 고급 기능을 실제 프로덕션 코드에서 올바르게 활용한다.

  3. AppTheme 디자인 시스템 강제화: AGENTS.md에 규범을 명시하고, AppTheme.swift에 모든 토큰(색상·간격·폰트·애니메이션)을 집중화. 하드코딩된 숫자가 없어 다크 테마나 디자인 리브랜딩 시 변경 범위가 최소화된다.

  4. 릴리스 파이프라인 완성도: scripts/release.sh가 preflight → 버전 범프 → 빌드/서명/공증 → GitHub Release → appcast 업데이트까지 원클릭으로 처리. Sparkle EdDSA 서명과 Apple 공증을 모두 수행하여 배포 보안 수준이 높다.

  5. 온디바이스 ML 검색 아키텍처: SigLIP2 Core ML 변환 + 자체 임베딩 스토어로 외부 API 없이 텍스트→영상 시맨틱 검색을 구현. 모델 변환 스크립트(models/siglip2/convert.py)와 cosine ≥ 0.99 parity gate를 문서화하여 재현성을 보장한다.

위험 / 개선 필요 사항

  1. EditorViewModel 비대화: 20개 extension 파일로 분산되어 있음에도 단일 EditorViewModel 클래스가 재생 상태, 선택 상태, 패널 가시성, 미디어 라이브러리, 타임라인 변환 등 모든 편집기 상태를 소유한다. 이는 테스트 격리를 어렵게 하고, 향후 기능 추가 시 파일 간 의존성 폭발을 유발할 수 있다.

  2. 테스트 커버리지 부재: 전체 소스의 약 2%에 해당하는 3개 파일만 테스트됨. ToolExecutor, GenerationService, CompositionBuilder, SnapEngine 등 비즈니스 로직 핵심이 테스트 없음. CI가 없어 PR 머지 시 빌드 회귀조차 자동 감지되지 않는다.

  3. 의존성 취약점 모니터링 없음: Package.resolved로 버전은 고정되어 있으나 Dependabot/Renovate 등 자동 취약점 알림 도구가 없다. Clerk, Convex, Sentry 같은 인증·데이터 경로 라이브러리의 보안 패치가 누락될 위험이 있다.

  4. 인증 없는 로컬 MCP 서버: localhost:19789에 인증 토큰 없이 HTTP 서버를 열어 둔다. 동일 기기에서 실행 중인 악의적 프로세스나 로컬 SSRF 취약점이 있는 다른 앱이 타임라인을 임의 조작할 수 있다. 최소한 임시 세션 토큰 검증을 추가해야 한다.

  5. 플랫폼 고착: macOS 26 (arm64 only) 요구사항은 현재(2026-06-20) 기준 최신 베타 OS로, 사용 가능한 설치 기반이 극히 협소하다. 이른 macOS 26 채택은 차별화 요소이지만, 커뮤니티 기여자 풀과 시장 접근성을 동시에 제한한다.

도입 권고

기술 도입 관점: Palmier Pro의 MCP 통합 구조와 ToolDefinitions 공유 패턴은 AI 에이전트를 기존 macOS 앱에 통합하려는 팀에 유용한 참조 구현이다. Swift 6 strict concurrency의 실전 적용 방식(특히 @MainActor + @Observable 조합)은 학습 자료로 가치가 높다.

보안 검토 관점: API 키 Keychain 저장, SentryDSN 런타임 주입 등 기본 보안 관행은 준수하나, SECURITY.md 부재, 의존성 취약점 모니터링 없음, 인증 없는 로컬 MCP 서버는 개선이 필요하다. 기업 환경 도입 전 이 세 항목을 우선 해결해야 한다.

기여 준비도 관점: AGENTS.md를 통해 AI 에이전트 기여자에게 명확한 규범을 제공한다는 점이 독특하다. 그러나 CI 부재와 낮은 테스트 커버리지로 인해 인간 리뷰어 부담이 크다(CONTRIBUTING.md 직접 언급). 소규모 스타트업의 초기 단계 제품으로 대규모 오픈소스 기여보다는 이슈 중심 참여가 현실적이다.

종합 권고: 생성 AI와 비디오 편집의 통합, MCP 네이티브 아키텍처라는 기술 방향성은 명확하고 혁신적이다. 현재 상태에서 프로덕션 영상 제작 도구로 쓰기엔 기능(트랜지션·효과·색보정 등)과 안정성(테스트·CI)이 부족하나, AI 에이전트 기반 워크플로 실험과 MCP 통합 레퍼런스로서의 활용 가치는 높다.
