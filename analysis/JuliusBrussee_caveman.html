분석 개요 (Analysis Overview)

항목 확인 내용 평가
목적 AI 코딩 에이전트(Claude Code, Codex, Gemini CLI, Cursor, Windsurf 등 30+ 도구)의 출력 토큰을 ~65~75% 절감하는 "caveman 스타일" 프롬프트 압축 플러그인/스킬 배포 도구. 기술적 정확도는 유지하면서 불필요한 수식어, 인사말, 관사 등을 제거함. ★★★★★ — 명확한 단일 문제 해결. Before/After 예시와 실측 벤치마크로 가치 증명.
구조 단일 저장소(monorepo). skills/ (단일 소스), src/hooks/ (Claude Code 훅), bin/install.js (통합 설치 스크립트), plugins/caveman/ (CI 미러), agents/ (cavecrew 서브에이전트), tests/, benchmarks/, evals/, docs/ 구성. 소스와 배포 미러 분리 명확. ★★★★☆ — 레이아웃 우수. plugins/caveman/skills/caveman-stats/ 미러가 CI 미동기화 상태로 방치된 점은 경미한 오점.
스택 Node.js ≥18 (순수 stdlib, 런타임 외부 의존성 없음), Python 3.10+ (compress 스크립트·evals·benchmarks), Bash/PowerShell (상태줄 스크립트), TOML (Codex/Gemini 커맨드 스텁), JSON/JSONC (설정 파일). 배포: npx, curl\|bash, irm\|iex. ★★★★★ — 런타임 npm 의존성 제로. 어디서나 npx -y로 동작.
진입점 bin/install.js (CLI entrypoint, package.json bin.caveman). install.sh / install.ps1은 30라인 shim → npx 위임. Claude Code 플러그인 진입점은 .claude-plugin/plugin.json의 SessionStart / UserPromptSubmit 훅 선언. ★★★★★ — 단일 소스 설치기. 과거 bash/PS1 쿼팅 버그(issue #249)를 Node 이식으로 해소.

데이터 영구 저장소 없음. 플래그 파일($CLAUDE_CONFIG_DIR/.caveman-active, 최대 64바이트)과 히스토리 JSONL(.caveman-history.jsonl)만 사용. 설정은 settings.json JSONC에 병합. 벤치마크 결과를 benchmarks/results/*.json에 커밋. ★★★★★ — 사용자 데이터 불수집. 플래그 파일 최소 footprint.
배포 npm(npx -y github:JuliusBrussee/caveman), curl\|bash, irm\|iex. Claude Code는 claude plugin install, Gemini는 gemini extensions install, 기타는 npx skills add. 테스트 Node.js node --test (installer unit/e2e), Python unittest (compress 안전 검사, 훅 스크립트, symlink 플래그, validate inline). tests/test_symlink_flag.js가 O_NOFOLLOW + 심링크 소유권 검증 로직을 완전 커버. 평가(evals): 3-arm 하네스(baseline/terse/skill), 스냅샷 커밋으로 CI 무비용 실행. ★★★☆☆ — 핵심 보안 경로 커버리지 우수. 단, 커버리지 측정 도구 없음. Provider 탐지 로직(PROVIDERS 배열)에 대한 직접 단위 테스트 부재.
보안 safeWriteFlag() / readFlag(): O_NOFOLLOW, 심링크 소유권 검증, 64바이트 캡, 모드 화이트리스트, 원자적 temp+rename, 0600 권한. curl|bash 경로는 PINNED_REF 고정 + SHA-256 체크섬 검증(manifest 없으면 경고). JSONC SETTINGS 헬퍼로 settings.json 쓰기 전 Zod 스키마 충돌 방지. SECURITY.md 부재. dependabot 설정 없음. ★★★★☆ — 로컬 심링크 공격 방어 매우 견고. SECURITY.md 및 자동 의존성 업데이트 파이프라인 미구축은 개선 과제.
성숙도 MIT 라이선스. GitHub Issues, PR 템플릿(bug/feature), CONTRIBUTING.md, CLAUDE.md(유지보수 가이드) 구비. FUNDING.yml로 스폰서십 연결. 커밋 메시지에 Conventional Commits 권장. CHANGELOG 부재. CODE_OF_CONDUCT.md 부재. 커뮤니티 단일 기여자 중심. ★★★★☆ — 문서·운영 성숙도 높음. CHANGELOG·CoC 미비.

강점 (Strengths)

  1. 제로 런타임 의존성 설치기 — bin/install.js가 Node.js stdlib만 사용하며 30개 이상의 에이전트를 단일 파일로 탐지·설치한다. 과거 bash/PS1 이중 소스 유지 문제를 제거하고 WSL/Windows 엣지 케이스도 명시적으로 처리한다.

  2. 보안 1등급 플래그 파일 구현 — safeWriteFlag() / readFlag()는 O_NOFOLLOW, 원자적 O_EXCL 생성, 64바이트 크기 캡, 모드 화이트리스트를 모두 구현해 로컬 심링크 clobber 공격을 막는다. 이 수준의 방어는 단순 설정 파일 도구에서 보기 드물다.

  3. 단일 소스 원칙 철저 준수 — skills/caveman/SKILL.md가 행동 정의의 유일 소스이며, CI가 plugins/caveman/ 미러로 자동 동기화한다. 유지보수자 가이드(CLAUDE.md)가 "무엇을 편집하지 말아야 하는가"를 명확히 문서화한다.

  4. 정직한 벤치마크 방법론 — 3-arm 평가(baseline / terse / skill)를 도입해 "caveman vs 아무 지시 없음"이 아닌 "caveman vs 단순 '간결히'라는 지시" 대비 델타를 측정한다. 수치 위조를 구조적으로 방지한다.

  5. 릴리스 불변성 보장 — PINNED_REF = 'v1.9.0'로 curl|bash 파이프 설치를 이동 브랜치(main)가 아닌 릴리스 태그에 고정하고, SHA-256 체크섬 매니페스트로 다운로드 무결성을 검증한다. 공급망 공격 표면을 명시적으로 축소한다.

위험 / 개선 필요 사항 (Risks / Areas for Improvement)

  1. SECURITY.md 부재 및 취약성 보고 채널 미지정 — 보안 문제가 발생하면 일반 GitHub Issue를 사용해야 한다. 훅 시스템이 사용자 홈 디렉터리를 다루는 만큼, CVD 정책(Coordinated Vulnerability Disclosure) 경로를 명시하는 것이 권장된다.

  2. 의존성 자동 업데이트 파이프라인 부재 — dependabot.yml이나 renovate.json이 없다. Python 의존성(benchmarks/requirements.txt, evals/)의 취약성 스캔이 이뤄지지 않는다. 현재는 런타임 npm 의존성이 없어 리스크가 낮지만, caveman-shrink MCP 서버는 향후 의존성 추가 가능성이 있다.

  3. CI 동기화 범위 불완전 — sync-skill.yml이 caveman-commit, caveman-review, caveman-help, caveman-stats 스킬은 플러그인 미러에 동기화하지 않는다. plugins/caveman/skills/caveman-stats/가 수동 커밋 상태로 방치되어 있어, 소스 수정이 미러에 반영되지 않는 시나리오가 발생할 수 있다.

  4. 테스트 커버리지 불투명 — istanbul/nyc/c8 등 커버리지 측정 도구가 설정되지 않았다. bin/install.js의 Provider 탐지 로직(detectMatch, vscodeExtPresent 등)과 opencode 네이티브 설치 경로에 대한 직접 단위 테스트가 없다.

  5. CHANGELOG 및 릴리스 노트 관리 부재 — 이슈(#249, #261, #392, #474 등)가 코드 주석에 광범위하게 참조되지만, 공식 CHANGELOG 파일이 없다. 사용자가 버전 간 변경 사항을 추적하기 어렵다.

도입 권고 (Adoption Recommendation)

요약 판단

도입 적극 권장. 다음 사용 사례에 특히 적합하다:

  • 토큰 비용 절감: Claude Code, Codex, Gemini 등 유료 LLM API를 대량 사용하는 개발팀. 실측 65% 출력 토큰 절감은 단순 "간결히" 지시를 크게 상회하는 실질적 절감이다.
  • 아키텍처 참조 모델: 다중 에이전트 플랫폼용 훅 기반 플러그인 시스템 설계, 심링크 안전 플래그 파일 패턴, JSONC 허용 설정 파일 병합 헬퍼 등 실용적인 구현 패턴의 참고 자료로 가치 있다.
  • 보안 검토 기준: 예측 가능한 경로의 플래그 파일에 대한 심링크 공격 방어(O_NOFOLLOW + 소유권 검증)가 벤치마크 수준으로 구현되어, 유사 도구의 보안 리뷰 기준으로 활용 가능하다.

주의 사항

  • 훅 파일이 사용자의 ~/.claude/settings.json을 직접 수정하므로, 엔터프라이즈 환경에서는 --dry-run 먼저 실행하여 변경 내용을 확인 후 적용 권장.
  • SECURITY.md 미비와 dependabot 부재는 기업 보안 정책 통과 시 장애 요인이 될 수 있다. 내부 포크 후 이 두 항목 추가 후 사용 권장.
  • 단일 메인테이너 프로젝트로 버스 팩터(bus factor)가 1이다. 핵심 의존성으로 사용하기보다 팀 내 설치 후 소스를 내부 미러에 보관하는 전략이 안전하다.
