Step 1. 목적 및 범위 정의 (Purpose and Scope)

대상 사용자: - 자신의 인프라를 직접 운영하려는 개인 사용자(프라이버시 중시) - SaaS 의존도를 낮추려는 소기업/중소기업 - 오픈소스 대안을 탐색하는 IT 관리자 및 DevOps 엔지니어 - 셀프호스팅 생태계를 연구하는 개발자 및 연구자

프로젝트 유형: 큐레이션 목록(Curated List) / 지식 디렉토리(Knowledge Directory) — 배포 가능한 소프트웨어가 아닌 문서 아티팩트(Document Artifact) 저장소.

English

awesome-selfhosted is a curated directory of free software network services and web applications that can be self-hosted — i.e., run on your own servers rather than using a SaaS provider. With 230,000+ GitHub stars, it is one of the most referenced open-source community resources globally, serving as the canonical lookup for anyone seeking self-hosted alternatives to commercial cloud services.

Project Type: Curated list / knowledge directory — a read-only documentation artifact, not deployable software.

English

The architecture follows a clean pipeline separation model. This repository is the View layer in a data pipeline where: - awesome-selfhosted-data = Model (YAML source of truth) - awesome-selfhosted (this repo) = Build artifact / distribution channel - awesome-selfhosted.net = Presentation layer (HTML + search)

The bot commit discipline enforces immutability of the view layer, ensuring the Markdown output is always a faithful, programmatically correct reflection of the YAML data source. This is architecturally sound for a content-heavy, community-contributed project of this scale.

Q1. 이 저장소에 직접 PR을 보냈는데 왜 거절됐나요?
A. 이 저장소의 README.md는 봇이 자동 생성합니다. 모든 항목 추가/수정/삭제는 awesome-selfhosted-data 저장소로 PR을 보내야 합니다. .github/PULL_REQUEST_TEMPLATE.md에도 이 안내가 명시되어 있습니다.

Q2. 소프트웨어 항목을 추가하고 싶은데 어떤 기준이 있나요?
A. 공식 기준은 awesome-selfhosted-data의 CONTRIBUTING.md에 있습니다. 핵심 요건은: (1) 자유 소프트웨어 라이선스일 것, (2) 자체 호스팅 가능할 것, (3) 유지보수가 활성화될 것, (4) 네트워크 서비스 또는 웹 애플리케이션일 것. 비자유 소프트웨어라면 non-free.md 항목으로 요청할 수 있습니다.

Q3. awesome-selfhosted.net과 이 GitHub 저장소의 차이는 무엇인가요?
A. 내용은 동일합니다. awesome-selfhosted.net은 HTML로 렌더링된 공식 권장 버전으로, 필터링·검색 기능이 제공됩니다. 이 GitHub 저장소는 Markdown 원본을 제공하며 "레거시" 버전으로 분류됩니다.

Q4. 목록에 있는 소프트웨어가 더 이상 유지보수되지 않는 것 같습니다. 어떻게 신고하나요?
A. awesome-selfhosted-data 저장소에 이슈를 작성하거나 PR로 해당 항목을 제거 요청하면 됩니다. 자동 check-unmaintained-projects 워크플로가 이를 정기적으로 감지하기도 합니다.

Q5. 이 목록을 내 웹사이트나 앱에 임베드하거나 재가공해도 되나요?
A. 네. Creative Commons BY-SA 3.0 라이선스 하에 원저자 표시(Attribution)와 동일 조건 공유(ShareAlike) 조건을 지키면 자유롭게 사용할 수 있습니다.

Q6. 로컬에서 목록을 예쁘게 보고 싶은데 어떻게 하나요?
A. pip install grip && grip README.md 후 브라우저로 http://localhost:6419에 접속하면 GitHub 스타일 Markdown 렌더링을 로컬에서 확인할 수 있습니다.

Q1. I submitted a PR directly to this repository. Why was it rejected?
A. The README.md in this repository is auto-generated by a bot. All additions, edits, or removals must be submitted as PRs to the awesome-selfhosted-data repository. The .github/PULL_REQUEST_TEMPLATE.md file in this repo explicitly states this.

Q2. I want to add a software entry. What are the criteria?
A. Official criteria live in CONTRIBUTING.md of awesome-selfhosted-data. Core requirements: (1) Free Software license, (2) self-hostable, (3) actively maintained, (4) network service or web application. If the software is non-free, request inclusion in non-free.md instead.
