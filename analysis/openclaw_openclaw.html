Step 1. 목적 및 범위 / Purpose and Scope

한국어

OpenClaw는 사용자 개인 기기에서 실행되는 로컬 퍼스트 AI 어시스턴트 게이트웨이다. WhatsApp, Telegram, Slack, Discord, Signal, iMessage, IRC, Microsoft Teams, Matrix, LINE, WeChat 등 20개 이상의 메시징 채널을 단일 제어 평면(Gateway)으로 연결하고, 다수의 LLM 프로바이더(OpenAI, Anthropic, Ollama, Gemini, Deepseek, Mistral 등)를 통합한다.

대상 사용자: 개인 단위 운영자(trusted operator) — 자신의 채널과 기기에서 강력하고 프라이버시-보존 AI 어시스턴트를 원하는 개발자 및 파워 유저.

제품 유형: CLI 도구 + 데몬 서버 + 플러그인 플랫폼 + 다플랫폼 앱(macOS/iOS/Android).

English

OpenClaw is a local-first personal AI assistant gateway running on the user's own devices. It bridges 20+ messaging channels (WhatsApp, Telegram, Slack, Discord, Signal, iMessage, Matrix, IRC, Microsoft Teams, LINE, WeChat, etc.) through a single control-plane Gateway and integrates numerous LLM providers (OpenAI, Anthropic, Ollama, Gemini, Deepseek, Mistral, etc.).

Target users: Single-user trusted operators — developers and power users wanting a privacy-preserving, always-on AI assistant across their existing messaging surfaces.

Product type: CLI tool + daemon server + plugin platform + multi-platform native apps (macOS/iOS/Android).

Step 4. 아키텍처 분석 / Architecture Analysis

핵심 패턴

이벤트 드리븐 플러그인 게이트웨이 (Event-Driven Plugin Gateway)

[메시징 채널] ──→ [채널 플러그인] ──→ [Gateway 서버]
                                          │
                   [인증/인가 레이어]      │
                   [세션 관리]            │
                   [라우팅 정책]          ↓
                              [에이전트 런타임]
                                          │
                   [LLM 프로바이더 플러그인] ↓
                   (OpenAI, Anthropic, ...)
                              [응답 전달]
                                    │
                   [메모리 플러그인] │ [도구 플러그인]
                   (LanceDB, 파일)  ↓  (웹검색, 코드, ...)

계층 구조

  1. 진입점 계층: src/entry.ts → CLI 파싱 → 컴파일 캐시/리스폰 → 게이트웨이 부트
  2. 게이트웨이 계층: src/gateway/server.ts - HTTP/WS 서버, 인증, 세션, 채널 상태
  3. 플러그인 SDK 계층: src/plugin-sdk/, packages/plugin-sdk/ - 외부 플러그인 API 표면
  4. 채널 계층: src/channels/ + extensions/<channel>/ - 채널별 메시지 수신/발신
  5. 에이전트/AI 계층: src/agents/ - LLM 호출, 도구 실행, 컨텍스트 관리
  6. UI 계층: ui/ - 웹 컨트롤 패널 (SPA)

아키텍처 설계 원칙 (AGENTS.md 기반)

  • 코어는 플러그인 무관: 채널 ID, 프로바이더 기본값, 정책을 코어에 하드코딩하지 않음
  • 플러그인 격리 경계: 플러그인은 openclaw/plugin-sdk/*만 통해 코어 접근
  • 소유권 경계 원칙: 프로바이더별 인증/검색/온보딩은 해당 플러그인 소유
  • 핫 패스 최적화: 런타임 재검색 없이 준비된 사실(프로바이더 ID, 모델 ref, 채널 ID) 전달
  • ACP (Agent Client Protocol): @agentclientprotocol/sdk를 통한 에이전트 간 통신
  • MCP (Model Context Protocol): HTTP 엔드포인트(src/gateway/mcp-http.*)로 도구 노출

Step 8. 최종 분석 보고서 / Final Analysis Report

강점 / Strengths

  1. 극도로 세분화된 플러그인 경계
    코어 → plugin-sdk → 플러그인 방향의 단방향 의존성이 명문화되어 있고 임포트 경계 테스트(vitest.boundary.config.ts)로 CI에서 자동 검증된다. 135개 이상 플러그인이 코어를 오염시키지 않는 구조.

  2. 프로덕션급 테스트 인프라
    40개+ Vitest 프로젝트 설정으로 유닛·인프라·경계·컨트랙트·게이트웨이·E2E·라이브·보안·성능 레이어를 체계적으로 분리. Crabbox/Testbox로 격리 환경 원격 검증까지 갖춘 점은 오픈소스 프로젝트로서 드문 수준.

  3. 로컬 퍼스트 보안 설계
    DM pairing 기본값, GHSA 비공개 보고, CodeQL·OpenGrep·Zizmor 다중 정적 분석, Docker 다이제스트 고정, systemd 토큰 파일 분리 등 보안이 아키텍처 레벨에서 설계되어 있음.

  4. 멀티 플랫폼 배포 일급 지원
    동일 코드베이스에서 CLI·데몬·Docker·Fly.io·Render·launchd/systemd·macOS/iOS/Android 앱을 동시 지원. Node 24와 Bun을 빌드 파이프라인에서 혼용하면서도 런타임은 Node 24로 단순하게 유지.

  5. 운영 AI 에이전트 워크플로 내재화
    AGENTS.md가 단순 기여 가이드가 아닌 게이트웨이 아키텍처 결정 원칙, 코드 스타일 정책, CI/PR/보안/릴리스 규칙을 망라하는 운영 문서로 기능. AI-assisted 워크플로(Codex 에이전트)를 프로젝트 인프라에 통합.

위험/개선 필요 사항 / Risks and Areas for Improvement

  1. 코어 복잡도 비대 위험
    src/gateway/ 하나에만 200개 이상의 파일이 집중되어 있다. 플러그인 경계는 우수하나, 게이트웨이 자체가 단일 거대 모듈이 될 위험이 있음. 서브도메인별 추가 분리 검토 권고.

  2. 의존성 패치/오버라이드 다수

  5. CODE_OF_CONDUCT 및 공식 OSPO 프로세스 부재: 기업 도입 시 필요한 공식 행동강령 및 OSPO(Open Source Program Office) 수준의 컴플라이언스 프로세스가 없음. 이는 기업 거버넌스 요구사항에서 갭을 형성.

9. 자주 묻는 질문 / FAQ

[한국어]

Q1. pnpm install 후 sharp 관련 빌드 오류가 발생합니다.

A: macOS에서 Homebrew의 libvips가 시스템에 설치되어 있을 경우 충돌이 발생할 수 있습니다. 다음 환경 변수를 설정하고 재설치하세요:

SHARP_IGNORE_GLOBAL_LIBVIPS=1 pnpm install

Q2. pnpm gateway:watch 실행 시 tmux 관련 오류가 나거나 아무것도 실행되지 않습니다.

A: gateway:watch 스크립트는 tmux를 사용합니다. tmux가 설치되어 있지 않거나 터미널 환경이 tmux를 지원하지 않는 경우 직접 게이트웨이를 실행하세요:

pnpm openclaw gateway --port 18789 --verbose
# 또는
node scripts/run-node.mjs gateway --port 18789 --verbose

Q3. 테스트 실행 중 ENOTEMPTY 오류가 발생합니다.

A: 동일한 worktree에서 여러 Vitest 프로세스가 동시에 실행되면 파일 캐시 경쟁이 발생합니다. 해결 방법:

# 방법 1: 직렬 실행
pnpm test:serial

# 방법 2: 최대 워커 수 제한
OPENCLAW_VITEST_MAX_WORKERS=1 pnpm test

# 방법 3: 별도 캐시 경로 지정

Q1. I get a sharp-related build error after pnpm install.

A: On macOS, a system-installed Homebrew libvips can conflict. Set this env var and reinstall:

SHARP_IGNORE_GLOBAL_LIBVIPS=1 pnpm install

Q2. pnpm gateway:watch gives tmux errors or does nothing.

A: The gateway:watch script uses tmux. If tmux is not installed or your terminal doesn't support it, run the gateway directly:

pnpm openclaw gateway --port 18789 --verbose
# or
node scripts/run-node.mjs gateway --port 18789 --verbose

Q3. I get ENOTEMPTY errors while running tests.

A: Concurrent Vitest processes in the same worktree cause a file cache race. Fix options:

# Option 1: serial run
pnpm test:serial

# Option 2: limit worker count
OPENCLAW_VITEST_MAX_WORKERS=1 pnpm test

# Option 3: use a separate cache path
OPENCLAW_VITEST_FS_MODULE_CACHE_PATH=/tmp/vitest-cache-2 pnpm test

Q4. When do I need to re-run pnpm openclaw setup?

A: Only in these cases: - After fully resetting your local OpenClaw config or workspace (e.g., after deleting ~/.openclaw/) - On first-time dev environment setup You do not need to re-run it after regular source code changes.

Q5. Running pnpm test directly in a Codex worktree or sparse checkout errors out.

A: In those environments, direct pnpm test* can trigger pnpm dependency reconciliation or install prompts. Use the wrapper instead:

# For a small number of explicit files
node scripts/run-vitest.mjs <path-or-filter>

# For broad checks
node scripts/crabbox-wrapper.mjs run ... --shell -- "pnpm test:changed"

Q6. How do I check type errors? Can I use tsc?

A: No. This project uses tsgo (TypeScript Native Preview) for type checking. Never add tsc --noEmit or typecheck:

pnpm check:test-types  # Check test types
pnpm check:changed     # Full check of changed files (includes types)
