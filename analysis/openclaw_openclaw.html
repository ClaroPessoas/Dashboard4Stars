상세 분석

1. 목적 및 범위 (Purpose & Scope)

OpenClaw는 "실제로 일을 처리하는 AI" 라는 슬로건 아래 개인 사용자의 디바이스 위에서 동작하는 AI 어시스턴트 플랫폼이다. 핵심 철학은 세 가지다:

  1. 로컬 퍼스트(Local-first): 게이트웨이는 기본적으로 localhost에서만 수신하며, 원격 노출은 Tailscale/SSH를 통해 명시적으로 허용해야 한다.
  2. 싱글 오퍼레이터 신뢰 모델: 멀티테넌트 SaaS가 아닌, 1인 운영자가 자신의 채널/그룹/에이전트를 통제하는 구조.
  3. 작업 실행 중심: 대화만이 아닌 파일 조작, 브라우저 자동화, 코드 실행, 채널 메시지 발송 등 실제 액션 수행.

제품은 CLI 어플리케이션, 로컬 게이트웨이 서버, 동반 앱(macOS/iOS/Android/Windows), 웹 대시보드, 그리고 플러그인 생태계(ClawHub)로 구성된 하이브리드 플랫폼이다.

9. 자주 묻는 질문 / FAQ

[한국어]

Q1. 게이트웨이가 시작되지 않고 "token placeholder" 오류가 납니다. .env의 OPENCLAW_GATEWAY_TOKEN 값이 비어있거나 문서에서 복사한 예시 값입니다. openssl rand -hex 32 명령으로 고유한 토큰을 생성해 설정하세요.

Q2. pnpm install 이후 빌드에서 import cycle 에러가 납니다.

pnpm check:import-cycles

결과를 보고 순환 의존성을 제거하세요. 새 파일을 추가할 때 반드시 기존 import 방향을 확인하세요.

Q3. 테스트 실행 중 ENOTEMPTY 오류가 발생합니다. Vitest 캐시 경쟁 조건입니다. 동시에 여러 pnpm test 프로세스를 실행하지 마세요. 별도의 캐시 경로가 필요하면 OPENCLAW_VITEST_FS_MODULE_CACHE_PATH 환경변수를 다르게 설정하세요.

Q4. Docker Compose로 실행 시 EACCES: mkdir '/Users/...' 오류가 납니다. 호스트의 macOS 경로가 컨테이너에 유출된 것입니다. .env의 OPENCLAW_STATE_DIR, OPENCLAW_CONFIG_PATH, OPENCLAW_CONFIG_DIR, OPENCLAW_WORKSPACE_DIR를 /home/node/.openclaw/... 로 덮어쓰세요. docker-compose.yml에는 이 값이 이미 하드코딩되어 있으니 .env에 중복 선언하지 마세요.

Q5. 플러그인 SDK에서 src/** 내부를 import하면 빌드 오류가 납니다. 아키텍처 제약입니다. 플러그인 코드는 오직 openclaw/plugin-sdk/* 공개 배럴만 사용해야 합니다. node scripts/check-sdk-package-extension-import-boundary.mjs --json으로 경계 위반을 확인할 수 있습니다.

Q6. TypeScript 타입 검사를 어떻게 실행하나요? tsgo 레인만 사용합니다: pnpm tsgo 또는 pnpm check:test-types. tsc --noEmit나 typecheck 스크립트는 절대 추가하지 마세요.

[English]

Q1. The Gateway won't start and shows a "token placeholder" error. Your OPENCLAW_GATEWAY_TOKEN in .env is empty or contains a verbatim example from documentation. Generate a unique token with openssl rand -hex 32 and set it.

Q2. After pnpm install, the build shows import cycle errors.

pnpm check:import-cycles

Review the output and eliminate the circular dependency. Always check the existing import direction before adding a new file.

Q3. Tests fail with ENOTEMPTY errors. This is a Vitest cache race condition. Never run multiple pnpm test processes concurrently in the same worktree. If you need separate caches, set OPENCLAW_VITEST_FS_MODULE_CACHE_PATH to a different path per process.

Q4. Docker Compose run fails with EACCES: mkdir '/Users/...'. A macOS host path has leaked into the container environment. Override OPENCLAW_STATE_DIR, OPENCLAW_CONFIG_PATH, OPENCLAW_CONFIG_DIR, and OPENCLAW_WORKSPACE_DIR to /home/node/.openclaw/.... The docker-compose.yml already hard-codes these; do not duplicate them in .env.

Q5. Importing from src/** inside a plugin SDK package causes build errors. This is an architecture constraint. Plugin code must only use public barrels from openclaw/plugin-sdk/*. Run node scripts/check-sdk-package-extension-import-boundary.mjs --json to find boundary violations.

Q6. How do I run TypeScript type-checking? Use only the tsgo lanes: pnpm tsgo or pnpm check:test-types. Never add tsc --noEmit or a typecheck script.

[한국어]

6. 성능 및 확장성 고려사항 / Performance & Scalability

[한국어]

알려진 성능 병목: - 컨텍스트 압축(Compaction): 긴 대화에서 컨텍스트 엔진의 압축 로직이 지연 유발 가능. packages/ 내 context-engine 관련 코드 참조. - 프롬프트 캐시 미스: 맵/셋/레지스트리의 비결정적 순서로 캐시 히트율 저하. 모델 페이로드 전 결정적 정렬 필수. - 요청 시점 플러그인 재검색: 제공자 id, 모델 ref, 채널 id 등 준비된 사실을 요청 핫 패스에서 재발견하지 말고 앞 단계에서 전달. - SQLite 동시 쓰기: Kysely 헬퍼 사용 및 WAL 모드 확인 권장.

수평/수직 확장 전략: - 현재 아키텍처는 단일 게이트웨이 프로세스 설계 (개인용 어시스턴트). - 수직 확장: 더 강력한 서버에서 실행, Node 24 + 충분한 RAM. - 여러 에이전트 인스턴스: agents/ 설정에서 다수의 에이전트 프로파일 구성.

캐싱 전략: - 게이트웨이/플러그인 메타데이터는 프로세스 생애 동안 안정적 (프로세스 재시작 없이 갱신 불가). - SQLite 기반 KV를 플러그인 캐시로 사용 (plugin-state-runtime). - 프로세스 로컬 캐시는 수명주기 소유자가 명확하고 단일 슬롯으로 bounded된 경우만 허용.

모니터링 및 로깅: - OpenTelemetry: extensions/diagnostics-otel 플러그인 (OTLP/HTTP 내보내기). - Prometheus: extensions/diagnostics-prometheus 플러그인 (인증된 게이트웨이 라우트). - macOS 로그: ./scripts/clawlog.sh - Docker 로그: docker compose logs -f openclaw-gateway - 디버그 모드: OPENCLAW_GATEWAY_STARTUP_TRACE=1 (게이트웨이 시작 타이밍 추적).

참고: 공식 문서 기반 권장 사항 / Note: Recommended based on official documentation — https://docs.openclaw.ai/diagnostics

[English]

Known performance bottlenecks: - Context compaction: On long conversations, the context engine's compaction logic can introduce latency. See context-engine related code under packages/. - Prompt cache misses: Non-deterministic ordering of maps/sets/registries reduces cache hit rates. Always sort deterministically before model/tool payloads. - Request-time plugin re-discovery: Provider id, model ref, channel id, etc. should be prepared and carried forward, not re-discovered on each hot-path request. - SQLite concurrent writes: Use Kysely helpers and verify WAL mode is enabled.

Horizontal / Vertical scaling strategies: - Current architecture is single-gateway-process by design (personal assistant use case). - Vertical scaling: Run on a more powerful server with Node 24 and sufficient RAM. - Multiple agent instances: Configure multiple agent profiles in agents/ settings.

Caching strategy: - Gateway/plugin metadata is process-stable (cannot be refreshed without a restart). - Use SQLite-backed KV for plugin caches (plugin-state-runtime). - Process-local caches are acceptable only when lifecycle-owned and single-slot bounded.

Monitoring and logging: - OpenTelemetry: extensions/diagnostics-otel plugin (OTLP/HTTP export). - Prometheus: extensions/diagnostics-prometheus plugin (authenticated gateway route). - macOS logs: ./scripts/clawlog.sh - Docker logs: docker compose logs -f openclaw-gateway - Debug mode: OPENCLAW_GATEWAY_STARTUP_TRACE=1 (gateway startup timing trace).

  • [ ] .env file protection: Confirm it is in .gitignore. Never commit phone numbers, videos, credentials, or live config.
  • [ ] Enforce HTTPS: Apply TLS via nginx/Caddy for external exposure. Use --bind loopback for internal-only.
  • [ ] Allowlist: Use agents.defaults.allowFrom to restrict access to authorized users only.
  • [ ] Docker security: cap_drop: [NET_RAW, NET_ADMIN], no-new-privileges:true (already applied in compose).
  • [ ] Agent sandbox: Enable agents.defaults.sandbox in untrusted code execution environments.
  • [ ] Dependency vulnerability scanning: Run pnpm audit. Review pnpm-lock.yaml changes — it is a security surface.
  • [ ] Secret scanning: Maintain GitHub CodeQL (codeql.yml) and Zizmor (.github/zizmor.yml) workflows.
  • [ ] SSRF prevention: Use ssrf-policy and ssrf-runtime SDK when plugins access external URLs.
  • [ ] Package integrity: shrinkwrap.json (for npm packages) and dependency patches require explicit approval.
