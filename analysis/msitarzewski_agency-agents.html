4. 아키텍처 분석 (Architecture Analysis)

데이터 흐름 파이프라인

[Source: <division>/*.md]
        ↓
[scripts/convert.sh]
  - YAML 프론트매터 파싱
  - 도구별 형식 렌더링
        ↓
[integrations/<tool>/]
  - cursor → .mdc 파일
  - codex → .toml 파일
  - aider → CONVENTIONS.md (roster)
  - windsurf → .windsurfrules (roster)
  - claude-code → .md (identity/pass-through)
  - kimi → agent.yaml + system.md
        ↓
[scripts/install.sh]
  - 도구 자동 감지
  - 대화형 위저드 또는 --no-interactive
  - ~/.claude/agents/, ~/.cursor/rules/ 등 복사/심링크

아키텍처 패턴

  • 데이터 주도 파이프라인: divisions.json과 tools.json이 스크립트와 CI의 동작을 제어
  • 단일 진실 소스(Single Source of Truth): 두 JSON 파일의 내용이 스크립트 내부 배열, CI 경로 필터와 반드시 일치해야 하며 불일치 시 빌드 실패
  • 완전 정적(Stateless): 런타임 없음, 서버 없음, API 없음
  • InstallKind 분류: per-agent (에이전트당 파일 1개), roster (전체를 단일 파일로 합침), plugin (빌드 아티팩트)
  • lint-agents.sh의 classify_header_target(): Markdown 섹션을 soul(Identity/Rules) 또는 agents(기능 정의)로 분류하여 OpenClaw 등 멀티파일 도구에 대응

8-A. 최종 평가 보고서

강점 (Strengths)

  1. 단일 진실 소스 아키텍처: divisions.json과 tools.json이 스크립트·CI·앱 카탈로그 전체를 구동하며, CI가 이 일관성을 자동으로 강제함. 새 Division이나 Tool 추가 시 한 곳만 수정하면 됨.

  2. 콘텐츠 품질 게이트: lint-agents.sh(프론트매터 검증) + Python shingle 유사도 기반 독창성 검사의 조합으로 단순한 "이름만 바꾼 복제 에이전트"가 머지되는 것을 방지하는 실용적 품질 통제.

  3. 광범위한 멀티툴 지원: 14개 AI 도구에 대한 변환 형식을 installKind(per-agent, roster, plugin)와 format 계약으로 명확히 분류하여 확장성 확보. 동일 소스에서 .md, .mdc, .toml, .yaml 등 다양한 형식 생성.

  4. 운영 의존성 제로: 외부 패키지 의존성 없이 bash + python3(stdlib만) 사용. 어떤 개발 환경에서도 클론 즉시 사용 가능.

  5. 수준 높은 문서화: 1,063줄 README에 퀵스타트, 멀티툴 가이드, 6개 실사용 시나리오, 에이전트 철학까지 포함. 중국어 기여 가이드로 국제 커뮤니티 포용. examples/에 실제 멀티에이전트 협업 결과물 제공.

위험/개선 필요 사항 (Risks & Improvements)

  1. 셸 스크립트 자동화 테스트 부재: install.sh와 convert.sh는 사용자 홈 디렉터리에 파일을 쓰는 핵심 스크립트이나 단위/통합 테스트가 없음. 새 도구 지원 추가 시 회귀 가능성이 높음. Bats(Bash Automated Testing System)나 Docker 기반 설치 검증 추가 권고.

  2. CHANGELOG 및 릴리즈 관리 부재: 에이전트 추가·수정 이력이 git 커밋 메시지에만 존재하며, 구조화된 CHANGELOG나 릴리즈 태깅이 없음. 사용자가 "무엇이 새로 추가됐는지" 파악하기 어려움. GitHub Releases + CHANGELOG.md 도입 권고.

  3. 프롬프트 인젝션 위험: 에이전트 파일 자체가 Markdown이므로 악의적 기여자가 시스템 프롬프트 오버라이드나 탈출 시퀀스를 삽입할 수 있음. 현재 lint 검사는 구조적 검증만 하며 콘텐츠 의미를 검사하지 않음. PR 리뷰어 체크리스트에 "프롬프트 인젝션 패턴 스캔" 항목 추가 및 자동 탐지 스크립트 도입 권고.

  4. CODE_OF_CONDUCT 별도 파일 부재: CONTRIBUTING.md에 행동 강령이 내재되어 있으나 GitHub의 커뮤니티 프로파일에서 별도 파일로 인식되지 않음. CODE_OF_CONDUCT.md 분리 및 Contributor Covenant 채택 권고.

  5. 에이전트 품질의 비균질성: 232개 에이전트의 깊이와 품질이 기여자마다 다를 수 있음. 현재 lint는 프론트매터 필드와 권장 섹션 존재 여부만 확인하며, 실제 콘텐츠 품질(코드 예제의 정확성, 성공 지표의 구체성)은 PR 리뷰어에 전적으로 의존.

도입 권고 (Adoption Recommendation)

기술 도입 관점: 개발팀이나 개인이 AI 코딩 도구를 사용하고 있고 특화된 AI 에이전트 퍼소나를 빠르게 확보하고 싶다면 즉시 도입을 권고한다. 설치 장벽이 사실상 없고(클론 + 셸 스크립트 or 네이티브 앱 클릭), MIT 라이선스로 상업적 사용도 자유로우며, 232개의 에이전트가 대부분의 비즈니스·기술 도메인을 커버한다.

아키텍처 벤치마킹 관점: 이 저장소의 divisions.json + tools.json 기반 단일 진실 소스 패턴, 그리고 installKind 계약으로 다양한 출력 형식을 추상화하는 방식은 콘텐츠 중심 멀티플랫폼 배포를 설계할 때 참고할 만한 훌륭한 패턴이다.

보안 리뷰 관점: 에이전트 파일 자체는 비실행형이므로 직접적 보안 위험은 낮다. 단, install.sh를 프로덕션 환경에서 사용한다면 실행 전 스크립트 감사와 --dry-run 옵션을 활용할 것을 권고한다. 프롬프트 인젝션 리스크는 AI 런타임 레벨의 문제이며, 이 저장소가 단독으로 해결할 수 없는 영역이다.

기여 준비 관점: CONTRIBUTING.md, 이슈 템플릿, PR 템플릿이 완비되어 오픈소스 기여 환경이 잘 갖춰져 있다. 새 에이전트 추가 기여는 매우 낮은 진입 장벽을 갖는다. 단, 셸 스크립트나 CI 인프라 기여는 자동화 테스트가 없으므로 신중한 수동 검증이 필요하다.
