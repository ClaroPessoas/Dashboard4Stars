5. 로컬 빌드 방법 / Local Build

[한국어]

PAI는 전통적인 빌드 단계가 없는 설정 주도(configuration-driven) 시스템입니다. TypeScript 소스는 Bun이 JIT로 실행합니다. 그러나 도구별 실행 방법은 다음과 같습니다:

# 개별 TypeScript 도구 실행 (빌드 불필요)
bun ~/.claude/PAI/TOOLS/BackupRestore.ts backup

# Pulse 데몬 직접 실행 (서비스 대신 개발 테스트용)
cd ~/.claude/PAI/PULSE && bun pulse.ts

# 보안 검증 도구 실행
bun Tools/validate-protected.ts

# 타입 체크 (선택)
cd Releases/v5.0.0/.claude && bunx tsc --noEmit

빌드 결과물: 없음 (Bun JIT 실행). 영구 출력물은 ~/.claude/PAI/MEMORY/ 아래 JSONL 및 Markdown 파일로 누적됩니다.

자주 발생하는 오류와 해결 방법:

오류 원인 해결
Cannot find module 'bun' npm으로 실행 시도 bun 명령으로 변경; npm/npx 절대 사용 금지
PULSE connection refused Pulse 데몬 미실행 bun ~/.claude/PAI/PULSE/pulse.ts 실행 또는 서비스 재시작
TypeScript 타입 오류 잘못된 타입 사용 bunx tsc --noEmit으로 확인 후 수정
PAI_DIR not set 환경 변수 누락 ~/.config/pai/.env 또는 쉘 프로파일에 PAI_DIR 설정

[English]

PAI is a configuration-driven system with no traditional build step. TypeScript sources are executed JIT by Bun. Per-tool execution:

# Run individual TypeScript tools (no build needed)
bun ~/.claude/PAI/TOOLS/BackupRestore.ts backup

# Run Pulse daemon directly (for development testing instead of the service)
cd ~/.claude/PAI/PULSE && bun pulse.ts

# Run security validation tool
bun Tools/validate-protected.ts

# Type check (optional)
cd Releases/v5.0.0/.claude && bunx tsc --noEmit

Build outputs: None (Bun JIT execution). Persistent outputs accumulate as JSONL and Markdown files under ~/.claude/PAI/MEMORY/.

Common build errors and fixes:

Error Cause Fix
Cannot find module 'bun' Attempted to run with npm Use bun command; npm/npx are strictly forbidden
PULSE connection refused Pulse daemon not running Run bun ~/.claude/PAI/PULSE/pulse.ts or restart the service
TypeScript type errors Incorrect type usage Check with bunx tsc --noEmit and fix errors
PAI_DIR not set Missing environment variable Set PAI_DIR in ~/.config/pai/.env or your shell profile

6. 성능 및 확장성 고려사항 / Performance & Scalability

[한국어]

알려진 성능 병목 지점:

  1. 컨텍스트 윈도우 사용량: 세션 시작 시 PRINCIPAL_IDENTITY, DA_IDENTITY, TELOS, PROJECTS, ARCHITECTURE_SUMMARY가 모두 로드됨 (~38% → v5.0.0에서 ~19%로 최적화). hooks/ContextReduction.hook.sh (RTK — Reduced Token Kit)가 Bash 도구 호출을 60-90% 토큰 절감으로 처리.

  2. Pulse 크론 밀도: PULSE.toml에 너무 많은 type=claude 크론을 활성화하면 API 비용이 급증. cost-tracker 크론을 반드시 활성화하여 모니터링할 것.

  3. Memory 파일 증가: MEMORY/OBSERVABILITY/*.jsonl은 모든 도구 호출을 기록. 정기 정리 필요: bash # 오래된 관측 로그 아카이브 (보통 Pulse 크론이 자동 처리) bun ~/.claude/PAI/TOOLS/SessionHarvester.ts --recent 20

수평/수직 확장:

PAI는 단일 사용자 로컬 시스템입니다. "확장"은 전통적 의미가 아니라: - 수직 확장: 더 강력한 로컬 머신으로 이전 (더 빠른 Pulse 크론 응답) - 에이전트 병렬화: Delegation 스킬의 6가지 병렬화 패턴 활용 - Arbol (클라우드 실행): PAI/DOCUMENTATION/Arbol/ArbolSystem.md — 장기 실행 태스크를 클라우드로 오프로드 (실험적)

캐싱 전략:

  • hooks/LastResponseCache.hook.ts — 마지막 응답 캐시
  • bun rtk gain — 컨텍스트 감소 절감량 확인
  • Inference.ts (bun TOOLS/Inference.ts fast|standard|smart) — 태스크별 모델 라우팅으로 비용 최적화

모니터링 및 로깅:

# API 비용 모니터링
bun ~/.claude/PAI/TOOLS/CostTracker.ts log
bun ~/.claude/PAI/TOOLS/CostTracker.ts alert-check

# 도구 활동 로그 실시간 확인
tail -f ~/.claude/PAI/MEMORY/OBSERVABILITY/tool-activity.jsonl

# Pulse 관측 대시보드
open http://localhost:31337    # 대시보드에서 Observability 탭 확인

[English]

Known performance bottlenecks:

  1. Context window usage: At session start, PRINCIPAL_IDENTITY, DA_IDENTITY, TELOS, PROJECTS, and ARCHITECTURE_SUMMARY all load (~38% → optimized to ~19% in v5.0.0). hooks/ContextReduction.hook.sh (RTK — Reduced Token Kit) processes Bash tool calls with 60-90% token savings.

  2. Pulse cron density: Enabling too many type=claude cron jobs in PULSE.toml causes API costs to spike. Always enable the cost-tracker cron for monitoring.

  3. Memory file growth: MEMORY/OBSERVABILITY/*.jsonl records every tool call. Periodic cleanup is needed: bash # Archive old observability logs (usually auto-handled by Pulse crons) bun ~/.claude/PAI/TOOLS/SessionHarvester.ts --recent 20

Horizontal / vertical scaling:

PAI is a single-user local system. "Scaling" means: - Vertical: Migrating to a more powerful local machine (faster Pulse cron response) - Agent parallelization: Using the Delegation skill's 6 parallelization patterns - Arbol (cloud execution): PAI/DOCUMENTATION/Arbol/ArbolSystem.md — offload long-running tasks to cloud (experimental)

Caching strategy:

  • hooks/LastResponseCache.hook.ts — caches last response
  • bun rtk gain — check context reduction savings
  • Inference.ts (bun TOOLS/Inference.ts fast|standard|smart) — per-task model routing for cost optimization

Monitoring and logging:

bun ~/.claude/PAI/TOOLS/CostTracker.ts alert-check

# Real-time tool activity log
