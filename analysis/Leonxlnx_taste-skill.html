상세 분석

1. 목적 및 범위

한국어
Taste Skill은 AI 코딩 에이전트가 프론트엔드 UI를 생성할 때 발생하는 "슬롭(slop)" — 즉, 획일적이고 예측 가능하며 낮은 퀄리티의 디자인 — 을 방지하기 위한 포터블 에이전트 스킬 파일 컬렉션이다. 사용자는 Codex, Cursor, Claude Code 등 AI 코딩 도구에 SKILL.md 파일을 주입함으로써 에이전트의 UI 생성 방향을 "Anti-Slop"으로 조정한다. 랜딩 페이지·포트폴리오·리디자인을 주 대상으로 하며, 대시보드·데이터 테이블·멀티스텝 폼은 명시적으로 범위 외(Out of Scope)로 선언되어 있다.

English
Taste Skill is a collection of portable agent "skill" files designed to override AI agents' default tendency to produce templated, low-quality frontend UIs. By injecting a SKILL.md file into a coding agent session, developers constrain the agent's design output to follow high-agency, anti-generic rules. Target use cases: landing pages, portfolios, redesigns. Explicitly excluded: dashboards, data tables, native mobile, realtime collaboration UIs.

3. 소프트웨어 스택

이 프로젝트는 실행 가능한 소프트웨어가 아닌 프롬프트 엔지니어링 콘텐츠 저장소다. 배포 매체: npx skills add(agent-skills CLI). 스킬이 지향하는 구현 대상 스택: React/Next.js (RSC), Tailwind v4, Motion(motion/react), GSAP+ScrollTrigger, Phosphor/HugeIcons 아이콘.

4. 아키텍처 분석

핵심 추상화: 3 Dials 모델

  • DESIGN_VARIANCE (1=완전 대칭 ~ 10=예술적 혼돈)
  • MOTION_INTENSITY (1=정적 ~ 10=시네마틱)
  • VISUAL_DENSITY (1=갤러리/공기감 ~ 10=조종석/데이터 밀집)

에이전트는 사용자의 브리프를 읽어 다이얼 값을 추론하고, 이를 기반으로 레이아웃·모션·타이포그래피 결정을 내린다. v1 대비 v2는 섹션 수 10→15, 브리프 추론(§0) 추가, 금지 패턴 대폭 강화, Pre-Flight Check 7→60+개 항목으로 대폭 확장되었다.

gpt-tasteskill의 "Python RNG" 패턴: 프롬프트 문자 수를 시드로 random.choice()를 시뮬레이션하여 에이전트가 매번 다른 레이아웃을 선택하도록 강제하는 독창적 접근.

5. 품질 및 테스트

공식 자동화 테스트 없음. CI/CD 없음. "프로덕션 테스트"는 실제 AI 에이전트로 수동 실행 후 결과물 검토 방식. CHANGELOG의 "round-5 hardening from test-13/14/15"가 이를 반영. §9의 금지 패턴 목록은 이러한 반복 테스트에서 실증적으로 도출된 AI Tell 목록이다.

강점

  1. 실증적 접근: v2의 금지 패턴 목록(§9)은 실제 LLM 생성물 반복 분석에서 도출된 실증적 근거를 가진다. em-dash 완전 금지, 프리미엄 소비재 팔레트 금지 등은 이론이 아닌 관측된 패턴이다.
  2. 다이얼 기반 설정 추상화: 3-Dials 모델은 단순하면서도 표현력이 높으며, 대화 중 재설정 가능하도록 에이전트 친화적으로 설계되었다.
  3. 범위 경계의 명시적 선언: §13 Out of Scope 섹션으로 스킬의 한계를 솔직하게 선언한다.
  4. 에이전트 간 이식성: npx CLI, 직접 파일 복사, 대화 붙여넣기 등 다양한 설치 경로를 지원하며 특정 에이전트에 종속되지 않는다.
  5. 연구 기반 개발: research/laziness/에 LLM 출력 절단의 근본 원인과 해결책을 체계적으로 문서화했다.

위험 및 개선 필요 사항

  1. 블록 라이브러리(§12) 미구현: skills/taste-skill/blocks/ 스키마만 선언, 실제 파일 없음. v2.0.0 stable의 핵심 미완성 작업.
  2. 자동화 테스트·CI 부재: 수동 에이전트 실행에 전적으로 의존. 최소한 Markdown 린터와 YAML 프런트매터 검증 자동화 필요.
  3. 거버넌스 문서 부재: CONTRIBUTING.md, CODE_OF_CONDUCT.md, 이슈/PR 템플릿 없어 커뮤니티 기여 진입 장벽.
  4. v2 안정성 불확실: 기본값이 된 v2 experimental이 여전히 활발히 변경 중.
  5. 스킬 간 규칙 중복: 13개 SKILL.md가 유사 규칙을 개별 정의, 공통 규칙 중앙화 메커니즘 없어 일관성 유지 어려움.
