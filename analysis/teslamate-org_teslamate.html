2. 상세 분석

Step 1. 목적과 범위 (Purpose & Scope)

TeslaMate는 Tesla 차량 소유자를 위한 자가 호스팅 텔레메트리 로거다. Tesla 공식 앱이 제공하지 않는 고해상도 데이터(위치, 속도, 에너지 소비, 배터리 건강도, 흡혈 방전 등)를 Tesla Owner API로 폴링하여 PostgreSQL에 저장하고, 동봉된 Grafana 대시보드 21개로 시각화한다. MQTT 퍼블리시를 통해 Home Assistant·Node-RED·Telegram과의 통합도 지원한다.

  • 타입: 애플리케이션 (셀프호스팅 SaaS 형태로 배포)
  • 대상 사용자: Tesla 차량 소유자, 홈오토메이션 애호가, 데이터 분석 관심자
  • 해결 문제: 공식 앱 대비 고정밀 로깅, 뱀파이어 드레인 최소화, 장기 배터리 건강도 추적, 다차량 관리

Step 4. 아키텍처 분석 (Architecture)

4.1 진입점

4.3 아키텍처 패턴

  • Domain-Driven Layering: TeslaApi(인프라/외부) → TeslaMate(도메인) → TeslaMateWeb(프레젠테이션)
  • State Machine per Vehicle: 각 차량이 독립적인 GenStateMachine 프로세스 — online, asleep, driving, charging 등의 상태를 OTP 방식으로 관리. 상태 전이 실패가 다른 차량에 영향을 미치지 않음.
  • Pre-Online Check Pattern: MCU2 차량의 가짜 온라인 이벤트를 스트리밍 API의 power=nil 신호로 구분하는 섬세한 로직 (pre_online_check 필드).
  • Phoenix LiveView: 서버 렌더링 실시간 UI — 별도 API/GraphQL 없이 LiveView가 상태 동기화 담당
  • Circuit Breaker: fuse 라이브러리로 외부 API 과부하 방지

3. 강점 (Strengths)

  1. OTP 기반 결함 격리: 차량별 GenStateMachine 프로세스 + Supervisor 전략으로, 특정 차량의 API 오류가 다른 차량이나 전체 시스템에 영향을 미치지 않는 고가용 설계.

  2. 정교한 차량 상태 관리: pre_online_check 패턴으로 MCU2 차량의 허위 온라인 이벤트를 스트리밍 API로 구분 — Tesla API의 실제 특성에 맞춘 도메인 지식이 코드에 반영.

  3. 포괄적 CI 파이프라인: Dialyzer(타입), Credo(스타일), treefmt(포매팅), typos(오탈자), OSV-Scanner(취약점), 실 DB 통합 테스트, 커버리지 리포트까지 단일 레포에서 완결.

  4. 공급망 보안 우수: 모든 GitHub Actions SHA 핀 + OSV-Scanner PR 차단 + Dependabot 전 생태계 커버 — 오픈소스 프로젝트로서 이례적으로 높은 수준.

  5. 운영 성숙도: 2019년부터 100개 마이그레이션 + 3000줄 CHANGELOG + OpenSSF 배지 + CLA 자동화 — 장기 유지보수 의지와 커뮤니티 신뢰도 확립.

4. 위험 / 개선 필요 사항 (Risks & Improvements)

  1. 빌트인 인증 부재: 네트워크 경계에 전적으로 의존하는 보안 모델은 설정 실수 시 모든 사용자 데이터(주행 위치, 충전 기록) 노출 위험. VPN/Tailscale 설정 가이드를 문서화했지만, 앱 레벨 인증 옵션(기본 비활성화 옵션이라도) 추가가 심층 방어 관점에서 권고됨.

  2. 커버리지 하한선 미설정: coveralls.json의 "minimum_coverage": 0 — CI가 커버리지 하락을 감지하지 않음. 단계적 목표치(예: 70%) 설정으로 회귀 방지 강화 필요.

  3. 암호화 키 관리 취약점: ENCRYPTION_KEY 미설정 시 재시작마다 새 키 생성 → Tesla 토큰 재입력 필요. 운영 환경에서 흔한 실수이며, 경고 메시지가 있으나 키 로테이션이나 시크릿 관리 통합(Vault, k8s Secrets 등)은 미지원.

  4. Tesla API 의존성 단일 실패점: Tesla 공식 API 변경/인증 방식 변경 시 전체 기능 장애. v4.0.x에서 리프레시 토큰 이슈 핫픽스 경험이 이를 방증. API 변경 감지 자동화 또는 캐내리 모니터링 부재.

  5. 공간 데이터 처리 제한: 위치 데이터 저장 및 쿼리에 PostGIS 없이 순수 Postgres를 사용 — 복잡한 지오펜스 쿼리와 지도 집계는 Raw SQL 의존. 향후 확장 시 병목 가능.

5. 도입 권고 (Recommendation)

기술 도입 / 참조 아키텍처 벤치마킹 관점:

TeslaMate는 Elixir + OTP 생태계의 실전 레퍼런스로서 높은 가치를 가진다. 특히 다음 케이스에 권고:

  • IoT 데이터 로거 설계 참조: 디바이스(차량)당 독립 GenStateMachine + PubSub 패턴은 수십~수백 개 엔드포인트를 관리하는 IoT 시스템의 좋은 벤치마크.
  • Tesla 차량 데이터 분석: 자가 호스팅 환경에서 개인 Tesla 데이터를 완전히 제어하고 싶은 사용자에게 즉시 운영 가능한 수준.
  • 오픈소스 운영 성숙도 학습: OpenSSF Best Practices, CLA 자동화, Actions SHA 핀, OSV-Scanner 통합 등은 오픈소스 프로젝트 운영의 모범 사례로 인용 가능.

주의사항: - 상업적 파생물에는 AGPL-3.0의 네트워크 서비스 조항이 적용되므로, SaaS 형태로 제공 시 소스 공개 의무 발생. - 빌트인 인증이 없으므로 퍼블릭 인터넷 직접 노출은 절대 금지. 반드시 VPN/리버스 프록시 뒤에 배치 필요. - Tesla API는 비공식 API로 언제든 변경될 수 있으며, 이는 서비스 중단 위험 상존.

종합 평가: ★★★★☆ (4.5/5) — OTP 설계 우수성과 운영 성숙도가 뛰어나며, 인증 부재와 외부 API 의존이 주요 리스크.
