프로젝트 개요 / Project Overview

FluidVoice is an open-source macOS voice-to-text dictation application built natively in Swift/SwiftUI. It supports multiple on-device and cloud-based speech recognition engines, optional AI post-processing, a voice-controlled Command Mode, and a Write Mode for inline text rewriting—all with a privacy-first, local-first design philosophy.

Step 1. 목적 및 범위 / Purpose and Scope

[한국어] FluidVoice는 macOS(Sequoia 15.0+)용 오픈소스 음성-텍스트 받아쓰기 애플리케이션이다. 주요 문제 해결: - 클라우드 의존 없는 온디바이스 고품질 음성 인식 (Apple Silicon 기반 Parakeet, Nemotron, CoreML 모델 활용) - 음성으로 맥 시스템 제어(Command Mode), 모든 앱 텍스트 필드에 직접 텍스트 입력(Write Mode) - 선택적 AI 후처리(OpenAI, Groq, Anthropic, Gemini, Ollama 등) 또는 완전 로컬 "Fluid Intelligence"

대상 사용자: 개인 사용자, 작가, 개발자, 접근성 필요 사용자 등 macOS에서 효율적으로 타이핑 대신 말하길 선호하는 사람들.

분류: 네이티브 macOS 애플리케이션 (오픈소스 핵심, 비공개 Fluid Intelligence AI 런타임 별도).

[English] FluidVoice is a native macOS dictation app that prioritizes on-device processing. The open-source repository contains the full dictation engine, all UI, analytics, and a built-in local HTTP API server. "Fluid Intelligence" (the private LLM runtime) is intentionally excluded from the public repo to sustain free development.

Step 4. 아키텍처 분석 / Architecture Analysis

진입점

  • @main FluidApp (fluidApp.swift:13) — SwiftUI 라이프사이클
  • AppDelegate — NSApplicationDelegate, 업데이트 체크, LocalAPIServer 시작, 분석 부트스트랩

아키텍처 패턴

서비스 컨테이너 패턴: AppServices.shared가 ASRService, AudioHardwareObserver 등 무거운 서비스를 지연 초기화로 보유. UI 준비 신호(signalUIReady()) 후에만 서비스 활성화 — EXC_BAD_ACCESS 런치 크래시 방지를 위한 방어적 전략이 코드 전반에 상세히 문서화됨.

Strategy 패턴 (TranscriptionProvider): TranscriptionProvider 프로토콜을 구현하는 FluidAudioProvider, WhisperProvider, NemotronProvider, AppleSpeechProvider, ExternalCoreMLTranscriptionProvider 등이 런타임 교체 가능.

Actor 기반 동시성: @MainActor로 UI 상태 보호, TranscriptionExecutor actor로 CoreML 순차 직렬화 (동시 접근 방지).

로컬 API 서버: LocalAPIServer (NWListener 기반, loopback-only)가 외부 툴(n8n, Raycast 등)과 음성 인식/딕셔너리 API를 HTTP로 제공.

LLM 통합 레이어: LLMClient가 OpenAI Chat Completions API, Responses API(o1/o3/gpt-5), SSE 스트리밍, thinking 토큰 추출, tool calls를 단일 인터페이스로 추상화.

레이어 구조

Presentation (SwiftUI Views/UI) 
    ↓
AppServices / AppNavigationRouter
    ↓
Services (ASRService, LLMClient, CommandModeService, RewriteModeService)
    ↓
Providers (TranscriptionProvider implementations)
    ↓  
Persistence (SettingsStore, KeychainService, HistoryStore)
    ↓
Platform (AVFoundation, CoreML, Keychain, Network.framework)

주요 특징

  • SettingsStore가 4,765 LOC의 거대한 UserDefaults 래퍼로, 사실상 앱 전체 상태 관리 역할을 함
  • ContentView.swift가 4,178 LOC — 뷰 로직이 과도하게 집중됨
  • ASRService.swift가 3,326 LOC — 단일 책임 원칙 위반 경계에 근접
  • Combine PassthroughSubject로 오디오 레벨 퍼블리셔 구현

Step 8. 최종 분석 결과 / Final Analysis

강점 / Strengths

  1. 강력한 Swift Concurrency 설계: @MainActor, actor, async/await를 일관되게 사용하여 audio pipeline의 race condition과 EXC_BAD_ACCESS 크래시를 방어적으로 처리. TranscriptionExecutor actor로 CoreML 직렬화, AppServices 지연 초기화로 SwiftUI AttributeGraph 크래시 회피 — 코드 내에 상세한 이유가 문서화되어 있어 유지보수성이 높다.

  2. 모델 불가지론적 추상화(Strategy Pattern): TranscriptionProvider 프로토콜을 통해 Parakeet, Whisper, Nemotron, Cohere, Apple Speech를 동일 인터페이스로 교체 가능. 새 모델 추가 시 기존 코드를 최소한으로 수정.

  3. 로컬 우선 + 선택적 클라우드: 음성/텍스트 데이터가 기본으로 기기를 벗어나지 않음. API 키는 Keychain 저장, 분석은 익명 opt-out 가능. 보안 설계가 사용자 프라이버시를 적극 고려.

  4. 실용적 테스트 전략: Whisper Tiny 실제 모델을 CI에서 다운로드 후 실제 오디오 파일로 E2E 검증하는 방식은 전사 파이프라인 전체를 통합적으로 커버. HTML injection 탐지, dictionary 전송 규칙, 업데이터 정렬 로직 등 비즈니스 위험이 높은 영역의 테스트가 충실함.

  5. 내장 로컬 HTTP API 서버: loopback-only NW.framework 기반 서버로 n8n/Raycast/자동화 도구와의 통합을 외부 의존 없이 제공. 인증 없이 loopback 제한으로 보안 위험 최소화.

위험/개선 필요 사항 / Risks and Areas for Improvement

  1. God Class 안티패턴: SettingsStore.swift (4,765 LOC), ContentView.swift (4,178 LOC), ASRService.swift (3,326 LOC)는 SwiftLint 임계값 상한에 도달하거나 초과. 단일 책임 원칙 위반으로 테스트 단리 어렵고, 병렬 기여 시 merge conflict 위험이 큼.

  2. cs.disable-library-validation 엔타이틀먼트: 모든 코드 서명 없는 dylib 로드를 허용 — Fluid Intelligence 런타임 통합을 위한 것이나, 악성 라이브러리 인젝션 공격 표면을 넓힘. App Store 배포 불가 요소이며, Notarization 경고 발생 가능.

  3. 브랜치 핀 의존성: FluidAudio, DynamicNotchKit, SwiftWhisper가 안정 버전 태그가 아닌 브랜치/커밋 해시로 고정. 업스트림 breaking change가 자동으로 들어올 수 있어 재현성과 공급망 보안이 취약함. Dependabot/Renovate 및 버전 태그 핀 적용 권장.

  4. SECURITY.md 및 취약점 공개 정책 부재: 보안 이슈 보고 채널이 정의되어 있지 않음. 오픈소스 프로젝트로서 CVE 관리, 책임 있는 공개 프로세스 없음.

  5. 단일 기여자 버스 팩터: 커밋 내 저자 정보(Barathwaj Anandan)와 pre-commit hook에 개인 Team ID(V4J43B279J)가 하드코딩 — 사실상 단일 개발자 프로젝트. 기여자 온보딩 문서(CONTRIBUTING.md) 부재, CODE_OF_CONDUCT.md 부재, 변경로그(CHANGELOG.md) 부재로 외부 기여자 유입 장벽이 높음.

[English]

For architectural benchmarking and as a reference implementation of native macOS Swift Concurrency patterns (actor isolation, @MainActor, async audio pipelines, CoreML integration), FluidVoice is an excellent, production-grade open source example well above average quality for its domain.

For enterprise deployment or embedding as a dependency: review the GPLv3 copyleft implications, the cs.disable-library-validation entitlement (which widens the dylib attack surface), and the single-maintainer risk before committing. Add Dependabot, SECURITY.md, and pin all dependencies to stable version tags before treating this as a supply-chain-safe dependency.

For end-user adoption: FluidVoice is a well-engineered, privacy-first dictation tool with broad model support and an active development cadence — recommended without reservation for individual use.
