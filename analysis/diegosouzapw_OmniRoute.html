1. 목적 및 범위 (Purpose & Scope)

OmniRoute는 통합 AI 프록시/라우터로, 모든 LLM 공급자에 대해 단일 OpenAI 호환 엔드포인트를 제공한다. 핵심 가치 제안은 다음과 같다:

  • 공급자 통합: 236개 LLM 공급자(50개 이상 무료), 월 1.6B 무료 토큰 집계
  • 자동 장애조치: 4계층(구독→API키→저렴→무료) 자동 폴백
  • 토큰 압축: RTK+Caveman 이중 압축(도구 집약 세션 평균 ~89% 절감)
  • 라우팅 지능: 17가지 전략(우선순위, 가중치, 비용 최적화, context-relay, fusion 등)
  • 프로토콜 지원: MCP(94개 도구), A2A JSON-RPC 2.0, OpenAI 호환 REST API
  • 플랫폼: 웹, Electron 데스크톱, Termux, PWA, NPM 패키지

대상 사용자: AI 개발자, 프롬프트 엔지니어, 자체 호스팅 LLM 운영자, 다중 공급자 비용을 최적화하려는 개인/팀.

4. 아키텍처 분석 (Architecture)

요청 파이프라인

클라이언트
  → /v1/chat/completions (Next.js App Router)
  → CORS → Zod 유효성 검사 → 인증 → 정책 검사 → 프롬프트 인젝션 감지
  → handleChatCore() [open-sse/handlers/chatCore.ts]
    → 캐시 확인 → 속도 제한 → 콤보 라우팅?
      → resolveComboTargets() → handleSingleModel() (타겟별)
    → translateRequest() → getExecutor() → executor.execute()
      → upstream fetch() → 재시도/백오프
    → 응답 변환 → SSE 스트림 또는 JSON
    → Responses API인 경우: TransformStream

핵심 아키텍처 패턴

① 3레이어 복원력 시스템: - Provider Circuit Breaker: 공급자 전체 차단 (CLOSED→DEGRADED→OPEN→HALF_OPEN). 임계값: OAuth 3회/60초, API 키 5회/30초, 로컬 2회/15초 - Connection Cooldown: 단일 키/계정 임시 제외. 지수 백오프 (baseCooldownMs * 2^failureIndex) - Model Lockout: 공급자+연결+모델 단위 격리 (모델별 쿼터 한도 시 활용)

② 콤보 라우팅 엔진 (open-sse/services/combo.ts): 17가지 전략: priority, weighted, fill-first, round-robin, P2C, random, least-used, cost-optimized, reset-aware, reset-window, headroom, strict-random, auto, lkgp, context-optimized, context-relay, fusion

③ Fusion 전략 (open-sse/services/fusion.ts): 모델 패널에 병렬 팬아웃 → 판정 모델이 단일 최종 답변 합성. 쿼럼 유예(quorum grace) 및 낙오자(straggler) 처리 포함.

④ 압축 파이프라인: 9개 압축 엔진 합성 (RTK + Caveman 이중 적용). 예산 강제(budget enforcement)로 과도한 압축 차단. 결과: 평균 ~89% 토큰 절감(도구 집약 세션).

⑤ MCP 서버 (open-sse/mcp-server/): 94개 도구, 30개 범위, 3개 전송(stdio/SSE/Streamable HTTP). 도구 호출은 mcp_audit 테이블에 기록.

⑥ A2A 프로토콜 (src/lib/a2a/): JSON-RPC 2.0, 6개 스킬(smart-routing, quota-management, provider-discovery, cost-analysis, health-report).

⑦ 메모리 파이프라인 (src/lib/memory/): FTS5 전문 검색 + Qdrant 벡터 저장소. 임베딩: 로컬(HuggingFace transformers ONNX) + 원격(API). 요약/재색인/캐시 포함.

⑧ 도메인 정책 엔진 (src/domain/): 정책 검사, 비용 규칙, 쿼터 캐시, 폴백 정책, 잠금 정책, 그레이드풀 저하(graceful degradation) 로직.

보안 아키텍처

가드레일 (옵트인): - PII 마스킹 (src/lib/guardrails/piiMasker.ts) — 기본값 false - 프롬프트 인젝션 감지 (promptInjection.ts) — 시스템 오버라이드/역할 탈취/탈옥 패턴 차단 - 비전 브리지 (visionBridge.ts) — 이미지 안전 검사

공개 자격증명 보호: OAuth client_id/secret은 resolvePublicCred()(open-sse/utils/publicCreds.ts) XOR 마스킹 패턴 의무 사용. 문자열 리터럴 금지 (Hard Rule #11).

DB 암호화: STORAGE_ENCRYPTION_KEY로 SQLite 암호화 (AES-256-GCM), 키 버전 회전 지원.

강점 (Strengths)

  1. 포괄적인 복원력 아키텍처: 3레이어 독립 장애 격리(공급자→연결→모델)가 소프트웨어적으로 정밀하게 분리되어 있다. 회로 차단기의 지연 복구(lazy recovery) 패턴은 만료된 OPEN 상태가 영구 제외로 남지 않도록 보장한다.

  2. 업계 최고 수준의 품질 게이트 시스템: ~48개 자동화 게이트(래칫 기반)가 커버리지, 복잡도, 타입 커버리지, 번들 크기, CodeQL 경고를 방향성 있게 강제한다. 뮤테이션 테스트(Stryker)를 모듈별 기준선으로 관리하는 것은 단순 커버리지 게이트보다 훨씬 강력한 회귀 방어다.

  3. 보안 심층 방어: 오류 위생화 의무 패턴, XOR 마스킹 공개 자격증명, 3단계 라우트 가드(로컬 전용 프로세스 생성 라우트 분리), PII 옵트인 설계(기본값 off로 데이터 무결성 보호)가 일관된 보안 철학을 보여준다.

  4. 극도로 발달한 문서화 생태계: AGENTS.md, CLAUDE.md, GEMINI.md, docs/ 16개 디렉터리, 44개 로케일, llm.txt, OpenAPI 190KB — AI 에이전트와 인간 개발자 모두를 위한 계층화된 문서 전략. check:fabricated-docs 게이트로 문서 정확성을 코드로 강제하는 것은 매우 드문 패턴이다.

  5. 다층 배포 유연성: 단일 Docker 이미지로 4개 런타임 프로파일(base/web/cli/host) 제공, Qdrant/Redis/bifrost 사이드카 선택 구성, Fly.io/VPS/Electron/NPM/Termux 동시 지원 — 자체 호스팅부터 엔터프라이즈 배포까지 대응한다.

위험/개선 필요 사항 (Risks & Improvement Areas)

  1. 단일 기여자 집중도 (Bus Factor = 1): CHANGELOG, 커밋 이력, 릴리스 워크플로 전체가 diegosouzapw 단일 계정에 의존한다. 프로젝트 연속성 계획이나 공동 유지 관리자가 없으며, CODEOWNERS 파일도 단일 오너로 추정된다. 핵심 유지 관리자 이탈 시 프로젝트 전체가 위험에 처할 수 있다.

  2. 지나친 복잡도와 진입 장벽: 64개 src/lib 서브모듈, 80개 익스큐터, 94개 DB 모듈, 21개 하드 규칙, ~48개 품질 게이트는 신규 기여자에게 매우 높은 진입 장벽이다. chatCore.ts(176KB) 단일 파일은 유지 관리 위험이 있다. TypeScript strict: false 설정은 타입 안전성 갭을 허용한다.

  3. 취약점 래칫 수치: quality-baseline.json에 취약점 수 기준선이 10개로 기록되어 있다. "osv-scanner로 탐지된 10개 취약점을 허용"하는 래칫은 단기 기술 부채지만, 프로덕션 환경에서는 지속적인 관리가 필요하다. gitleaks 3건(공개 OAuth 키 false positive)도 해소가 필요하다.

  4. ESLint 경고 누적: quality-baseline.json에 ESLint 경고 4,121건이 기록되어 있으며, 이는 open-sse/와 tests/에서 @ts-expect-error/any 사용 누적 결과다. --require-tighten 게이트 적용이 예정되어 있으나 현재는 미실행 상태다. 장기적으로 코드 품질 신호를 오염시킬 수 있다.

  5. 웹 쿠키 기반 공급자의 신뢰성/법적 위험: 80개 익스큐터 중 상당수(ChatGPT-web 118KB, Gemini-web, Claude-web, Grok-web 등)가 비공식 웹 인터페이스 리버스 엔지니어링을 기반으로 한다. 이는 공급자 ToS 위반 위험, 잦은 브레이킹 변경으로 인한 유지 관리 부담, 법적 불확실성을 동반한다.

기술 도입 (Technology Adoption)

권고 수준: 조건부 강력 권고 (Conditionally Strongly Recommended)

OmniRoute는 다중 LLM 공급자를 통합 관리해야 하는 자체 호스팅 환경에서 현존하는 가장 완성도 높은 오픈소스 AI 게이트웨이다. 복원력 아키텍처, 품질 게이트 시스템, 보안 설계 모두 엔터프라이즈 수준이다.

도입에 적합한 시나리오: - 다중 LLM 공급자 비용을 최적화하려는 자체 호스팅 팀 - OpenAI 호환 단일 엔드포인트가 필요한 AI 인프라 통합 - MCP/A2A 프로토콜 지원이 필요한 에이전트 오케스트레이션 - 토큰 압축으로 비용 절감이 필요한 대용량 LLM 워크로드

주의 사항: - 법적 검토 필수: 웹 쿠키 기반 공급자 사용 시 해당 공급자 ToS 검토 후 사용 범위 결정 - 단일 기여자 위험 인지: 포크 유지 관리 계획 수립 권고 - 운영 팀 역량 필요: ~48개 품질 게이트와 복잡한 아키텍처는 숙련된 Node.js/TypeScript 팀을 전제
