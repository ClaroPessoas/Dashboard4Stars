강점 / Strengths

  1. 업계 최빠른 캡처 속도: Claude Sonnet 5 (2026-07-01), Claude Opus 4.8, GPT-5.5 등 신규 모델 출시 직후 수일 내에 시스템 프롬프트가 수록됨. 경쟁 저장소 대비 리드타임이 현저히 짧음.

  2. 광범위한 벤더 커버리지: Anthropic, OpenAI, Google, xAI, Microsoft, Meta, Mistral, Perplexity, Qwen, Cursor 등 주요 AI 공급사를 망라하며, 각 제품의 다양한 변형(API vs. 웹앱, 도구 포함 vs. 미포함, 모델 버전별)까지 체계적으로 수집.

  3. 자동화된 트래픽 분석 인프라: Python으로 구현된 일일 트래픽 누적 시스템이 GitHub Actions와 연동되어 참조자(referrer), 페이지뷰, 별(star) 획득 추이를 시계열로 관리함. self-contained HTML 대시보드까지 자동 생성.

  4. 최소 마찰 공개 라이선스: CC0 1.0(퍼블릭 도메인)으로 큐레이션 작업을 공개, 재사용·재배포에 법적 장벽 없음. .gitattributes를 통한 공백 보존으로 프롬프트 원문 재현성 확보.

  5. 미디어 신뢰도 및 커뮤니티 영향력: Washington Post 등 주요 언론 보도, Trendshift 트렌딩 진입, star history 성장 차트로 확인되는 실질적 영향력. AI 투명성 담론의 1차 자료(primary source)로 자리매김.

위험/개선 필요 사항 / Risks & Areas for Improvement

  1. 법적·윤리적 취약성: 수록된 프롬프트는 각 AI 기업의 독점적 지식재산일 가능성이 높음. OpenAI, Google, Anthropic 등의 서비스 이용약관(ToS)은 시스템 프롬프트 추출·공개를 명시적으로 금지하거나 제한할 수 있음. CC0는 기여자의 큐레이션에만 적용되며, 원본 콘텐츠 저작권은 별개 문제. 현재 SECURITY.md, 법적 고지, DMCA 대응 절차 전무.

  2. 단일 유지관리자 의존(Bus Factor = 1): 전체 저장소가 단 1인에 의해 운영됨. 유지관리자 이탈 시 프로젝트 전체가 방치될 위험. 공동 관리자(co-maintainer) 없음, 이슈 라벨·PR 트리아지 시스템 없음.

  3. 콘텐츠 무결성 검증 부재: 수록된 프롬프트가 실제 해당 AI의 시스템 프롬프트인지 검증하는 자동화 프로세스 없음. 악의적 기여자가 조작된 프롬프트를 제출할 경우 탐지 메커니즘 없음 (README에 Claude가 진본임을 확인하는 스크린샷이 있으나 이것만으로는 충분하지 않음).

  4. 트래픽 자동화의 보안 허점: accumulate-traffic.py가 subprocess.check_output으로 git show origin/traffic:...을 실행하는 패턴은 경로 인젝션 위험성이 있음. 또한 GitHub GraphQL API를 urllib로 직접 호출하는 방식은 토큰 만료·레이트 리밋 처리가 미흡.

  5. 버전 이력 및 변경 추적 체계 없음: AI 모델 버전별 프롬프트 변화를 비교할 수 있는 구조화된 diff 링크가 일부만 제공됨 (Claude Fable 5 vs. Opus 4.8 diff 예시). 자동화된 버전간 diff 생성 파이프라인, CHANGELOG, 시간별 프롬프트 진화 검색 기능이 부재.

총평

asgeirtj/system_prompts_leaks는 AI 시스템 프롬프트 아카이브 분야에서 사실상 표준(de facto standard)으로 자리잡은 저장소이다. 단일 기여자에 의해 운영됨에도 불구하고 업데이트 빈도, 커버리지의 폭, 미디어 공신력 측면에서 경쟁 자료를 압도한다.

연구자·개발자 관점: 직접 참조 및 포크를 적극 권장한다. 단, 수록 콘텐츠를 상업적 목적으로 활용하거나 파생 제품을 만들 경우 반드시 원본 AI 기업의 ToS를 검토해야 한다.

프로젝트 지속가능성 관점: 현재의 Bus Factor 1 구조는 장기 신뢰성의 핵심 리스크다. 관심 있는 기여자는 적극적인 PR·이슈 참여를 통해 공동 관리 체계 구축에 기여하는 것이 바람직하다.

법적 리스크 관점: 프롬프트 수집·공개 활동 자체는 법적 회색 지대에 존재한다. 저장소 자체의 CC0 라이선스는 큐레이션 작업에만 적용되므로, 수록된 프롬프트를 재활용할 때는 원본 콘텐츠에 대한 독립적인 법적 검토가 필요하다.
