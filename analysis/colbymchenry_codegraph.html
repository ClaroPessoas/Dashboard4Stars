1. 목적 및 범위 / Purpose & Scope

EN: CodeGraph is a local-first code intelligence library, CLI, and MCP server that parses source code via tree-sitter, stores the resulting symbol graph in SQLite, and exposes it to AI coding agents over the MCP protocol. Its primary value proposition is reducing AI agent cost and latency by replacing repetitive file-scanning (grep/glob/Read tool calls) with direct graph queries. Target users are developers using Claude Code, Cursor, Codex CLI, or opencode on medium-to-large codebases.

KO: CodeGraph는 로컬 우선 코드 인텔리전스 라이브러리·CLI·MCP 서버입니다. tree-sitter로 소스를 파싱해 SQLite에 심벌 그래프를 저장하고, MCP 프로토콜로 AI 에이전트에게 노출합니다. 핵심 가치는 에이전트가 반복적인 파일 탐색(grep·glob·Read) 대신 그래프를 직접 쿼리해 토큰 비용과 응답 시간을 절감하는 것입니다. 7개 실제 오픈소스 프로젝트 벤치마크에서 평균 35% 비용 절감·70% 도구 호출 감소가 측정되었습니다.

4-2. 주요 아키텍처 패턴

  • 파이프라인 + 레이어드 아키텍처: 각 계층이 명확히 분리되어 있고 단방향 의존성을 유지
  • 어댑터 패턴: SQLite 백엔드 선택 (sqlite-adapter.ts) — native/wasm 투명 전환
  • 플러그인/레지스트리 패턴: installer/targets/registry.ts — 새 에이전트 추가 시 1파일 + 1줄
  • 워커 스레드 오프로드: tree-sitter WASM 파싱을 메인 스레드와 분리, WASM 메모리 누수 방지를 위한 주기적 워커 재사이클
  • 옵저버/이벤트: FileWatcher가 OS 네이티브 이벤트(FSEvents/inotify/RDCW)를 구독해 2초 디바운스 후 증분 동기화
  • 적응형 출력 예산: getExploreOutputBudget(fileCount) — 프로젝트 규모에 따라 MCP 응답 크기를 동적 조정

8. 강점 / Strengths

  1. 측정 기반 가치 제안: 7개 실제 오픈소스 프로젝트에 대한 구체적인 A/B 벤치마크(비용·토큰·시간·도구 호출 4개 지표)를 README에 직접 제시. 주장이 아닌 데이터로 설득.

  2. 우수한 레이어 분리와 확장성: installer/targets/registry.ts의 플러그인 패턴으로 새 에이전트 추가가 파일 1개+라인 1개로 가능. frameworks/ 디렉터리도 동일한 패턴으로 15개 프레임워크를 수용.

  3. 실용적인 이중 SQLite 백엔드: native better-sqlite3가 없어도 WASM 폴백으로 투명하게 동작하며, codegraph status로 백엔드 확인 가능. 엔터프라이즈 환경(빌드 도구 없는 CI)에서도 작동.

  4. 워커 스레드 + 메모리 관리: tree-sitter WASM의 메모리 비해제 특성을 인식해 250파일마다 워커를 재사이클하는 실용적 해법. 10초 파싱 타임아웃으로 hung 프로세스 방지.

  5. 적응형 MCP 출력 예산: 프로젝트 규모에 따라 응답 크기를 자동 조정(getExploreOutputBudget). 소형 프로젝트에서 과도한 컨텍스트 소비를 방지하고, 대형 프로젝트에서는 충분한 정보를 제공 — 에이전트 비용 최적화의 핵심 설계.

9. 위험/개선 필요 사항 / Risks & Improvements

  1. CI/CD 파이프라인 부재: GitHub Actions가 전혀 없어 PR 머지 전 자동 테스트 실행이 불가능. 릴리스가 로컬 빌드+수동 스크립트에 의존해 회귀 위험이 있음. npm test + TypeScript 빌드를 자동화하는 기본 workflow 추가가 시급.

  2. 단일 기여자 버스 팩터: 전체 코드베이스가 단일 기여자(colbymchenry)에 의해 유지. CONTRIBUTING.md·이슈 템플릿·코드 오브 컨덕트가 없어 외부 기여가 구조적으로 어려움. 오픈소스 커뮤니티 성장을 위한 온보딩 인프라 필요.

  3. 공급망 보안 미비: Dependabot/Renovate 미설정으로 의존성 취약점이 자동 감지되지 않음. better-sqlite3 같은 네이티브 모듈은 C 레벨 취약점에 노출될 수 있음. SECURITY.md 부재로 보안 취약점 보고 채널도 없음.

  4. ESLint/Prettier 부재: TypeScript strict 모드가 타입 오류를 잡지만, 코드 스타일 일관성과 잠재적 런타임 오류(unused var 이외)는 린터 없이 검출 불가. 특히 다중 기여자가 생겼을 때 코드 품질 유지에 어려움.

  5. WASM 폴백의 성능 격차: WASM 백엔드는 native 대비 5–10x 느리고 MCP database is locked 오류를 유발할 수 있음. Node.js 버전 업그레이드 후 prebuilt binary가 없으면 자동으로 WASM으로 전락하는데, 이를 사용자가 인지하지 못하면 성능 저하를 CodeGraph의 버그로 오인할 수 있음.
