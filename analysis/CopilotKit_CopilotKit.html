1. 프로젝트 개요 / Project Overview

1.1 목적 및 분류 / Purpose and Classification

해결하는 문제 / Problem solved CopilotKit은 풀스택 에이전틱(Agentic) 애플리케이션, 생성형 UI, AI 채팅 인터페이스를 빠르게 구축할 수 있게 해주는 SDK입니다. 개발자가 LangGraph, CrewAI 등 AI 에이전트를 React·Angular·Vue·React Native·Slack·Teams 등의 UI와 연결하는 복잡성을 추상화합니다.

분류 / Classification: Framework + Platform (오픈코어 모델 / Open-Core Model)

  • 오픈소스 프레임워크 계층: React/Angular/Vue UI SDK + 런타임 어댑터 (MIT 라이선스)
  • 클라우드 플랫폼 계층: CopilotKit Intelligence Platform (프리미엄/엔터프라이즈, 라이선스 키 기반)

MIT + Apache 2.0 혼용: 완전 호환 — MIT는 Apache 2.0의 특허 조항(Section 3)을 흡수하는 방식으로 공존 가능.

GPL 전파 위험: 없음. 직접 의존성 전체가 Permissive 계열이므로 GPL 전파 체인이 형성되지 않습니다.

AGPL SaaS 위험: 없음. AGPL 라이선스 의존성이 없어 SaaS 배포 시 소스 공개 의무가 발생하지 않습니다.

⚠️ 특수 항목: @copilotkit/license-verifier (~0.4.2)

3.3 보안 아키텍처 평가 / Security Architecture Assessment

인증/인가 방식: CopilotKit 자체는 인증 레이어를 제공하지 않으며, Express/Hono 미들웨어를 통해 상위 애플리케이션에서 처리하도록 설계. 이는 프레임워크의 의도적 설계이나 도입 시 별도 인증 구현 필요.

시크릿 관리: .env.example 패턴 사용, 실제 키는 미커밋 확인. GitHub Actions는 환경 변수 + OIDC 조합 사용. COPILOTKIT_LICENSE_TOKEN 서버 환경변수로 관리.

텔레메트리: 라이선스 키 보유 시 전량 전송, 미보유 시 샘플링 전송. SCARF_ANALYTICS=false로 비활성화 가능.

SBOM: 자동화 파이프라인 없음 — 엔터프라이즈 도입 시 별도 구성 필요.

The current version is 1.59.5 and the repository is an Nx monorepo of 20 npm packages.

  • Schema validation: Zod, class-validator
  • Testing: Vitest 3.x, Playwright (E2E)

9. 자주 묻는 질문 / FAQ

[한국어]

Q1. pnpm install 이후 빌드 시 "패키지를 찾을 수 없음" 오류가 발생합니다.
원인: 패키지 간 의존성(workspace:*)이 있어 순서대로 빌드해야 합니다.
해결: pnpm build를 루트에서 한 번 실행하면 Nx가 의존 순서를 자동으로 처리합니다.

Q2. Windows에서 pnpm install 중 심링크 오류가 발생합니다.
원인: pnpm은 하드링크/심링크를 사용하는데, Windows에서는 개발자 모드가 필요합니다.
해결: 1. 설정 → 업데이트 및 보안 → 개발자용 → 개발자 모드 활성화 2. 관리자 권한으로 PowerShell 재시작 3. pnpm install 재실행

Q3. npx nx run @copilotkit/xxx:build 명령어가 "project not found" 오류를 냅니다.
원인: Nx 캐시 또는 워크스페이스 인식 문제.
해결:

npx nx reset          # Nx 캐시 초기화
pnpm install          # 의존성 재설치
npx nx graph          # 프로젝트 그래프 확인

Q4. 커밋 시 pre-commit 훅이 실패합니다.
원인: lefthook이 lint, 타입 체크, 테스트를 자동 실행합니다.
해결: 오류 메시지를 확인하고 해당 문제를 수정합니다. 주요 체크:

pnpm lint       # 린팅 오류 확인
pnpm check-types  # 타입 오류 확인
pnpm test       # 테스트 실패 확인

Q5. GraphQL 코드 생성 오류가 발생합니다.
원인: @copilotkit/runtime-client-gql은 GraphQL 스키마에서 타입을 자동 생성합니다.
해결:

npx nx run @copilotkit/runtime:build   # 런타임 먼저 빌드
npx nx run @copilotkit/runtime-client-gql:graphql-codegen  # 코드 재생성

Q6. 로컬 A2UI 패키지를 연동하고 싶습니다.
해결: .pnpmfile.cjs에 로컬 A2UI 연동 설정이 있습니다:

A2UI_LOCAL=1 pnpm install
# @a2ui/web_core, @a2ui/react가 로컬 경로로 매핑됩니다

Q7. 새 훅(hook)을 만들 때 무엇을 해야 하나요?
@copilotkit/react-core에서 훅을 구현한 후 반드시: 1. JSDoc 작성 (사용 예제 포함) 2. Vitest 단위 테스트 작성 3. showcase/shell-docs/src/content/reference/hooks/<hookName>.mdx 문서 파일 생성 4. 개념 가이드가 필요하면 showcase/shell-docs/src/content/docs/ 추가

Cause: Packages have workspace:* cross-dependencies and must be built in dependency order.
Fix: Run pnpm build from the root once — Nx automatically resolves the correct build order.

Q2. Symlink errors during pnpm install on Windows.
Cause: pnpm uses hard links/symlinks which require Developer Mode on Windows.
Fix: 1. Settings → Update & Security → For developers → Developer Mode ON 2. Restart PowerShell as administrator 3. Re-run pnpm install

Q3. npx nx run @copilotkit/xxx:build says "project not found".
Cause: Stale Nx cache or workspace registration issue.
Fix:

npx nx reset          # Clear Nx cache
pnpm install          # Reinstall dependencies
npx nx graph          # Verify project is in graph

Cause: lefthook automatically runs lint, type-check, and tests on commit.
Fix: Read the error message and address the specific failure:

pnpm lint         # Check for lint errors
pnpm check-types  # Check for type errors
pnpm test         # Check for test failures

npx nx run @copilotkit/runtime:build                            # Build runtime first

CopilotKit Provider Frontend context root; sets runtime URL
CopilotChat / CopilotSidebar Ready-to-use chat UI components
useCopilotChat Low-level chat hook for custom UIs
useCopilotAction Register frontend tools (callable by agents)
useCoAgent Subscribe to and control agent state
CopilotRuntime Server-side runtime class
AgentRunner Agent execution abstraction layer
AG-UI Protocol Runtime ↔ frontend event streaming

Data flow:

  1. User sends message → CopilotKit Provider executes GraphQL mutation
  2. HTTP POST → runtime /copilotkit endpoint
  3. AgentRunner resolves and executes the agent
  4. LLM response streams back → AG-UI events (text chunks, tool calls) sent via SSE
  5. On frontend tool call: local handler executes → result returned to agent
  6. Final state update → React state re-renders UI

6. 성능 및 확장성 고려사항 / Performance & Scalability

[한국어]

알려진 성능 병목 지점: 1. SSE 연결 지속: LLM 응답 스트리밍 중 연결이 오래 유지됨 → 리버스 프록시(nginx, Cloudflare)의 타임아웃 설정 필요 2. GraphQL 오버헤드: 모든 채팅 요청이 GraphQL을 거침 → 프로덕션에서 DataLoader 패턴 활용 권장 3. 에이전트 콜드 스타트: LangGraph 에이전트가 Python 기반일 경우 첫 호출 지연 발생

수평/수직 확장 전략: - 수평 확장: CopilotRuntime은 무상태(stateless) 설계 → 로드 밸런서 뒤 다중 인스턴스 배포 가능 - 에이전트 상태 지속성: @copilotkit/sqlite-runner로 에이전트 스레드 상태를 SQLite에 저장 (단일 서버용) - 분산 상태: AWS Bedrock AgentCore 사용 시 @copilotkit/agentcore-runner 활용

캐싱 전략: - LLM 응답 자체는 캐시하지 않음 (스트리밍 특성상 어려움) - 에이전트 메타데이터(사용 가능한 툴 목록 등)는 프론트엔드에서 캐시 가능 - Nx 빌드 캐시: CI에서 원격 캐시 설정으로 빌드 시간 단축

Known performance bottlenecks: 1. Persistent SSE connections: LLM response streaming keeps connections open — configure reverse proxy (nginx, Cloudflare) timeouts accordingly 2. GraphQL overhead: Every chat request passes through GraphQL — consider DataLoader patterns in high-throughput scenarios 3.
