1. 프로젝트 개요 / Project Overview

1.1 목적 및 분류 / Purpose and Classification

해결하는 문제 / Problem solved

Harness는 Claude Code용 "팀 아키텍처 팩토리(Team-Architecture Factory)" 메타 스킬이다. 도메인 한 문장(예: "핀테크 리스크 평가 팀")을 입력하면, 6가지 사전 정의 팀 아키텍처 패턴(Pipeline, Fan-out/Fan-in, Expert Pool, Producer-Reviewer, Supervisor, Hierarchical Delegation) 중 적합한 패턴을 선택하여 .claude/agents/와 .claude/skills/ 경로에 에이전트 정의 및 스킬 파일 집합을 자동 생성한다.

멀티에이전트 LLM 시스템을 도입하려는 개발자·팀이 "에이전트 팀 아키텍처 설계 → 파일 스캐폴딩" 과정에서 반복 지출하는 설계·구성 비용을 제거하는 것이 핵심 가치다.

6.3 AGPL·GPL 전파 위험 시나리오 / AGPL/GPL Propagation Risk Scenarios

해당 없음 — 프로젝트 및 의존성에 AGPL/GPL 구성요소 없음. 전파 위험 시나리오 해당 없음.

Known performance characteristics

Item Value
Token consumption (single complex task) 50K–200K tokens
SKILL.md body size target ≤ 500 lines
Recommended team size (small tasks) 2–3 agents
Recommended team size (medium tasks) 3–5 agents
Recommended team size (large tasks) 5–7 agents

Known performance bottlenecks:

  1. SKILL.md size: Body over 500 lines increases context-loading cost → split into references/
  2. Team size: More members means more SendMessage communication overhead → 3 focused agents beat 5 scattered ones
  3. Per-phase team reconstruction: TeamCreate/TeamDelete carries cost → only use when phase-level restructuring is genuinely required
  4. Serial chaining: Chaining multiple Claude invocations with && causes exponential API cost → run one at a time

Scaling strategies:

  • Horizontal scaling: Generate separate harnesses per domain for independent execution (isolated contexts per team)
  • Iterative quality improvement: Use Phase 7 feedback loop to continuously improve the harness itself
  • Use harness-100: Clone domain-specific teams instantly from the 100-harness catalog (revfactory/harness-100) to reduce token cost

Monitoring and logging:

  • Intermediate artifacts preserved in _workspace/ → audit-traceable post-execution
  • File naming convention: {phase}_{agent}_{artifact}.{ext} (e.g., 01_analyst_requirements.md)
  • CLAUDE.md change history table serves as the harness evolution log
