강점

  1. NumPy API 완전 호환 — import cupy as cp만으로 기존 NumPy 코드 GPU 가속 전환 가능
  2. 이중 GPU 백엔드 — cupy_backends/ 추상화 계층이 NVIDIA CUDA와 AMD ROCm을 단일 코드베이스로 지원
  3. 3단계 CI 파이프라인 — GitHub Actions(정적/빌드) → PFN 내부 CI → 자체 호스팅 ROCm 러너로 실제 GPU 검증
  4. JIT 커널 확장성 — Jitify 통합으로 Python에서 동적 CUDA 커널 생성, cupy.RawKernel/ElementwiseKernel API 제공
  5. 풍부한 테스트 생태계 — 354개 테스트 파일, cupy.testing 비교 유틸리티, typing 테스트까지 포괄

위험/개선 필요 사항

  1. SECURITY.md 부재 — 취약점 신고 채널 미문서화. GPU 라이브러리 특성상 조속한 보안 정책 수립 필요
  2. SBOM 및 아티팩트 서명 미비 — PyPI 배포 패키지에 Sigstore/PEP 740 적용 권고
  3. 대형 단일 파일 — core.pyx(~116KB), __init__.py(1,159줄) 유지보수 부담
  4. 서브모듈 취약점 추적 부재 — CCCL/Jitify 등 NVIDIA 서드파티 CVE 자동 추적 미적용
  5. ROCm CI 불균형 — AMD GPU 테스트가 자체 호스팅 러너에 의존, 커뮤니티 기여자 재현 어려움

도입 권고

NumPy 코드의 GPU 가속이 필요한 환경에서 1순위 도입 후보. 기술적 완성도와 생태계 성숙도 모두 높으며, v15를 향한 개발 모멘텀도 지속적이다. 엔터프라이즈 환경에서는 SECURITY.md 부재와 SBOM 미비 여부를 조직 보안 정책과 대조 후 도입 결정을 권고한다. AMD GPU 환경은 ROCm CI 성숙도를 별도 검증 후 적용할 것.
