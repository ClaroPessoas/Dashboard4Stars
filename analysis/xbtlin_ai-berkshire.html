강점 (Strengths)

  1. 반편견 메커니즘이 아키텍처 레벨로 내장 — 정보 풍부도 등급(A/B/C), 역방향 검증, 8항목 빠른 거부 체크리스트가 파이프라인에 강제 삽입. AI 환각 및 확증 편향을 시스템 수준에서 완화하는 독특한 설계.
  2. 재무 계산의 정밀성 보장 — Python Decimal 기반 financial_rigor.py로 LLM 심산 오류 원천 차단. 시장가치 검증, 3시나리오 모델, Benford 법칙 검사 모두 프로그래매틱하게 감사 가능.
  3. 4대 마스터 다변관점 대립 구조 — 4개 에이전트가 독립적으로 분석하고 Team Lead가 종합. 실제 투자위원회 토론 구조를 모방한 설계.
  4. 180개 이상의 실제 보고서 아카이브 — Skill 출력 품질을 직접 검증할 수 있는 레퍼런스 보고서 다수.
  5. 실거래 수익으로 검증된 방법론 — 2024 +69.29%, 2025 YTD +66.38%. S&P 500 대비 40-50%p 초과 수익.

위험/개선 필요 사항 (Risks)

  1. 테스트 커버리지 전무 — financial_rigor.py 핵심 계산 엔진에 단위 테스트 없음. 회귀 버그가 잘못된 투자 판단으로 이어질 수 있음.
  2. 의존성 선언 파일 부재 — requirements.txt 미존재. 외부 기여자의 환경 재현 불가.
  3. 스크래퍼의 ToS 위험 — 雪球·Morningstar 스크래핑은 해당 플랫폼 이용약관 위반 가능성.
  4. 보고서 명명 규칙 비일관성 — 구형 파일이 CLAUDE.md 규칙을 따르지 않아 180개 파일이 혼재.
  5. Bus Factor = 1 — 단일 기여자. CONTRIBUTING.md·이슈 템플릿 없어 외부 기여 유도 어려움.

도입 권고 (Adoption Recommendation)

  • 개인 투자 리서치: 즉시 사용 권고. Claude Code 환경에서 skills/ 복사만으로 전문급 투자 리서치 프레임워크를 즉시 활용 가능.
  • 팀/기업 환경: requirements.txt, pytest 단위 테스트, ToS 호환 API 교체 후 조건부 도입 권고.
  • 아키텍처 벤치마크: 멀티 에이전트 AI 파이프라인 설계, 특히 반편견 메커니즘과 계산 검증 게이트 패턴은 금융 외 도메인에서도 벤치마크 가치 있음.
  • 오픈소스 기여: 테스트 추가 또는 보고서 명명 규칙 마이그레이션 스크립트 작성부터 기여 시작 권장.
