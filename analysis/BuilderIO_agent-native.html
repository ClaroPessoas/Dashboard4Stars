1. 목적 및 범위 / Purpose & Scope

한국어

Agent-Native는 BuilderIO가 개발한 오픈소스 풀스택 프레임워크로, AI 에이전트와 UI를 동등한 일급 시민으로 취급합니다. 핵심 철학은 "에이전트가 앱 옆에서 채팅하는 것이 아닌, 앱 안에서 실제로 동작"하는 것입니다. 에이전트와 프론트엔드가 동일한 SQL 데이터와 액션 표면을 공유하여, UI에서 할 수 있는 모든 것을 에이전트도 동일한 코드 경로로 수행할 수 있습니다.

English

Agent-Native is an open-source full-stack framework by BuilderIO that treats AI agents and UI as equal first-class citizens sharing the same SQL-backed state and action surface. Everything the UI can do, the agent can do through the same code path — no parallel tooling, no shadow API.

대상 사용자 / Target Users: - SaaS 제품을 에이전트 우선으로 구축하려는 개발팀 - 에이전트 네이티브 아키텍처를 탐구하는 스타트업 - 자체 소유 AI 애플리케이션(15개 템플릿 중 하나를 클론)을 원하는 팀 - Claude Code, Cursor, Pi 등 코딩 에이전트에 스킬을 연동하려는 개발자

유형 / Type: 오픈소스 프레임워크 + 프로덕션 템플릿 플랫폼 (Framework + Platform)

4-1. 진입점 / Entry Points

4-2. 핵심 패턴: 통합 액션 표면 / Unified Action Surface

// defineAction — 한 번 정의, 어디서나 사용
export default defineAction({
  description: "...",
  schema: z.object({ name: z.string() }),
  http: { method: "GET" },
  run: async ({ name }, ctx) => {
    // ctx.caller: "tool" | "http" | "frontend" | "cli" | "mcp" | "a2a"
    // ctx.userEmail, ctx.orgId — 요청 범위 ID
    return { message: `Hello, ${name}!` };
  },
});

동일 액션을 호출하는 경로: - 프론트엔드: useActionQuery() / useActionMutation() - 에이전트 도구: 채팅 루프 내 도구 호출 - HTTP: GET /_agent-native/actions/hello?name=world - MCP: /mcp/tools/call - A2A: 에이전트 간 JSON-RPC 프로토콜 - CLI: pnpm action hello --name world

8. 강점 / Strengths

  1. 통합 액션 표면 (Unified Action Surface) defineAction() 하나로 UI·에이전트·HTTP·MCP·A2A·CLI를 모두 커버하는 패턴은 코드 중복을 제거하고 에이전트와 UI가 동일한 비즈니스 로직을 사용함을 보장합니다. 업계에서 드문 수준의 아키텍처 일관성.

  2. 보안 우선 문화 (Security-First Engineering) 14개 가드 스크립트가 CI에서 실행되어 자격증명 누출, 비범위 쿼리, drizzle-kit push 등을 자동 차단합니다. npm OIDC 신뢰 게시와 PR 비밀 스캔까지 포함한 계층적 보안.

  3. 최신 기술 스택 (Bleeding-Edge Stack) TypeScript 6 네이티브 파서, React 19, Vite 8, Tailwind 4, Drizzle ORM — 2026년 기준 가장 최신 패키지만 사용. Rust 기반 oxlint/oxfmt로 빌드 속도도 최적화.

  4. AI 기반 개발 워크플로우 (AI-Augmented Developer Experience) 모든 PR에 Claude/Codex가 시각 리캡을 자동 생성하는 pr-visual-recap.yml은 코드 리뷰 품질을 AI로 증폭시키는 혁신적 접근.

  5. 운영 성숙도 (Operational Maturity) 16개 전문화된 CI 워크플로우, 50개+ 구현 스킬, Neon 프리뷰 브랜치, Changesets 자동화, LLM 평가 테스트, 다중 클라우드 배포 설정 — 스타트업 프로젝트 수준을 넘어선 기업급 운영 체계.

9. 위험 및 개선 필요 사항 / Risks & Areas for Improvement

  1. Dependabot/Renovate 부재 의존성 취약점 자동 알림 도구가 없습니다. 현재 pnpm overrides로 일부 패치를 강제하지만, 신규 CVE에 대한 자동 감지가 없어 보안 취약점이 조용히 누적될 수 있습니다. → 권고: dependabot.yml 또는 renovate.json 추가

  2. SECURITY.md 및 CONTRIBUTING.md 부재 취약점 보고 채널과 기여 가이드라인이 문서화되지 않았습니다. 오픈소스 프로젝트로서 외부 기여자와 보안 연구자를 위한 공식 채널이 필요합니다. → 권고: SECURITY.md (취약점 신고 이메일/프로세스), CONTRIBUTING.md 추가

  3. 테스트 커버리지 수치 미공개 Vitest와 Playwright가 설정되어 있지만 코드 커버리지 리포트(@vitest/coverage-v8 설치됨에도)가 CI에서 생성·게시되지 않습니다. 회귀 위험 구간을 파악하기 어렵습니다. → 권고: CI에 vitest run --coverage + 커버리지 배지 추가

  4. 모노레포 규모 복잡성 14개 패키지 + 15개 템플릿 = 29개 독립 앱이 단일 저장소에 존재합니다. pnpm-lock.yaml이 40,000줄 이상이며 전체 설치 시간이 길 수 있습니다. 신규 기여자의 진입 장벽이 높습니다. → 권고: 개발 전용 "slim" 설치 경로 문서화 강화

  5. ADR(아키텍처 결정 기록) 부재 drizzle-kit push 프로덕션 방지 사건(2026-04-21)처럼 중요한 설계 결정들이 가드 스크립트 주석이나 AGENTS.md에 분산되어 있습니다. 공식 ADR 시스템이 없어 설계 이유를 추적하기 어렵습니다. → 권고: docs/adr/ 디렉토리 신설, 주요 결정 소급 문서화

10. 도입 권고 / Adoption Recommendation

기술 도입 관점

강력 권고 — Agent-Native는 AI 에이전트와 UI를 진정한 동등 파트너로 만드는 몇 안 되는 프레임워크입니다. 단순한 "AI 채팅 위젯 추가" 수준을 넘어, 에이전트가 앱의 모든 기능을 동일한 코드 경로로 수행하는 아키텍처를 제공합니다.

도입 적합 시나리오: - AI 에이전트가 UI와 동일한 데이터를 읽고 변경해야 하는 SaaS 제품 - 빠른 프로토타이핑이 필요한 에이전트 네이티브 스타트업 (15개 템플릿 즉시 클론) - Claude Code, Cursor 등 코딩 에이전트에 커스텀 스킬을 연동하려는 팀 - 멀티 테넌트 워크스페이스 구조가 필요한 B2B SaaS

주의 사항: - Node 24+ 필수 — 레거시 환경 제약 - Anthropic Claude API 의존도 높음 (다른 공급자도 지원하나 Claude 중심) - Dependabot 부재로 의존성 보안 모니터링 직접 필요 - 모노레포 전체 이해에 상당한 학습 곡선

아키텍처 벤치마킹 관점

defineAction() 패턴 — 단일 정의로 UI·에이전트·HTTP·MCP·CLI를 모두 커버하는 설계 — 은 에이전트 시대의 API 설계 패턴으로 참조할 가치가 높습니다. ownableColumns() 기반 공유 시스템과 SQL-기반 애플리케이션 상태 관리도 벤치마킹 적합합니다.

보안 리뷰 관점

조건부 승인 — 14개 가드 스크립트와 OIDC npm 게시는 우수하나, Dependabot 부재와 SECURITY.md 미작성은 도입 전 해결이 필요합니다. 내부 도입 시 dependabot.yml 추가와 취약점 보고 프로세스 수립을 선행하십시오.

기여 준비도 관점

중급 — 50개 스킬 파일과 AGENTS.md가 상세한 구현 가이드를 제공하지만 CONTRIBUTING.md와 이슈 템플릿이 부재합니다. 기존 PR(#1589 활발)을 참고하거나 Discord를 통한 소통이 현재로서는 기여 진입로입니다.
