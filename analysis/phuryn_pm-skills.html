강점 (Strengths)

  1. 일관된 플러그인 아키텍처 — 확장에 최적화 9개 플러그인 모두가 동일한 디렉토리 레이아웃, 프론트매터 규칙, 명명 규칙을 따른다. validate_plugins.py가 이 일관성을 자동으로 강제하여, 새 스킬·커맨드 추가 시 구조적 회귀가 불가능하다. 오픈소스 기여자가 패턴을 학습하는 비용이 매우 낮다.

  2. 스킬/커맨드 이중 레이어 설계 — 조합성과 재사용성 스킬(명사/지식)과 커맨드(동사/워크플로우)의 분리는 단순하지만 강력한 설계다. /discover는 4개 스킬을 체이닝하고, prioritization-frameworks는 어떤 커맨드에서도 독립적으로 참조된다. 플러그인 간 하드 참조 금지 규칙은 독립 설치를 보장한다.

  3. 점진적 공개 패턴(Progressive Disclosure) 프론트매터(경량 메타데이터)와 SKILL.md 본문(상세 콘텐츠)의 분리는 AI 컨텍스트 윈도우를 효율적으로 사용한다. 트리거 문구 기반의 자동 로딩은 사용자가 명시적 명령 없이도 적절한 스킬을 활성화하게 한다.

  4. 멀티-에이전트 호환성 — 광범위한 생태계 커버리지 Claude Code, Claude Cowork, Codex CLI(OpenAI), Gemini CLI, Cursor, OpenCode, Kiro를 단일 레포지토리로 지원한다. marketplace.json 스키마가 표준화되어 있어 새로운 AI 에이전트 플랫폼 지원 추가가 용이하다.

  5. 검증 도구의 완성도 — 자동화된 품질 게이트 validate_plugins.py는 외부 패키지 없이 Python 표준 라이브러리만으로 110개 컴포넌트(68스킬 + 42커맨드) 전체를 검증한다. 에러/경고/정보 3단계 리포팅, 컬러 출력, exit code까지 갖춘 프로덕션 수준의 도구다.

위험 / 개선 필요 사항 (Risks / Areas for Improvement)

  1. CI/CD 자동화 부재 — 릴리즈 파이프라인 없음 GitHub Actions 워크플로우가 존재하지 않는다. PR 시 validate_plugins.py 자동 실행이 없어, 기여자가 로컬에서 수동 실행을 잊을 경우 유효하지 않은 변경이 머지될 수 있다. 버전 범프, 릴리즈 노트 생성도 수동이다.

  2. 버전 동기화의 취약성 — 수동 프로세스 의존 9개 plugin.json + marketplace.json의 버전을 수동으로 동기화해야 한다. CLAUDE.md에 규칙이 명시되어 있지만 자동화가 없다. 하나라도 누락 시 validate_plugins.py가 감지하지 못한다(버전 일치 여부를 크로스-체크하지 않음).

  3. SECURITY.md 부재 런타임 코드가 없어 실질적 보안 리스크는 낮지만, GitHub 오픈소스 표준(OSSF Scorecard, OpenSSF Best Practices)에서 SECURITY.md는 성숙도 지표다. 취약점 보고 경로가 README에도 명시되지 않았다.

  4. AI 응답 품질 검증 불가 — 구조 검증만 존재 현재 테스트는 파일 구조·프론트매터 유효성만 확인한다. 스킬 콘텐츠가 실제 AI 에이전트와 통합될 때 의도대로 동작하는지(트리거 문구의 효과, 출력 품질, 프레임워크 충실도)를 자동으로 검증하는 방법이 없다.

  5. 기여자 경험 — PR 템플릿·이슈 템플릿 부재 .github/PULL_REQUEST_TEMPLATE.md, .github/ISSUE_TEMPLATE/ 디렉토리가 없다. 기여자 수가 늘어날 경우 PR 품질 관리와 이슈 트라이지가 수동 부담으로 전가된다. 릴리즈별 CHANGELOG.md도 없다.
