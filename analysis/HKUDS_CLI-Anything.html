1. 목적 및 범위 / Purpose & Scope

KR: 모든 GUI/데스크톱 소프트웨어를 AI 에이전트가 사용할 수 있는 CLI로 변환하는 SOP·툴킷·플러그인 마켓플레이스. "오늘 소프트웨어는 사람용, 내일은 에이전트용"이 표어. HKU Data Intelligence Lab(HKUDS) 주도, Apache 2.0(LICENSE 파일은 11KB 분량).

EN: SOP + toolkit + plugin marketplace that turns GUI/desktop apps (GIMP, Blender, LibreOffice, FreeCAD, OBS, Godot, Krita 등 50+) into agent-native CLIs. Targets Claude Code, Pi, OpenClaw, Codex, Cursor, GitHub Copilot CLI. Hybrid product: methodology (HARNESS.md) + many CLI harnesses + a registry/hub package manager.

2. 구조 / Repository Structure

  • Monorepo. 톱레벨 디렉터리 ≈ 60+.
  • 패턴: <software>/agent-harness/ 안에 cli_anything/<software>/ Python 패키지 + <SOFTWARE>.md SOP + setup.py.
  • 공유 자원:
  • skills/ — 캐노니컬 SKILL.md(에이전트 발견용) 50+개 통합 디렉터리
  • cli-anything-plugin/ — Claude Code 플러그인 본체 (HARNESS.md, skill_generator.py, templates, commands, guides)
  • cli-hub/ — pip install cli-anything-hub PyPI 패키지(브라우즈/설치/업데이트)
  • registry.json (45KB) + public_registry.json (15KB) — 카탈로그
  • .github/ — workflows, ISSUE/PR templates, CODEOWNERS, scripts
  • docs/, assets/, .claude-plugin/marketplace.json
  • 도메인 지향 + 플러그인-마켓플레이스 패턴. 각 하니스는 독립 PyPI 배포 가능.

3. 스택 / Stack

영역 사용 기술
언어 Python ≥3.10
CLI 프레임워크 Click ≥8.0
REPL prompt-toolkit ≥3.0
테스트 pytest, pytest-cov
패키징 setuptools (namespace pkg), python -m build, twine
플러그인 Claude Code Plugin Marketplace (.claude-plugin/marketplace.json)
백엔드 호출 subprocess (shell=False) → melt/ffmpeg/gimp/blender 등 외부 바이너리
CI GitHub Actions (check-root-skills, publish-cli-hub, deploy-pages, pr-labeler)
배포 PyPI(trusted publishing, OIDC), GitHub Pages(웹 허브)
메타 JSON 카탈로그(registry.json, public_registry.json)

데이터 저장 불필요(파일/세션 JSON 위주). DB/메시지큐 없음.

4. 아키텍처 / Architecture

  • 7-Phase SOP 문서화(HARNESS.md): codebase 분석 → CLI 설계 → 구현 → 백엔드 통합 → 렌더/익스포트 → 세션·REPL → 테스트.
  • 진입점:
  • 각 하니스: console_scripts (예: cli-anything-gimp=cli_anything.gimp.gimp_cli:main)
  • 허브: cli-hub=cli_hub.cli:main
  • 플러그인: Claude Code 슬래시커맨드 /cli-anything
  • 계층:
  • presentation = Click 명령 + ReplSkin(prompt-toolkit)
  • business = cli_anything/<software>/ 도메인 모듈
  • backend = utils/<software>_backend.py (실 바이너리 호출)
  • state = 파일 기반 세션 JSON, _locked_save_json 패턴(파일락)
  • 통신: 외부 백엔드는 subprocess 인자 리스트, REST/gRPC 없음. 출력 듀얼 모드: human + --json.
  • 발견 메커니즘: 캐노니컬 skills/cli-anything-<name>/SKILL.md → 에이전트가 자동 발견·로드. 패키지 내부에도 사본(cli_anything/<software>/skills/SKILL.md) 미러.

5. 품질·테스트 / Quality & Tests

  • 컨벤션: 각 하니스 cli_anything/<software>/tests/에 test_core.py(백엔드 불필요 unit) + test_full_e2e.py(실 바이너리).
  • README 뱃지: "2,269 passing tests".
  • CI:
  • check-root-skills.yml — skills/ 미러 검증 (sync/validate 스크립트)
  • publish-cli-hub.yml — PyPI 버전 중복 체크 후 trusted publishing
  • pr-labeler*.yml — 라벨 자동화
  • deploy-pages.yml — 허브 사이트 배포
  • 린트/포맷터 별도 명시 없음(PEP 8 가이드만). 타입체커 미통합.
  • 버저닝: registry.json 항목별 SemVer + 하니스 setup.py(1.0.0 류). cli-hub만 0.3.0.
  • 릴리스 노트: README "News" 섹션이 사실상 changelog 역할. 별도 CHANGELOG 미존재.

6. 보안·공급망 / Security & Supply Chain

  • SECURITY.md 존재. 위협모델 명시: prompt-injected 에이전트 → 백엔드로 악성 인자 전달.
  • 통제:
  • shell=True 금지
  • 코덱 allowlist (ALLOWED_VCODECS/ALLOWED_ACODECS frozenset)
  • _script_fu_escape() (GIMP), xml_escape() (MLT/SVG)
  • os.path.abspath() 경로 정규화
  • API 키 config 파일 chmod 0o600
  • 공개 보고: GitHub Private Vulnerability Reporting (Security 탭). 48h acknowledge, 7d critical fix 목표.
  • 공급망 약점:
  • Dependabot/Renovate 설정 부재(.github/에 dependabot.yml 없음)
  • SBOM/아티팩트 서명 없음
  • PyPI trusted publishing은 사용(긍정), 그러나 의존성 핀 미흡(click>=8.0 등 lower-bound only)
  • 라이선스: Apache-2.0 (루트), cli-hub setup.py에는 MIT 명시 — 충돌/혼선 위험.

강점 / Strengths

  1. 에이전트-네이티브 First-class 설계 — SKILL.md 자동 발견, --json 의무, REPL+subcommand dual 모드. 단순 CLI 모음이 아닌 에이전트 운영 계약을 표준화.
  2. 확장 가능한 모노레포 패턴 — <sw>/agent-harness/ + canonical skills/ 미러 + CI 검증으로 50+ 하니스를 일관 관리.
  3. 운영 자동화 — PyPI trusted publishing(OIDC, 버전 중복 회피), root-skills 검증 워크플로, PR labeler, GH Pages 허브 자동 배포.
  4. 방어 가능한 위협 모델 — prompt-injection을 1급 위협으로 명시, 코덱 allowlist·Script-Fu/XML escape·shell=False 강제.
  5. 커뮤니티 견인력 — 다국어 README(EN/CN/JA), wishlist·contributor-signup 이슈 템플릿, registry-only PR 경로(standalone 친화).

위험·개선 / Risks

  1. 라이선스 충돌 신호 — 루트 LICENSE는 Apache-2.0, cli-hub/setup.py는 license="MIT". 분리 의도라면 명시 필요, 아니면 정정.
  2. 공급망 가드 미흡 — Dependabot/Renovate 설정 없음, 의존성 lower-bound only, SBOM/서명 부재. PyPI publishing은 OIDC이나 입력 의존성 무결성은 약함.
  3. 품질 게이트 부족 — 린터/포매터/타입체커 CI 미통합. "2,269 passing" 수치는 README 자체 광고일 뿐 커버리지 리포트 미공개.
  4. CHANGELOG·SemVer 일관성 — README "News"가 사실상 체인지로그. 하니스별 버전 동기화 정책 없음.
  5. 모노레포 비대 — 60+ 톱레벨 디렉터리, 일부는 README 항목과 미일치 가능. 신규 컨트리뷰터 진입장벽 + git 사용자 빌드 시간 ↑.

도입 권고 / Recommendation

  • 에이전트 플랫폼 통합 후보로 즉시 채택 가능. Claude Code/Codex/Pi 등 다중 호스트 검증 완료.
  • 벤치마크 가치 高 — HARNESS.md 7-Phase는 자체 에이전트-CLI 빌드 시 참조 SOP로 활용 권장.
  • 보안 리뷰: 채택 전 SECURITY.md 위협모델 + allowlist 정책 코드 감사 통과, 추가로 Dependabot/SBOM 보강 요구.
  • 운영 도입: cli-hub(pip install cli-anything-hub) 안정성은 Beta(v0.3.0) — 프로덕션 핵심 경로 의존 전에 락파일 핀 강제 필요.
  • 기여 친화: registry-only PR 경로로 외부 기여 진입 비용 낮음. 자체 GUI 도구 통합 시 비용효율적.

종합: 에이전트 시대 CLI 표준화에 가장 유력한 오픈소스 베이스라인. 보안/공급망/품질 게이트 보강만 더하면 엔터프라이즈 채택 가능. Methodology 자체는 즉시 차용 권장.
