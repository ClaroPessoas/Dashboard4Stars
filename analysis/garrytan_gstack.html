강점 (Strengths)

1. 정교한 다계층 보안 아키텍처

프롬프트 인젝션 방어가 단순 규칙을 넘어 ML(TestSavantAI ONNX, DeBERTa-v3, Claude Haiku 전사록 분류기)과 결정론적 카나리 인젝션을 결합한 6계층 앙상블로 설계되어 있다. 각 계층의 역할과 한계가 코드(THRESHOLDS, combineVerdict)와 문서(CLAUDE.md, ARCHITECTURE.md)에 명확히 기술되어 있다. 물리적 포트 분리로 터널 공격 표면을 사전에 차단한 점도 주목할 만하다.

2. 3계층 테스트 피라미드 + 허메틱 E2E 환경

무료 정적 검증(<2초) → LLM 판관 평가($0.15) → 실제 claude -p 세션 E2E($4 상한)의 비용-신뢰도 트레이드오프를 명시적으로 설계했다. test/helpers/hermetic-env.ts가 env allowlist 스크러빙, 격리된 CLAUDE_CONFIG_DIR, MCP 서버 차단을 자동 적용해 로컬 개발자 상태가 CI 결과에 개입하지 않는다. diff 기반 선택적 실행으로 유료 eval 비용을 관리한다.

3. 스킬 생성 파이프라인의 단일 소스 원칙

SKILL.md 파일들이 .tmpl 템플릿과 scripts/resolvers/(preamble, design, review, gbrain 등) 조합으로 자동 생성된다. /ship, /cso, /spec, /document-release 등 여러 스킬에서 공유되는 redaction taxonomy, jargon 목록, 작성 스타일이 단일 소스에서 파생되어 드리프트를 방지한다.

4. 브라우저 데몬의 실용적 설계

CLI → HTTP → Bun 서버 → CDP → Chromium 파이프라인에서 첫 호출 후 100-200ms 응답 레이턴시와 세션 영속성(쿠키, 탭, localStorage)을 구현한다. 랜덤 포트 선택(10000-60000)으로 Conductor 다중 워크스페이스 충돌을 제거하고, 바이너리 버전 불일치 시 자동 재시작해 "오래된 바이너리" 버그를 사전에 차단한다.

5. 이벤트 소싱 기반 결정 메모리

decisions.jsonl + learnings.jsonl로 교차 세션 결정과 운영 학습을 영속화한다. gstack-decision-search가 keyword + 선택적 gbrain 시맨틱 검색을 지원해 과거 결정을 재토론하는 낭비를 줄인다. gbrain 비활성 시에도 파일 기반 경로가 단독으로 동작하는 점이 핵심 설계 원칙이다.

위험 / 개선 필요 사항 (Risks & Areas for Improvement)

1. 단일 저자 의존성 (Bus Factor = 1)

GitHub 커밋 히스토리(shallow clone 기준)에서 실질적 커미터가 garrytan@gmail.com 한 명이다. 커뮤니티 PR이 존재하지만 코어 아키텍처 변경은 단일 저자에 집중된다. 장기 유지보수와 포크 에코시스템 성장에 구조적 위험이다.

2. SBOM 및 공급망 보안 도구 부재

package.json에 dependabot.yml이나 renovate.json 설정이 없다. 904KB CHANGELOG와 270개 테스트의 정교함과 대비되는 공백으로, @huggingface/transformers 등 ML 의존성의 취약점 추적이 자동화되어 있지 않다.

3. macOS arm64 전용 컴파일 바이너리의 git 추적

browse/dist/, design/dist/의 컴파일 바이너리(~58MB, macOS Mach-O arm64)가 git에 추적되고 있다. CLAUDE.md에 "historical mistake"임이 명시되어 있지만 git rm --cached가 아직 실행되지 않았다. 저장소 크기와 플랫폼 혼동 위험이 지속된다.

4. 스킬 품질의 LLM 비결정성

E2E 테스트가 실제 claude -p 세션을 구동하므로 결과가 모델 응답의 비결정성에 노출된다. gate/periodic 분류로 완화하고 있지만, 모델 버전 업그레이드 시 스킬 프롬프트 품질 회귀를 체계적으로 감지하기 어렵다. parity-baseline-v*.json 파일들이 이 문제를 부분적으로 다루지만 자동화된 회귀 경보 체계는 명확하지 않다.

5. Supabase/gbrain 의존성의 선택적 처리 복잡성

gbrain 통합이 선택사항임에도 bin/, lib/, scripts/resolvers/ 전반에 gbrain 분기 코드가 산재해 있다. GBRAIN_PREPARE pooler 버그(#1965)처럼 edge case가 실제 사용자에게 조용히 실패하다가 뒤늦게 발견되는 패턴이 반복된다. 선택적 통합의 테스트 커버리지 보장이 어렵다.

English Summary

gstack (v1.58.4.0) is an MIT-licensed AI engineering workflow framework by Garry Tan (Y Combinator CEO). It extends Claude Code with 23 specialist slash-command skills (/ship, /review, /qa, /cso, /office-hours, etc.) and a persistent Chromium browser daemon, targeting solo builders who want to ship at the velocity of a 20-person team.

Architecture highlights: Browser daemon (CLI → HTTP → Bun server → CDP → Chromium, ~100-200ms after cold start); dual-listener tunnel with physical port separation for security; 6-layer prompt injection defense (ONNX ML + Haiku transcript classifier + canary + threshold ensemble); skill generation pipeline (.tmpl + resolver composition → SKILL.md); diff-based test selection with hermetic E2E environments; event-sourced decision memory (JSONL).

Stack: TypeScript on Bun runtime, Playwright/Chromium, Anthropic Claude SDK, HuggingFace Transformers (ONNX), ngrok, Supabase/pgvector (optional gbrain), single-binary deployment via bun build --compile.

Strengths: Multi-layer security architecture; cost-tiered 3-layer test pyramid (free static / LLM judge / real claude -p E2E); single-source skill generation pipeline; practical browser daemon design; cross-session decision memory.

Risks: Bus factor of 1 (single author); no SBOM or automated dependency vulnerability tracking; tracked macOS-arm64 binaries in git (acknowledged technical debt); LLM non-determinism in E2E test assertions; optional gbrain integration complexity generating silent edge-case failures.

Recommendation: Conditionally adopt. Excellent for Claude Code-based AI-assisted development workflows. Architectural patterns (browser daemon, dual-listener tunnel, diff-based test selection) are worth benchmarking. Address SBOM absence and binary git-tracking before enterprise adoption.
