프로젝트 개요 / Project Overview

Maigret는 사용자 이름(username) 하나만으로 3,000개 이상의 웹사이트에서 계정을 검색하고, 프로필 페이지에서 가능한 모든 정보를 수집하는 OSINT(공개출처정보) 도구입니다. API 키가 불필요하며 CLI 도구, Python 라이브러리, 웹 인터페이스 세 가지 형태로 사용할 수 있습니다.

Maigret is an OSINT tool that collects a dossier on a person by username only, checking for accounts across 3,000+ websites and extracting all available information from profile pages. No API keys are required; it operates as a CLI tool, Python library, and web interface.

Step 1. 목적 및 범위 / Purpose and Scope

Maigret는 OSINT 도구 카테고리에서 사용자명 기반 계정 조회 분야의 사실상 표준입니다.

  • 해결 문제: 하나의 사용자명으로 수천 개 사이트에서 계정 존재 여부를 빠르게 확인하고 연결된 신원 정보를 수집
  • 대상 사용자: 보안 연구자, OSINT 전문가, 저널리스트, 법집행기관, 상업용 OSINT 플랫폼(Social Links, UserSearch 등이 내부 활용)
  • 유형: CLI 도구 + Python 라이브러리 + 웹 인터페이스 복합체
  • 주요 특징:
  • 3,000+ 사이트 데이터베이스, 기본 상위 500개 사이트 검색
  • 재귀 검색(발견된 다른 사용자명/ID로 추가 검색)
  • AI 분석 모드(--ai, OpenAI 호환 API)
  • Cloudflare 우회(FlareSolverr 연동)
  • Tor/I2P 프록시 지원

Step 4. 아키텍처 분석 / Architecture Analysis

진입점 흐름

CLI: maigret USERNAME
  └─→ maigret/maigret.py::run()
        └─→ asyncio.run(main())
              ├─ Settings 로드
              ├─ MaigretDatabase 로드 (data.json)
              ├─ 사이트 필터링 (top N, tags, 사이트명)
              └─→ checking.maigret() [핵심 검색 함수]
                    └─→ AsyncioQueueGeneratorExecutor
                          └─→ 각 사이트별 병렬 HTTP 검사

아키텍처 패턴

  • 비동기 큐 기반 실행: AsyncioQueueGeneratorExecutor가 세마포어 방식으로 동시 연결 수를 제한하며 사이트를 병렬 검사
  • 전략 패턴 (체커 선택): 사이트 속성(protection 필드)에 따라 SimpleAiohttpChecker, CurlCffiChecker, CloudflareWebgateChecker 중 선택
  • 플러그인식 리포트: save_csv_report, save_html_report, save_pdf_report, save_xmind_report 등 포맷별 함수 조합
  • 데이터 모델: MaigretSite, MaigretEngine, MaigretDatabase 클래스로 사이트 데이터 캡슐화
  • 재귀 검색: 각 검색 결과에서 추가 사용자명/ID를 추출해 동적으로 검색 큐에 추가
  • 상태 관리: 메모리 내 딕셔너리(QueryResultWrapper) - 영구 상태 없음

레이어 분리 평가

  • CLI/UI 레이어: maigret.py, web/app.py
  • 비즈니스 로직: checking.py, permutator.py, extractors.py
  • 데이터 접근: sites.py, db_updater.py, settings.py
  • 출력: report.py, notify.py

checking.py가 1644줄로 비대하며 HTTP 검사, 오류 분류, 활성화 로직 등 여러 책임이 혼재함.

주목할 보안 사항

  1. Path Traversal 수정 (PR #2635): /reports 경로에서 send_from_directory로 path containment를 강화함. 수정 이력 확인됨.
  2. Flask Secret Key: os.urandom(24).hex()로 자동 생성 (환경변수 FLASK_SECRET_KEY로 오버라이드 가능). 재시작 시 세션 무효화됨.
  3. Docker 보안: FLASK_HOST=0.0.0.0 기본값이 Docker 환경에서 모든 인터페이스 바인딩. 로컬 배포 시 주의 필요.
  4. API 키 노출 위험: settings.json에 openai_api_key 빈 문자열로 기본값 설정. 사용자가 파일에 직접 키를 입력할 경우 git 실수 커밋 위험.
  5. OSINT 도구 특성: 법적 면책 조항 명시(README.md), GDPR/CCPA 준수 책임을 사용자에게 귀속.

강점 / Strengths

  1. 완벽한 다중 진입점 설계: CLI, Python 라이브러리 API, Flask 웹 UI를 모두 지원하여 다양한 통합 시나리오에 대응. maigret/__init__.py에서 search 함수를 직접 노출해 프로그래밍 방식 임베딩이 용이.

  2. 강력한 비동기 아키텍처: aiohttp 기반 비동기 큐 실행으로 최대 100개 동시 연결을 관리하며 수백 개 사이트를 병렬 검사. 키보드 인터럽트(Ctrl+C) 시 부분 결과를 보존하는 세심한 SIGINT 핸들링 구현.

  3. 자동 갱신 사이트 데이터베이스: 실행 시 GitHub에서 메타 파일을 확인하고 24시간 간격으로 새 데이터베이스를 자동 다운로드. 오프라인 시 번들 DB로 폴백. Pre-commit 훅으로 기여자가 DB 메타데이터를 자동 재생성.

  4. 광범위한 배포 옵션: PyPI, Docker(CLI+Web 멀티 스테이지), Snap, Windows PyInstaller 독립 실행형, Google Cloud Shell, Colab 등 모든 주요 플랫폼과 실행 환경을 포괄. OIDC Trusted Publisher로 PyPI 배포 공급망 보안 강화.

  5. 포괄적인 리포트 형식: HTML, PDF, CSV, TXT, JSON(simple/ndjson), XMind 마인드맵, D3 그래프, Markdown 등 8가지 이상의 리포트 형식 지원. Jinja2 템플릿 기반으로 확장 용이.

위험/개선 필요 사항 / Risks and Areas for Improvement

  1. checking.py 과밀집(God Module): 1644줄에 HTTP 검사 로직, 오류 분류, 활성화 메커니즘, Cloudflare 우회 설정 빌더, SIGINT 핸들링까지 혼재. 기능 추가 시 복잡도가 기하급수적으로 증가할 위험. 체커 클래스별 파일 분리 권장.

  2. SECURITY.md 부재: 취약점 신고 방법, 연락처, 지원 버전, CVE 처리 프로세스가 명시되어 있지 않음. OSINT 도구 특성상 악용 가능성이 있는 취약점 신고 경로 확보가 중요. GitHub Security Advisories 설정 권장.

  3. 테스트 커버리지 하한선(60%): CI에서 60%를 강제하나, OSINT 검사 로직의 복잡성을 감안하면 낮은 편. 특히 checking.py의 각 체커 클래스, Cloudflare 우회 로직, 재귀 검색 경로에 대한 단위 테스트 보강 필요.

  4. Docker 기본값 FLASK_HOST=0.0.0.0: 웹 이미지에서 모든 인터페이스 바인딩. 로컬 Docker 실행 시 포트가 열려 있으면 네트워크 내 다른 호스트에서 접근 가능. 기본값을 127.0.0.1로 변경하거나 문서화를 강화할 필요.

  5. 의존성 수 과다: pyproject.toml에 40개 이상의 런타임 의존성. mock, six, future와 같은 구 호환성 패키지가 아직 잔존. Python 3.10+만 지원하므로 six, future, mock(Python 3 내장으로 대체 가능) 등 레거시 의존성 정리 여지가 있음.
