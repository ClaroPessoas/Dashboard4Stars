세부 분석 (Detailed Analysis)

1. 목적 및 범위 (Purpose & Scope)

한국어: Meetily는 기업 및 개인 사용자가 회의 내용을 클라우드에 전송하지 않고 완전히 온-디바이스에서 캡처·전사·요약할 수 있도록 설계된 프라이버시 우선 AI 회의 보조 도구다. IBM 2024 데이터 기준 평균 데이터 유출 비용 $4.4M, GDPR 벌금 €58.8억 등의 위험을 기업 프라이버시 규정 준수로 해결하는 것을 핵심 가치로 내세운다.

대상 사용자: GDPR 준수가 필요한 기업, 회의 내용 기밀이 중요한 법무·의료·금융 종사자, 프라이버시를 중요시하는 일반 사용자.

유형: 크로스 플랫폼 데스크탑 애플리케이션 (macOS/Windows/Linux).

English: Meetily is a privacy-first AI meeting assistant that captures, transcribes, and summarizes meetings entirely on-device without transmitting data to external servers. It targets enterprise and individual users facing GDPR compliance, legal recording restrictions, and data breach risks.

4. 아키텍처 분석 (Architecture)

오디오 이중 파이프라인 (핵심 설계):

Raw Audio (Mic + System)
         ↓
┌────────────────────────────────────────────┐
│          Audio Pipeline Manager             │
│        (audio/pipeline.rs)                 │
└─────────────┬──────────────────────────────┘
              ↓                        ↓
    ┌──────────────────┐    ┌────────────────────────┐
    │  Recording Path  │    │  Transcription Path    │
    │ (프로 믹싱/덕킹) │    │  (VAD 필터링 → Whisper)│
    └──────────────────┘    └────────────────────────┘
              ↓                        ↓
    RecordingSaver.save()    WhisperEngine.transcribe()

IPC 통신 패턴: - Frontend → Rust: invoke('start_recording', {...}) Tauri 커맨드 - Rust → Frontend: app.emit("transcript-update", payload) 이벤트 - 상태 동기화: SidebarProvider.tsx가 React 전역 상태, Tauri 이벤트로 Rust 상태와 동기화

아키텍처 패턴: 이벤트 기반(Event-Driven) + 레이어드(Layered). Rust 레이어가 도메인 로직을 완전히 소유하며, 프론트엔드는 표현 계층(Presentation Layer)에 집중.

강점 (Strengths)

  1. 전문적 오디오 처리 설계: RMS 기반 덕킹, EBU R128 라우드니스 정규화, RNNoise 신경망 노이즈 제거, VAD 기반 Whisper 부하 ~70% 절감 등 방송 수준의 오디오 파이프라인. 단순 녹음 앱과 확연히 차별화.

  2. 완성도 높은 GPU 가속 지원: Metal+CoreML(macOS), CUDA(NVIDIA), ROCm/HIPBlas(AMD), Vulkan(Intel/AMD), OpenBLAS(CPU) 등 모든 주요 하드웨어 가속 경로를 단일 코드베이스에서 Cargo feature flag로 관리. 전사 성능을 5~10배 향상.

  3. 명확한 모듈 분리 아키텍처: 기존 1028줄 모놀리식 core.rs를 devices/, capture/, pipeline.rs, recording_manager.rs 등으로 체계적 리팩토링 완료. 새 플랫폼 오디오 드라이버 추가가 명확한 인터페이스로 가능.

  4. 완비된 CI/CD 파이프라인: 8개 GitHub Actions 워크플로우로 macOS/Windows/Linux 멀티 플랫폼 자동 빌드, 서명, 릴리즈. 개발자가 별도 작업 없이 모든 플랫폼 배포 자동화.

  5. 풍부하고 실용적인 문서화: CLAUDE.md의 Claude Code 전용 개발 가이드, docs/GPU_ACCELERATION.md, docs/BUILDING.md 등 신규 기여자와 플랫폼 특이사항을 철저히 커버. 실제 코드 경로까지 명시한 높은 품질의 개발 문서.

위험/개선 필요 사항 (Risks & Areas for Improvement)

  1. 테스트 커버리지 심각한 부족: 핵심 비즈니스 로직인 오디오 파이프라인, VAD, Whisper 전사, LLM 요약 연동에 대한 자동화 테스트가 사실상 없음. 프론트엔드 3개 파일만 존재. 리그레션 감지 능력 매우 제한적. Rust #[cfg(test)] 단위 테스트 및 통합 테스트 전략 수립 필요.

  2. 단일 기여자 버스 팩터: 주요 기여자가 1인(Sujith S)에 집중. Rust 오디오 처리와 같은 복잡한 도메인 지식이 소수에게 집중되어 장기 유지보수 위험 존재. 기여자 다양성 확대 및 지식 문서화 강화 필요.

  3. 보안 공식 프로세스 부재: SECURITY.md 취약점 신고 채널 미제공, Dependabot/Renovate 의존성 취약점 자동 스캔 미설정. Rust 생태계(whisper-rs, ort)의 빠른 의존성 변화를 추적하지 않으면 공급망 위험 증가. SBOM 생성도 미비.

  4. 레거시 아카이브 공존에 따른 혼란 위험: backend/ 디렉토리의 아카이브된 Python/FastAPI 코드가 저장소에 공존. CLAUDE.md에서 명시적으로 경고하지만, 신규 기여자/사용자가 잘못된 경로를 따를 위험. 별도 브랜치나 서브모듈로 분리하거나 README에 더 강한 경고 추가 권고.

  5. 로컬 데이터 암호화 전략 미명시: 로컬 SQLite DB 및 녹음 파일에 대한 저장 데이터 암호화 여부가 공식 문서에 명시되지 않음. 기기 분실 시나리오에서 회의 내용 노출 위험. 민감한 비즈니스 회의 내용을 다루는 엔터프라이즈 사용 시 중요한 보안 요소.
