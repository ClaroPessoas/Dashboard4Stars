1. 목적 및 범위 (Purpose & Scope)

한국어

SkillSpector는 NVIDIA가 개발한 AI 에이전트 스킬 보안 스캐너다. Claude Code, Codex CLI, Gemini CLI 등의 AI 에이전트 플랫폼에서 실행되는 "스킬(플러그인)"은 묵시적 신뢰 하에 실행되며 검증이 거의 이루어지지 않는다는 보안 공백을 해결한다. 핵심 질문은 "이 스킬을 설치해도 안전한가?"이며, 정적 패턴 분석·행동 AST 분석·YARA 서명 매칭·실시간 CVE 조회·선택적 LLM 의미 분석을 결합하여 0~100 위험 점수와 권고사항을 출력한다.

English

SkillSpector is a security scanner for AI agent skills developed by NVIDIA. It addresses a critical gap: skills (plugins) for agent platforms like Claude Code, Codex CLI, and Gemini CLI execute with implicit trust and minimal vetting. Research on 42,447 skills found 26.1% contain vulnerabilities and 5.2% show likely malicious intent. The tool answers "Is this skill safe to install?" by combining static regex analysis, Python AST inspection, YARA signature matching, live OSV.dev CVE lookups, and optional LLM semantic evaluation — producing a 0–100 risk score with severity labels and install recommendations.

분류 / Classification: 보안 도구 (Security Tool/Scanner)
대상 사용자 / Target Users: AI 에이전트 플랫폼 운영자, 보안 엔지니어, 개발자, 기업 IT 팀

4.2 상태 관리 (State Management)

SkillspectorState (TypedDict, total=False):

키 유형 역할
input_path str 원본 입력 경로
skill_path str 정규화된 로컬 경로
file_cache dict 파일명 → 내용 매핑
findings Annotated[list, operator.add] 모든 분석기의 발견사항 집계
filtered_findings list 메타 분석기 후 최종 발견사항
risk_score int 0–100 위험 점수
report_body str 최종 출력 내용

핵심 설계 결정: findings의 Annotated[list, operator.add] 리듀서는 20개 병렬 분석기가 경합 없이 독립적으로 발견사항을 추가할 수 있도록 한다.

4.5 위험 점수 계산 알고리즘

score = 0
for finding in findings:
    score += {CRITICAL: 50, HIGH: 25, MEDIUM: 10, LOW: 5}[finding.severity]
if has_executable_scripts:
    score *= 1.3       # 실행 가능 스크립트 1.3배 가중치
score = min(100, max(0, round(score)))
점수 범위 심각도 권고사항
0–20 LOW 설치 가능 (SAFE)
21–50 MEDIUM 주의 (CAUTION)
51–80 HIGH 설치 금지
81–100 CRITICAL 설치 금지

강점 (Strengths)

  1. 다층 탐지 전략 (Multi-Layer Detection Strategy)
    정적 패턴(regex) + 행동 AST + YARA 서명 + 실시간 CVE + LLM 의미 분석을 단일 파이프라인으로 결합. 단일 기법의 오탐/미탐을 상호 보완하여 높은 탐지율을 달성한다.

  2. LangGraph 기반 병렬 워크플로 설계 (LangGraph Parallel Workflow)
    20개 분석기가 동시에 실행되며 operator.add 리듀서로 경합 없이 발견사항을 집계한다. 새 분석기 추가가 레지스트리(ANALYZER_NODES 딕셔너리)에만 등록하면 되므로 확장성이 뛰어나다.

  3. 실시간 CVE 조회 (Live CVE Lookup via OSV.dev)
    정적 취약점 목록(15개)을 훨씬 초월하는 수만 건의 PyPI/npm 어드바이저리를 OSV.dev API로 실시간 조회. 캐시 TTL(1시간)과 오프라인 폴백을 갖춰 운영 안정성도 확보했다.

  4. 플러그형 LLM 공급자 시스템 (Pluggable LLM Provider Architecture)
    OpenAI, Anthropic, NVIDIA Build 세 공급자를 환경변수 하나(SKILLSPECTOR_PROVIDER)로 교체 가능하며, 슬롯별 기본 모델 설정과 모델 레지스트리 YAML로 세밀한 제어를 지원한다.

  5. SARIF 2.1.0 표준 지원 (SARIF 2.1.0 Compliance)
    GitHub Code Scanning, VS Code, JetBrains 등 주요 IDE/CI 도구와 표준 형식으로 통합 가능. 보안 결과를 개발 워크플로에 자연스럽게 삽입할 수 있다.

위험 및 개선 필요 사항 (Risks & Areas for Improvement)

  1. 스텁(Stub) 분석기 다수 (Incomplete Stub Analyzers)
    behavioral_taint_tracking(TT1–TT5), mcp_rug_pull, 일부 semantic_* 분석기가 스텁으로 남아 있다. 이 범주들은 보고서에 표시되지만 실질적인 탐지가 이루어지지 않아 보안 보장의 범위가 문서상 기술보다 좁다.

  2. GitHub Actions CI/CD 미설정 (No Visible CI/CD Pipeline)
    .github/workflows/ 디렉토리에 워크플로 파일이 체크인되지 않았다. PR 자동 테스트, 보안 스캔(ironically), 릴리즈 자동화 여부를 확인할 수 없다. Makefile 기반 수동 프로세스에만 의존한다면 재현 가능성과 일관성이 저하된다.

  3. SBOM 및 의존성 자동 감사 부재 (No SBOM or Automated Dependency Audit)
    Dependabot, Renovate, Snyk 등 의존성 자동 업데이트/취약점 감사 도구 설정이 확인되지 않는다. 역설적으로 보안 스캐너를 만들면서 자신의 의존성 취약점 관리가 수동에 의존하는 점은 개선 필요가 있다.

  4. Docker/Kubernetes 미지원 (No Container/Kubernetes Support)
    배포 옵션이 PyPI 설치와 로컬 LangGraph 개발 서버에 국한된다. 엔터프라이즈 환경에서 REST API 서버나 컨테이너 기반 배포가 필요할 때 직접 구현이 필요하다. docs/plans/에 REST API(FastAPI) 계획이 있으나 미구현 상태다.

  5. 비정형 콘텐츠 탐지 한계 (Limited Non-Code Detection)
    이미지 임베드 텍스트, 암호화/컴파일된 바이너리, 영어 외 언어 콘텐츠에 대한 탐지가 불가능하다. 런타임 동적 행동 분석(샌드박스 실행)도 지원하지 않아 난독화된 악성 코드는 탐지를 회피할 수 있다.
