세부 분석 / Detailed Analysis

Step 1. 목적 및 범위 / Purpose and Scope

Career-Ops는 AI 코딩 CLI를 완전한 구직 커맨드 센터로 전환하는 로컬 우선 구직 자동화 도구다. 작자 santifer가 개인 구직 과정(740개+ 공고 평가, 100개+ CV, Head of Applied AI 포지션 획득)에서 실전 사용하여 검증한 뒤 오픈소스화했다. 대상 사용자는 AI 코딩 CLI에 익숙한 기술직 구직자이며, AI에 의한 스크리닝에 AI로 대응하는 역발상 컨셉이 핵심이다.

프로젝트 유형: 복합 도구(CLI 자동화 + 마크다운 프롬프트 라이브러리 + TUI 대시보드 + 플러그인 플랫폼)

핵심 원칙: Human-in-the-Loop — AI는 평가·초안을 준비하고, 최종 제출은 반드시 사용자가 결정한다.

Step 4. 아키텍처 분석 / Architecture Analysis

3대 원칙: 1. 로컬 우선(Local-first): 계정·서버 불필요, 모든 데이터가 로컬에 존재 2. AI 무관(AI-agnostic): 프롬프트 로직이 modes/ 마크다운에 격리, 어떤 CLI/모델로도 실행 가능 3. Human-in-the-Loop: 제출 버튼은 항상 사용자가 누름

아키텍처 패턴: 프롬프트 기반 파이프라인 아키텍처. 전통적인 MVC나 Clean Architecture와 다르게, 비즈니스 로직(스코어링·아케타입 감지·협상 프레임워크)이 마크다운 프롬프트 파일에 구현되고, AI CLI가 런타임 실행기 역할을 한다.

핵심 데이터 흐름:

scan.mjs → data/pipeline.md → [AI 평가 (oferta.md + cv.md)] → reports/NNN-*.md
                                             ↓
                              data/applications.md (tracker)
                                             ↓
                              apply mode → [human reviews] → submit

플러그인 시스템: 훅 기반 옵트인 구조. manifest.json 파싱 (실행 전), allowedHosts 네트워크 허용 목록, humanInTheLoop: true 강제, 공급망 검증(plugins-registry.json 신뢰 루트).

상태 관리: 파일 기반. data/applications.md가 소스 오브 트루스, data/applications.db는 SQLite 파생 인덱스(재생성 가능). 원자적 보고서 번호 예약으로 동시성 충돌 방지.

Step 5. 품질 및 테스트 시스템 / Quality and Test System

테스트 아키텍처: - test-all.mjs (9,758줄, 500개+ 검증): 구문 검사, 스크립트 실행, 데이터 계약 경계, 개인정보 노출, 업데이터 안전성, 경로 커버리지 검증. 프레임워크 없이 Node.js 내장만 사용하여 clean checkout에서 즉시 실행 가능 - updater-migration-tests.mjs: 시스템/유저 경계 교차 여부 및 버전 간 안전 업그레이드 강제 - detect-reposts.test.mjs, followup-cadence.test.mjs, tracker-columns-tests.mjs: 독립 모듈 테스트 - test-salary-filter.mjs, test-trust-validator.mjs: 특화 기능 검증 - Go: open_command_test.go (TUI 오픈 커맨드 크로스플랫폼 테스트)

CI/CD: - PR 트리거: 테스트(--quick) + CodeQL + 의존성 리뷰 + no-user-data 가드 - main 푸시: CodeQL 전체 분석 + release-please 자동화 - 릴리즈: SBOM 생성(SPDX JSON), npm 퍼블리시(scaffolder, provenance 포함) - 주간: Dependabot(npm+gomod+Actions), Renovate, CodeQL 스케줄 스캔

린팅/포맷팅: 별도 linter 설정 파일 없음(.eslintrc 등). CodeRabbit 자동 리뷰가 주요 코드 품질 게이트 역할.

버저닝: Conventional Commits + release-please 자동화, VERSION 파일 + package.json 동기화, semver.

강점 / Strengths

  1. 이중 레이어 데이터 계약 아키텍처: DATA_CONTRACT.md→update-system.mjs→updater-migration-tests.mjs→no-user-data.yml로 이어지는 시스템/유저 경계 강제 체계가 코드·CI·문서 3계층에서 동시 작동. 사용자 개인정보가 실수로 커밋될 가능성을 구조적으로 차단한다.

  2. 프레임워크 의존성 최소화: Node.js 의존성 4개(Playwright, js-yaml, dotenv, @google/generative-ai)의 극단적 경량화. 테스트 스위트도 외부 프레임워크 없이 Node.js 내장만 사용, clean checkout 즉시 실행 가능.

  3. AI 무관 아키텍처: 비즈니스 로직이 마크다운 프롬프트(modes/)에 구현되어 Claude Code, Gemini, Codex, Qwen, OpenCode 등 모든 AI CLI에서 동일하게 작동. 스탠드얼론 평가기(Gemini/Ollama/OpenRouter)도 지원하여 모델 락인 없음.

  4. 다층 보안 게이팅: CodeQL(JS+Go 이중 언어), Dependabot+Renovate 이중 의존성 관리, SBOM 릴리즈 첨부, 플러그인 공급망 격리(allowedHosts+manifest 선파싱+registry 신뢰 루트)가 체계적으로 구성되어 있다.

  5. 운영 성숙도: v1.16.0, 14개 언어 README, 완전 자동화된 릴리즈(release-please+npm provenance publish), BDFL 거버넌스+Contributor Ladder, CITATION.cff 학술 인용 지원, 7개 언어 모드(EN/DE/FR/JA/AR/TR 등)에 이르는 국제화 수준이 단기간(2026년) 성장 대비 매우 성숙하다.

위험 및 개선 필요 사항 / Risks and Areas for Improvement

  1. 의존성 리뷰 임시 우회: .github/workflows/dependency-review.yml에 continue-on-error: true가 설정되어 고위험 의존성이 실제로 병합을 차단하지 않는다(#343 이슈 추적 중). Dependency Graph 활성화 전까지는 보안 게이트에 구멍이 존재한다.

  2. Playwright 버전 불일치 리스크: package.json은 playwright@1.61.1을 선언하나 Dockerfile에 playwright@1.58.1 하드코딩이 남아 있다. 버전 드리프트가 PDF 생성·스크래핑에서 재현하기 어려운 오류를 유발할 수 있다.

  3. 로컬 전용 설계의 규모 한계: 현재 아키텍처는 개인 사용에 최적화되어 있고, 팀 공유나 원격 스케줄링 시나리오에 대한 공식 지원이 없다. 문서가 Discord Discussion에서 논의 중인 "hosted layer" 방향을 언급하지만 현재 Core에는 없다.

  4. 린터/포맷터 부재: ESLint, Prettier, Go gofmt 강제 CI 스텝이 없다. 코드 품질이 CodeRabbit 리뷰와 기여자 자율에 의존하며, 대규모 기여 확대 시 스타일 일관성 유지가 어려워질 수 있다.

  5. 테스트 커버리지 불균형: test-all.mjs가 광범위하나 일부 핵심 스크립트(예: analyze-patterns.mjs, openrouter-runner.mjs, gemini-eval.mjs)에 대한 독립 단위 테스트가 없다. 35,000줄+ 파일들이 통합 테스트 수준에서만 검증된다.

도입 권고 / Adoption Recommendation

기술 도입: AI 보조 구직 자동화 도구로서 강력 권고. 로컬 우선 설계, Human-in-the-Loop 원칙, AI 무관 아키텍처, 4개 의존성의 경량 스택은 개인 구직자에게 실질적인 레버리지를 제공하며 프라이버시 리스크를 최소화한다.

아키텍처 벤치마킹: Markdown-as-Prompt 아키텍처 패턴, 시스템/유저 이중 레이어 데이터 계약 구조, 플러그인 공급망 거버넌스(allowedHosts+manifest 선파싱) 패턴은 유사한 AI 에이전트 툴킷 설계 시 참고 가치가 높다.

보안 검토: 전반적으로 양호하나 Dependency Graph 미활성화에 따른 continue-on-error 우회, Playwright 버전 불일치는 즉시 해결이 권고된다.

기여 적합성: good first issue 경로, 명확한 Contributor Ladder, 빠른 리뷰 응답, 세밀한 기여 범위 가이드(provider 모듈·번역·문서 저장입구 제공)로 오픈소스 첫 기여에 적합하다.

운영 성숙도: v1.16.0, SBOM, 자동화된 릴리즈, 다국어 문서, BDFL 거버넌스로 개인 프로젝트 대비 매우 높은 운영 성숙도를 보인다. 사용자 데이터 보호 철학이 설계 전반에 일관되게 반영되어 있다.
