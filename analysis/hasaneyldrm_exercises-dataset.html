1. 목적 및 범위 / Purpose & Scope

이 저장소는 개발자용 피트니스 운동 데이터셋 + 셋업 마법사이다.

  • 문제 정의: 운동 앱 또는 ML 프로젝트를 시작할 때 정제된 구조화 데이터와 초기 백엔드 뼈대 코드를 얻는 것이 번거롭다. 이 프로젝트는 데이터(JSON), DB 스키마(SQL), API 클라이언트 예시 코드, LLM 프롬프트를 한곳에서 제공한다.
  • 대상 사용자: 운동·피트니스 앱 개발자, 헬스 ML/AI 연구자, 데이터 엔지니어, 교육·시제품 개발자.
  • 분류: 정적 데이터셋 저장소 + 서버리스 개발자 도구 (Library / Dataset + Developer Tool).
  • 원출처: ExerciseDB v1 by AscendAPI (Kaggle을 통해 재호스팅된 데이터 기반). 스페인어·이탈리아어·터키어·러시아어·중국어 번역 및 instruction_steps 배열 분리, 인터랙티브 HTML 도구는 이 프로젝트에서 추가됨.
  • 미디어 미포함: 썸네일 이미지와 GIF 애니메이션은 소유권 분쟁으로 인해 의도적으로 제외. media_id 필드로 ExerciseDB CDN 참조 가능.

4. 아키텍처 분석 / Architecture Analysis

진입점

파일 역할

  • 상태 관리: 단일 state 객체 (exercises, filtered, rendered, 현재 필터 값들)
  • 렌더링: DOM 직접 조작 (innerHTML, createElement)
  • 무한스크롤: IntersectionObserver + load-sentinel 요소로 배치 렌더링
  • 필터·검색: 클라이언트사이드 배열 필터 (메모리 내 전체 데이터)

  • 데이터 중복: index.html 내 인라인 + exercises.json에 동일 데이터 별도 존재

setup.html 아키텍처

  • 탭 UI: DB 종류별(MSSQL, PostgreSQL, MySQL, SQLite) SQL DDL 탭
  • SQL 생성기: 브라우저 메모리에서 exercises.json fetch 후 INSERT 구문 생성, Blob URL로 .sql 파일 다운로드
  • API 코드 예시: JavaScript, Python, C#, Java, PHP, Go, cURL — 라이브 URL 입력 시 모든 예시 동시 갱신
  • LLM 프롬프트 생성기: 프레임워크(Express/FastAPI/ASP.NET/Spring/Laravel/Gin) × DB(PostgreSQL/MySQL/MSSQL/SQLite) 조합으로 완성형 백엔드 생성 프롬프트 출력

아키텍처 패턴

  • SPA-lite: 단일 HTML 파일에 CSS·JS·데이터 모두 포함 (빌드 없는 단일 파일 앱)
  • 레이어 미분리: 프레젠테이션, 비즈니스 로직, 데이터 접근이 동일 파일에 혼재
  • 이벤트 기반 UI: addEventListener 패턴으로 상태 전이 처리

8. 강점 / Strengths

  1. 제로 의존성 배포: 빌드 도구, 패키지 매니저, 서버 없이 브라우저에서 즉시 실행. 개발자 온보딩 마찰이 사실상 0에 가깝다.

  3. end-to-end 개발자 경험: JSON 데이터 → SQL DDL 생성 → API 클라이언트 코드 → LLM 백엔드 프롬프트까지 한 번에 제공하는 setup.html은 프로토타입 개발 속도를 크게 높인다.
  4. 이식성 높은 JSON 스키마: id, category, body_part, equipment, target, muscle_group, secondary_muscles 등 잘 정규화된 필드 구조로 Python(pandas), JavaScript, TypeScript에서 바로 타입 정의 및 필터링이 가능하다.
  5. 미디어 분리 결정의 투명성: 이미지/GIF를 제외한 이유(저작권 분쟁)를 명시하고 media_id로 원본 CDN 참조를 유지한 결정은 법적 리스크를 최소화하면서 데이터 참조 체인을 보존한다.

9. 위험 및 개선 필요 사항 / Risks & Improvements

  1. index.html 9MB 인라인 데이터: 전체 데이터셋이 단일 HTML 파일에 JS 리터럴로 포함되어 초기 로드 비용이 크다. setup.html처럼 fetch('data/exercises.json')을 사용하는 방식으로 전환하면 파일 크기를 99% 줄이고 캐싱 효율을 높일 수 있다.
  2. LICENSE 파일 부재: 명시적 라이선스 없이 저장소를 공개하면 법적 재사용 불명확성이 발생한다. ExerciseDB v1 원본 라이선스와 이 프로젝트의 추가 기여물(번역, HTML 도구)에 대한 조건을 별도 LICENSE 파일로 명시해야 한다.
  3. 데이터 무결성 자동 검증 없음: 스키마 유효성 검사(필수 필드 존재, 언어 키 완전성, category/equipment/target 허용값 범위)를 자동으로 검증하는 스크립트나 CI가 없다. 향후 데이터 갱신 시 조용한 데이터 손상 위험이 있다.
  4. 데이터 이중화: 동일한 1,324개 레코드가 index.html (인라인)과 exercises.json (파일)에 각각 존재한다. index.html이 exercises.json을 fetch하도록 리팩토링하면 단일 진실 원천(SSOT)을 유지하고 데이터 업데이트 오류를 방지할 수 있다.
  5. 커뮤니티·거버넌스 인프라 부재: CONTRIBUTING.md, CHANGELOG, 이슈 템플릿, CI, 릴리스 태그가 없어 외부 기여 수용 및 버전 관리가 어렵다. 오픈소스 프로젝트로 성장하려면 기초 거버넌스 문서가 필요하다.

한국어

이 저장소는 운동 앱 프로토타입, ML 벤치마크 데이터셋, 교육 시연에 즉시 활용 가능한 고품질 데이터 소스다. 제로 의존성 아키텍처와 즉시 사용 가능한 개발자 도구(setup.html)는 온보딩 마찰을 최소화한다.

도입 시 유의사항: - 상업적 활용 전 ExerciseDB v1 원본 라이선스(oss.exercisedb.dev) 확인 필수. 현재 LICENSE 파일이 없어 법적 명확성이 낮다. - 미디어(이미지·GIF)가 포함되지 않으므로 시각 자산이 필요한 앱은 ExerciseDB 공식 CDN 또는 별도 미디어 소스를 추가로 확보해야 한다. - 프로덕션 앱에 통합 시 index.html의 9MB 인라인 데이터 방식보다 exercises.json 직접 fetch 방식을 사용하는 것을 강권한다. - 단일 커밋·단일 기여자 프로젝트로 장기 유지보수 지속성을 보장할 수 없으므로, 필요 시 포크 후 자체 관리를 권장한다.

권고 등급: 조건부 채택 권장 (Conditional Adopt) 데이터 자체의 품질과 구조는 우수하나, 라이선스 명확화와 데이터 이중화 해소 후 프로덕션 도입을 권장한다.

English Summary

This repository is a ready-to-use fitness exercise dataset + developer onboarding wizard. The dataset quality is strong: 1,324 exercises, consistent schema, 6-language multilingual instructions in both prose and step-array formats, covering 28 equipment types and 19 target muscles.

Key adoption considerations: - Commercial use: No LICENSE file exists. The README disclaims ownership of underlying content and points to ExerciseDB v1's terms. Legal review is required before any commercial use. - Media assets: Images and GIFs are intentionally excluded due to ownership disputes. The media_id field provides a pointer to the ExerciseDB CDN for those with access rights. - Technical debt: index.html's 9MB inline data embed is the primary architectural concern — trivially fixable by switching to a fetch() call. No test infrastructure or CI exists. - Maturity: Single commit, single contributor project as of analysis date. Fork and self-maintain if long-term stability is required.

Recommendation: Conditionally Adopt — excellent data asset for prototyping, ML, and education; resolve license ambiguity and data duplication before production integration.
