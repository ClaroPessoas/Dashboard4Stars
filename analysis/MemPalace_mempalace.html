Step 1. 목적 및 범위 / Purpose & Scope

해결하는 문제 (Problem Statement)

AI 에이전트(특히 Claude Code)는 대화 세션이 끝나면 모든 컨텍스트를 잃는다. MemPalace는 이 "대화 간 기억 상실" 문제를 해결하기 위해 설계된 로컬 우선 메모리 시스템이다.

핵심 설계 요구사항: - 원문 보존(Verbatim Always): 사용자가 말한 내용을 단 한 글자도 요약하거나 의역하지 않고 저장 - 100% 리콜: 모든 검색 경로는 100% 리콜을 목표로 측정됨 - API 키 불필요: 핵심 기능은 외부 서비스 없이 로컬에서 동작 - 프라이버시 by 아키텍처: 데이터가 물리적으로 사용자 기기를 벗어날 수 없음

대상 사용자 (Target Users)

  • AI 코딩 에이전트(Claude Code, OpenAI Codex CLI)를 사용하는 개발자
  • 대화 기록의 장기 보존이 필요한 파워 유저
  • 로컬 LLM(Ollama, LM Studio, llama.cpp) 사용자

분류 (Classification)

애플리케이션 + 라이브러리 + MCP 플러그인 — 독립 실행형 CLI, Python 패키지, MCP 서버의 세 가지 인터페이스를 동시에 제공하는 복합 시스템.

Step 4. 아키텍처 분석 / Architecture Analysis

진입점 (Entry Points)

CLI:     mempalace.cli:main
         ├── init <dir>        — 폴더에서 룸 감지
         ├── split <dir>       — 메가 파일 분할
         ├── mine <dir>        — 프로젝트/대화 채굴
         ├── search "query"    — 시맨틱 검색
         ├── wake-up           — L0+L1 컨텍스트 표시
         └── status            — 팰리스 인벤토리

MCP:     mempalace.mcp_server:main
         └── 29개 도구 (읽기, 쓰기, 유지보수)
             ├── mempalace_status
             ├── mempalace_search
             ├── mempalace_add_drawer
             ├── mempalace_delete_drawer
             └── ...

팰리스 계층 구조 (Palace Hierarchy)

WING (사람/프로젝트)
  └── ROOM (날짜/주제)
        └── DRAWER (원문 텍스트 청크)
              ↑ 포인터
        CLOSET (AAAK 압축 인덱스)
  • Drawers: 원문 보존, 검색 결과로 반환되는 실제 내용
  • Closets: AAAK 형식의 손실 압축 인덱스, LLM이 스캔하여 어느 Drawer를 열지 결정
  • Wings: 사람 또는 프로젝트 기준 최상위 스코핑
  • Rooms: 날짜 또는 주제 기준 중간 스코핑

4계층 메모리 웨이크업 스택 (L0–L3)

L0: Identity (~100 tokens)      — 항상 로드. "나는 누구인가?"
L1: Essential Story (~500–800)  — 항상 로드. 핵심 순간들.
L2: On-Demand (~200–500 each)   — 주제/윙이 언급될 때 로드.
L3: Deep Search (무제한)        — 전체 ChromaDB 시맨틱 검색.

웨이크업 비용: ~600–900 토큰 (L0+L1), 컨텍스트 95%+ 자유 유지

RFC 001 플러그인 백엔드 인터페이스

class BaseBackend(ABC):
    name: ClassVar[str]
    spec_version: ClassVar[str]
    capabilities: ClassVar[frozenset[str]]

    @abstractmethod
    def get_collection(self, palace_ref: PalaceRef, ...) -> BaseCollection: ...

class BaseCollection(ABC):
    @abstractmethod
    def add(self, ids, documents, metadatas, embeddings) -> None: ...
    @abstractmethod
    def query(self, query_embeddings, n_results, where, ...) -> QueryResult: ...
    @abstractmethod
    def upsert(self, ...) -> None: ...
    @abstractmethod
    def delete(self, ...) -> None: ...
    @abstractmethod
    def count(self) -> int: ...

구현체: ChromaDB (기본), SQLiteExact, Qdrant, pgvector

하이브리드 검색 (BM25 + 벡터)

쿼리
  ├── BM25 키워드 매칭 (k1=1.5, b=0.75)
  ├── 벡터 시맨틱 유사도 (ChromaDB HNSW)
  ├── FTS5 전문 검색 (폴백)
  └── AAAK 클로짓 랭킹 부스트

AAAK 압축 방언 (인덱스 레이어)

헤더:   FILE_NUM|PRIMARY_ENTITY|DATE|TITLE
제텔:   ZID:ENTITIES|topic_keywords|"key_quote"|WEIGHT|EMOTIONS|FLAGS
터널:   T:ZID<->ZID|label
아크:   ARC:emotion->emotion->emotion

중요 사항: AAAK는 손실 압축 — 원문 재구성 불가. 96.6% 벤치마크는 원문 모드(Drawers)에서 달성됨.

시간적 지식 그래프 (Temporal Knowledge Graph)

kg.add_triple(subject, predicate, object, valid_from, valid_to)
kg.query_entity(name, as_of=date, direction="out|in|both")
kg.invalidate(subject, predicate, object, ended=date)

SQLite 로컬 저장. 사실의 유효 기간(valid_from → valid_to) 추적.

강점 / Strengths

  1. 원문 보존(Verbatim) 원칙의 철저한 구현 설계 원칙이 PR 수용 기준에 명시되어 있으며, sanitize_content()는 길이 제한을 두지 않고 원문을 그대로 저장한다. 요약/의역을 허용하는 PR은 아키텍처 레벨에서 거부된다. AAAK 클로짓이 손실 압축임을 명확히 구별하는 문서가 존재한다.

  2. RFC 001 기반 플러그인 백엔드 — 벤더 독립성 BaseBackend / BaseCollection 추상 인터페이스가 명확히 정의되어 있고, ChromaDB·SQLite·Qdrant·pgvector 4개 구현체가 존재한다. 새 백엔드 추가는 두 클래스를 상속하고 entry_points에 등록하는 것으로 완성된다.

  3. 다계층 CI/CD — 릴리스 품질 보증 버전 동기화 검사(version-guard.yml)가 5개 소스를 검증하고, OIDC Trusted Publishing으로 토큰 없이 릴리스한다. 단일 잡 publish(BlobNotFound 방지), 멀티아키텍처 Docker 이미지, 다플랫폼 테스트 매트릭스가 함께 구성된다.

  4. 4계층 메모리 스택(L0–L3)의 토큰 경제성 웨이크업 비용 ~600–900 토큰으로 컨텍스트의 95%+를 자유롭게 유지한다. L0(항상), L1(항상), L2(온디맨드), L3(딥서치)의 계층적 설계가 비용과 리콜을 동시에 최적화한다.

  5. 로컬 우선 프라이버시 by 아키텍처 핵심 기능이 외부 API 없이 동작하며, ONNX 임베딩 모델이 로컬에서 실행된다. "물리적으로 데이터가 기기를 벗어날 수 없다"는 설계가 텔레메트리 부재와 결합하여 프라이버시를 아키텍처 레벨에서 보장한다.

위험/개선 필요 사항 / Risks & Areas for Improvement

  1. ChromaDB 버전 상한 제약 (<2) chromadb>=1.5.4,<2 제약은 ChromaDB 2.x가 출시될 경우 업그레이드 블로킹 리스크를 내포한다. HNSW 링크 비율 검사(_hnsw_link_to_data_ratio)처럼 내부 API에 의존하는 코드가 버전 업에 취약하다.

  2. Dependabot/Renovate 자동 의존성 업데이트 부재 의존성 취약점 자동 감지 도구가 확인되지 않는다. 76MB 저장소에 1.1MB uv.lock 파일이 있지만, CVE 알림이나 자동 PR 생성 도구가 없으면 보안 패치가 지연될 수 있다.

  3. SBOM 및 아티팩트 서명 미비 Docker 이미지와 PyPI 패키지에 대한 SBOM(Software Bill of Materials) 생성 및 Sigstore/cosign 아티팩트 서명이 확인되지 않는다. 공급망 보안 강화를 위해 필요하다.

  4. 훅 스크립트의 bash 의존성 — macOS/Windows 호환성 복잡성 mempal_save_hook.sh에 macOS bash 3.2 호환 우회코드(mapfile → sed 파이프라인)가 존재한다. 셸 스크립트 기반 훅은 크로스 플랫폼 배포 시 유지보수 부담이 증가한다. Python 기반 훅으로의 이전이 장기적으로 유리하다.

  5. 단일 메인테이너 리스크 활발한 개발이 주로 milla-jovovich 중심으로 이루어지고 있으며, 오픈소스 기여자 다양성이 제한적으로 관찰된다. 버스 팩터(bus factor)가 낮을 경우 프로젝트 지속성에 위험이 된다.

1. 프로젝트 개요 / Project Overview

1.1 목적 및 분류 / Purpose and Classification

해결하는 문제 / Problem solved

AI 어시스턴트(특히 Claude Code, Gemini CLI 등 MCP 클라이언트)는 세션 간 컨텍스트를 잃는다. MemPalace는 모든 대화·프로젝트 파일을 사용자 로컬 머신에 원문 그대로(verbatim) 저장하여, 어떤 세션에서도 이전 대화·지식을 즉시 검색·주입할 수 있는 장기 기억 시스템을 제공한다. "요약 없음, 외부 API 없음, 100% 재현율(recall)"이 핵심 설계 요구사항이다.

분류 / Classification: Platform (Memory/RAG) + Tool (CLI + MCP Server) - 29개 MCP 도구, 4개 플러그인 스토리지 백엔드, CLI 디스패처 포함 - 사용자에게는 설치형 툴로 동작하며, AI 에이전트에게는 장기기억 플랫폼으로 동작

종합 판정 / Overall Verdict: 🔵 Review

상세 판정 근거:

MemPalace는 상용화에 있어 법적 라이선스 위험이 매우 낮은 프로젝트이다. MIT 라이선스와 전적으로 Permissive한 의존성 구성은 소스 비공개 상용 제품 내 포함, SaaS 배포, 재판매 등 모든 상업 시나리오에서 법적 장애물이 없다. 기술적으로는 플러그인 백엔드 아키텍처(RFC 001), 하이브리드 검색, 지식 그래프, 다국어 지원 등 엔터프라이즈 수준의 설계를 갖추고 있다.

그러나 조건부 채택(Review)으로 분류하는 이유는 다음과 같다:

  • 커뮤니티 버스 팩터: 장기 유지 관리 지속 여부에 대한 확신을 얻기 전, 기여자 분포 및 조직 구조 실사(due diligence)가 선행되어야 한다
  • NOTICE·SBOM 미비: 엔터프라이즈 공급망 감사 대응을 위한 최소 컴플라이언스 문서가 없음. 도입 전 이 파일들을 프로젝트에 기여하거나 내부적으로 생성해야 한다
  • posthog 전이 텔레메트리: 데이터 격리 요구가 엄격한 환경에서는 chromadb 텔레메트리 비활성화 절차를 배포 표준에 명시해야 한다
  • 운영 관측성 격차: 대규모 엔터프라이즈 배포(K8s)를 위해서는 헬스체크 엔드포인트와 메트릭 노출 레이어를 추가해야 한다

이러한 조건들은 모두 기술적으로 해결 가능하며, 라이선스 구조 자체의 위험은 없다. 소규모 팀 또는 인터널 배포 시나리오에서는 즉시 도입 가능, 엔터프라이즈 외부 배포 시나리오에서는 30~90일 내 조건부 도입 가능으로 판단한다.
