1. 프로젝트 개요 / Project Overview

1.1 목적 및 분류 / Purpose and Classification

해결하는 문제 / Problem solved

AI 어시스턴트(특히 Claude Code, Gemini CLI 등 MCP 클라이언트)는 세션 간 컨텍스트를 잃는다. MemPalace는 모든 대화·프로젝트 파일을 사용자 로컬 머신에 원문 그대로(verbatim) 저장하여, 어떤 세션에서도 이전 대화·지식을 즉시 검색·주입할 수 있는 장기 기억 시스템을 제공한다. "요약 없음, 외부 API 없음, 100% 재현율(recall)"이 핵심 설계 요구사항이다.

분류 / Classification: Platform (Memory/RAG) + Tool (CLI + MCP Server) - 29개 MCP 도구, 4개 플러그인 스토리지 백엔드, CLI 디스패처 포함 - 사용자에게는 설치형 툴로 동작하며, AI 에이전트에게는 장기기억 플랫폼으로 동작

2.4 라이선스 호환성 분석 / License Compatibility Analysis

충돌 없음 / No conflicts detected: - 모든 코어 의존성이 MIT 또는 Apache 2.0 이상의 permissive 라이선스 - AGPL, GPL 컴포넌트 없음 → 전파 위험 없음 - BUSL / Commons Clause 없음 → 상용화 금지 조항 없음

LGPL 주의사항 (psycopg[binary]): - pgvector 백엔드는 선택적 의존성 (pip install mempalace[pgvector]) - psycopg[binary]는 Python 동적 임포트로 사용 — LGPL의 "동적 링크" 조건 충족 - LGPL-3.0 하에서는 라이브러리 자체를 수정하지 않는 한 소스 공개 의무 없음 - 권고: pgvector 백엔드 사용 시 제품 고지문에 psycopg3 LGPL 고지 포함 권장

posthog 전이 의존성: - chromadb가 posthog를 사용하여 익명 텔레메트리를 수집할 수 있음 - MemPalace는 CHROMA_TELEMETRY=false 또는 유사 환경 변수로 이를 비활성화해야 하는지 문서화 미비 - 엔터프라이즈 배포 시 chromadb 텔레메트리 비활성화 확인 필요

3.2 알려진 위험 요소 / Known Risk Factors

긍정적 사항 / Positive findings: - HNSW 인덱스 부패 탐지·격리 로직 구현 (mcp_server.py, backends/chroma.py — _HNSW_LINK_TO_DATA_MAX_RATIO = 10.0) - 프롬프트 오염 방지 모듈 존재 (query_sanitizer.py) — MCP 도구 경유 프롬프트 인젝션 방어 - MCP stdio 보호 구현 (mcp_server.py) — chromadb/posthog의 stdout 직접 쓰기 문제 해결 - 파일 원자적 쓰기 (.tmp 사이드카) 구현 확인 — 크래시 안전성 - 입력 검증 중앙화 (config.py: sanitize_name(), sanitize_kg_value()) — 경로 순회·특수문자 방지 - UTF-16 고아 서로게이트 제거 (strip_lone_surrogates()) — 클립보드·MCP 데이터 오염 방어

종합 판정 / Overall Verdict: 🔵 Review

상세 판정 근거:

MemPalace는 상용화에 있어 법적 라이선스 위험이 매우 낮은 프로젝트이다. MIT 라이선스와 전적으로 Permissive한 의존성 구성은 소스 비공개 상용 제품 내 포함, SaaS 배포, 재판매 등 모든 상업 시나리오에서 법적 장애물이 없다. 기술적으로는 플러그인 백엔드 아키텍처(RFC 001), 하이브리드 검색, 지식 그래프, 다국어 지원 등 엔터프라이즈 수준의 설계를 갖추고 있다.

그러나 조건부 채택(Review)으로 분류하는 이유는 다음과 같다:

  • 커뮤니티 버스 팩터: 장기 유지 관리 지속 여부에 대한 확신을 얻기 전, 기여자 분포 및 조직 구조 실사(due diligence)가 선행되어야 한다
  • NOTICE·SBOM 미비: 엔터프라이즈 공급망 감사 대응을 위한 최소 컴플라이언스 문서가 없음. 도입 전 이 파일들을 프로젝트에 기여하거나 내부적으로 생성해야 한다
  • posthog 전이 텔레메트리: 데이터 격리 요구가 엄격한 환경에서는 chromadb 텔레메트리 비활성화 절차를 배포 표준에 명시해야 한다
  • 운영 관측성 격차: 대규모 엔터프라이즈 배포(K8s)를 위해서는 헬스체크 엔드포인트와 메트릭 노출 레이어를 추가해야 한다

이러한 조건들은 모두 기술적으로 해결 가능하며, 라이선스 구조 자체의 위험은 없다. 소규모 팀 또는 인터널 배포 시나리오에서는 즉시 도입 가능, 엔터프라이즈 외부 배포 시나리오에서는 30~90일 내 조건부 도입 가능으로 판단한다.
