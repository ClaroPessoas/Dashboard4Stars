1. 프로젝트 개요 / Project Overview

1.1 목적 및 분류 / Purpose and Classification

해결하는 문제 / Problem solved: Google Notebook LM에 대한 프라이버시 중심의 오픈소스 대안으로, 사용자가 PDF·오디오·비디오·웹 페이지 등 멀티모달 콘텐츠를 업로드하고 AI 기반 노트 생성, 시맨틱 검색, 채팅, 팟캐스트 제작을 완전한 데이터 통제권 하에 수행할 수 있도록 한다.

An open-source, privacy-first alternative to Google Notebook LM, enabling users to manage multi-modal content (PDFs, audio, video, web pages), generate AI-powered notes, search semantically, chat with AI, and produce podcasts—all with full data sovereignty and multi-provider AI flexibility.

분류 / Classification: Application / Platform (Self-hosted AI Research Assistant)

3.3 보안 아키텍처 평가 / Security Architecture Assessment

인증/인가 (Auth/AuthZ): - PasswordAuthMiddleware: 단순 Bearer Token(비밀번호) 방식 - 단일 사용자 개념으로 설계된 인증 — 다중 사용자/역할 기반 접근 제어(RBAC) 없음 - 문서에서 프로덕션 배포 시 OAuth/JWT + 역방향 프록시 사용 권장

시크릿 관리: - OPEN_NOTEBOOK_ENCRYPTION_KEY: Fernet(AES-128-CBC + HMAC-SHA256)으로 DB 내 API 키 암호화 - Docker Secrets 패턴 지원(_FILE 접미사) - 기본 암호화 키 없음 — 미설정 시 ValueError 발생 (안전) - SSRF 방지: 사용자 제공 URL 검증, 프라이빗 IP 차단(Ollama 예외) - 경로 순회 방지: os.path.basename() + Path.resolve() 검증

암호화: - DB 저장 자격증명: Fernet 대칭 암호화 ✅ - 전송 암호화: 역방향 프록시(Nginx/Caddy/Traefik) 활용 권장, 자체 TLS 미내장 - API 키는 프론트엔드로 절대 반환되지 않음 ✅

7.4 상용화 도입 권고 / Commercialization Recommendation

종합 판정 / Overall Verdict: 🔵 Review (조건부 도입 — 추가 검토 필요)

상세 근거 / Detailed Rationale:

Open Notebook은 내부 도구·소규모 팀·프리미엄 셀프호스팅 솔루션 용도로는 즉시 도입 가능한 수준의 완성도를 갖추고 있다. MIT 라이선스 기반의 명확하고 안전한 라이선스 구조, 빠른 릴리즈 주기, 포괄적인 문서화는 강점이다.

그러나 다중 사용자 SaaS 플랫폼이나 엔터프라이즈 배포를 목표로 한다면, 다음 선결 조건 충족이 필요하다:

  • 보안: OAuth/OIDC 기반 인증 체계로 교체, RBAC 구현, Dependabot 활성화
  • 운영: 메트릭 노출(Prometheus), 구조화 JSON 로깅, 분산 추적 통합
  • 확장성: LangGraph 체크포인트를 분산 지원 백엔드로 교체, 파일 스토리지 오브젝트 스토리지 전환, 멀티테넌시 레이어 구현
  • 컴플라이언스: SBOM 생성 자동화, NOTICE 파일 작성, CI/CD 라이선스 스캔 연동
  • 지속성: 기업 지원 계약, 공동 메인테이너 확보, 또는 포크 후 내재화 계획 수립
