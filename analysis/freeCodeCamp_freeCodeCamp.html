freeCodeCamp.org는 501(c)(3) 비영리 단체가 운영하는 무료 코딩 교육 플랫폼이다. 주요 목적은 성인 학습자가 개발자로 전직할 수 있도록 인터랙티브 커리큘럼과 인증서를 무료로 제공하는 것이다. 플랫폼은 다음을 포함한다:

  • 반응형 웹 디자인, JavaScript, 프론트엔드 라이브러리, Python, 관계형 DB, 백엔드 API 등 6개 이상의 기술 인증 과정
  • A1~B1 수준 영어/스페인어/중국어 언어 인증 과정
  • 코딩 인터뷰 준비, Odin Project 리믹스, Project Euler, Rosetta Code 포함

Step 4. 아키텍처 분석 (Architecture)

API 아키텍처 (Fastify 플러그인 패턴)

api/src/server.ts          ← 부트스트랩 + 시그널 핸들링
  └── app.ts               ← Fastify 인스턴스 + AJV 설정
       ├── plugins/         ← 횡단 관심사 (auth, csrf, cors, security, mailer, growthBook)
       └── routes/
            ├── public/     ← 인증 불필요 (auth, certificate, donate, signout, status, user)
            └── protected/  ← JWT 인증 필요 (challenge, certificate, donate, settings, user)

Fastify의 캡슐화 + 플러그인 패턴을 활용하여 보안, 인증, CSRF를 미들웨어처럼 구성한다. TypeBox를 통한 런타임 스키마 검증으로 타입 안전성을 API 경계에서 보장한다. Sentry는 instrument.ts에서 최초 임포트로 초기화되어 모든 에러를 사전 캡처한다.

클라이언트 아키텍처 (Gatsby + Redux)

gatsby-config.ts           ← 플러그인 설정, 환경변수 주입
gatsby-node.ts             ← 챌린지/페이지 프로그래밍 방식 생성
  └── src/
       ├── pages/           ← 파일시스템 기반 라우팅
       ├── templates/       ← 챌린지/소개 페이지 템플릿
       ├── components/      ← 도메인별 UI 컴포넌트
       └── redux/           ← Redux Store (Saga + Observable)
            ├── root-reducer.ts
            ├── root-saga.ts
            └── root-epic.ts

Gatsby가 빌드 타임에 커리큘럼 데이터를 GraphQL 레이어로 로드하고, 챌린지 페이지를 정적 생성한다. 클라이언트 사이드에서는 Redux가 사용자 세션, 챌린지 진행 상태, 인증 플로우를 관리한다.

  • 기여자: 수천 명의 자원봉사자 (RepoBeats 통계 연동)

  • i18n: Crowdin 연동으로 12개 언어 지원 (영어, 중국어, 스페인어, 일본어, 한국어 등)

강점 (Strengths)

  1. 성숙한 모노레포 아키텍처: Turborepo + pnpm 워크스페이스 조합으로 의존성 그래프를 명시적으로 관리하며, 원격 캐시로 CI 빌드를 대폭 가속화한다. 패키지 간 경계가 명확해 독립적 빌드/테스트가 가능하다.

  2. 철저한 E2E 테스트 커버리지: 100개 이상의 Playwright 스펙 파일이 실제 사용자 플로우(챌린지 제출, 인증서 발급, 결제, 시험 등)를 망라한다. API 라우트별 통합 테스트도 수천 줄 수준으로 매우 두텁다.

  3. 보안 설계의 체계성: OWASP 헤더, CSRF 방어, TypeBox 스키마 검증, AJV DoS 방어, Auth0 위임 인증, GitHub Actions SHA 핀 고정이 모두 기본 탑재되어 있다.

  4. 자동화된 운영 인프라: 의존성 업데이트(Renovate), 번역(Crowdin), PR 라벨링, 스팸 관리, 비활성 이슈 닫기까지 운영 부담을 최소화하는 자동화가 완비되어 있다.

  5. 도메인 분리와 타입 안전성: API의 Fastify 플러그인 아키텍처와 TypeBox 스키마가 런타임 유효성 검사와 컴파일 타임 타입 안전성을 동시에 보장한다. 프론트엔드와 백엔드 모두 TypeScript 5.9로 전환 완료되어 있다.

위험 / 개선 필요 사항 (Risks and Areas for Improvement)

  1. Gatsby의 기술 부채: Gatsby는 React 기반 SSG이나 커뮤니티 지원이 감소 추세이며, 빌드 속도 문제(--max-old-space-size=7168 설정이 이를 방증)가 있다. Next.js, Astro 등 현대적 대안으로의 장기 마이그레이션 계획 검토가 필요하다.

  2. MongoDB + Prisma의 타입 불일치: Prisma schema에 Json? 타입 다수 사용 — 이는 타입 안전성 보장이 불가능한 영역이며, 데이터 정합성 문제가 잠재적으로 존재한다. challengeType, completedDate 등 핵심 필드에 명시적 타입 정의가 필요하다.

  3. SECURITY.md 부재: 루트에 SECURITY.md 파일이 없으며 외부 URL만 참조한다. GitHub Security Advisories와 연동된 공식 보안 취약점 보고 채널이 저장소 수준에서 명시되어야 한다.

  4. 클라이언트 상태 관리 복잡성: Redux-Saga와 Redux-Observable(RxJS epic)이 혼재하여 (root-saga.ts, root-epic.ts) 유지보수 복잡도가 높다. 신규 기여자의 학습 곡선을 높이며 장기적으로 단일 패턴으로 통일이 권장된다.

  5. 단일 브랜치 기반 배포: deploy-api.yml, deploy-client.yml 모두 workflow_dispatch (수동 트리거) 방식이며, E2E 워크플로우도 workflow_run 연동이 주석 처리되어 있다. 완전 자동화된 프로덕션 배포 파이프라인 구축이 미완성 상태이다.
