진입점 독립 실행 스크립트 방식: helpers/transcribe.py, helpers/transcribe_batch.py, helpers/pack_transcripts.py, helpers/timeline_view.py, helpers/render.py, helpers/grade.py. 각 스크립트에 if __name__ == "__main__": main() 구조. LLM 자체가 조율자(orchestrator) 역할을 하며 스크립트를 직접 쉘 호출. main() 분리가 잘 되어 있어 단독 실행과 모듈 임포트 모두 지원. render.py가 grade.py를 동일 디렉터리에서 상대 임포트(try/except 처리됨).

1. 목적 및 범위 (Purpose & Scope)

video-use는 Claude Code, Codex, Hermes 등 쉘 접근 가능한 AI 에이전트에서 동작하는 대화형 비디오 편집 스킬이다. 사용자가 원시 촬영본 폴더를 가리키고 "launch video로 편집해줘"라고 요청하면 에이전트가 전체 파이프라인을 실행해 edit/final.mp4를 생성한다.

핵심 혁신: LLM은 영상을 "보지 않는다." 대신 ElevenLabs Scribe의 단어 단위 타임스탬프 트랜스크립트(~12KB 텍스트)를 읽고, 의사결정 지점에서만 timeline_view(필름스트립 + 파형 PNG)를 생성해 시각 정보를 보충한다. 이는 프레임 덤프 방식(~45M 토큰)과 비교해 극적으로 효율적이다.

적용 분야: 토킹헤드, 몽타주, 튜토리얼, 인터뷰, 트래블 영상 등.

4. 아키텍처 분석 (Architecture Analysis)

파이프라인

[원시 영상]
    │
    ▼
transcribe_batch.py  ──→  transcripts/<name>.json  (캐시, 불변)
    │
    ▼
pack_transcripts.py  ──→  takes_packed.md  (LLM 주 입력, ~12KB)
    │
    ▼
[LLM 추론] ─── timeline_view.py (온디맨드 드릴다운)
    │
    ▼
edl.json  (LLM이 생성한 편집 결정)
    │
    ├─ grade.py (per-segment 색보정)
    ├─ render.py (추출 → concat → overlay → 자막 → loudnorm)
    └─ [병렬 서브에이전트] → animations/slot_N/render.mp4
    │
    ▼
self-eval (timeline_view on rendered output, max 3회)
    │
    ▼
final.mp4 + project.md (세션 메모리)

핵심 설계 패턴

  1. LLM-as-Orchestrator: 에이전트가 제어 흐름을 소유, 헬퍼 스크립트는 순수 I/O 변환기.
  2. Immutable Transcript Cache: 동일 소스 변경 없으면 Scribe 재호출 없음. 결정론적 아티팩트.
  3. Hard Rules 12가지: 자막 최후 적용(Rule 1), 오디오 페이드(Rule 3), PTS 시프트(Rule 4), 출력 타임라인 오프셋(Rule 5) 등 — 렌더링 정확성의 불변 제약.
  4. Parallel Sub-Agents: 다중 애니메이션 슬롯을 Agent 툴로 병렬 실행, 전체 시간 ≈ 가장 느린 슬롯.
  5. Self-Eval Loop: 렌더된 결과물을 LLM이 재검증 후 사용자에게 공개.

강점 (Strengths)

  1. 혁신적인 토큰 효율 설계: 프레임 덤프 없이 텍스트 트랜스크립트(~12KB) + 온디맨드 PNG로 LLM이 영상을 편집. 45M 토큰 문제를 수천 토큰으로 해결.

  2. Hard Rules 기반 정확성 보장: 자막 최후 적용, 30ms 오디오 페이드, PTS 시프트, 불변 트랜스크립트 캐시 등 12가지 비가역적 규칙이 코드와 가이드에 이중으로 명시되어 조용한 실패(silent failure)를 방지.

  3. Self-Eval 루프: 사용자에게 미리보기를 보여주기 전 LLM이 렌더된 출력을 직접 검증(시각 점프, 오디오 팝, 자막 가시성 등). 에이전트 기반 시스템의 드문 자가 품질 보증 구조.

  4. 병렬 서브에이전트 애니메이션: 여러 애니메이션 슬롯을 Agent 툴로 동시 실행하여 전체 생성 시간 최소화. HyperFrames/Remotion/Manim/PIL 간 엔진 선택 자유도 제공.

  5. 풍부하고 실용적인 운영 문서: SKILL.md가 LLM의 운영 매뉴얼로서 안티패턴, 편집 기법, 색보정 원리, 애니메이션 타이밍 규칙까지 실제 프로덕션 경험에서 도출된 내용으로 가득 차 있어 에이전트 동작의 일관성을 높임.

위험/개선 필요 사항 (Risks & Improvements)

  1. 자동화 테스트 전무: 헬퍼 스크립트에 단위/통합 테스트가 없다. grade.py의 auto-grade 로직, pack_transcripts.py의 phrase 그루핑, render.py의 SRT 타임스탬프 계산 등은 회귀에 취약하다. GitHub Actions + pytest + ffmpeg 모의 픽스처 구성을 권고.

  2. librosa 의존성 선언 불일치: pyproject.toml에 librosa가 선언되어 있으나 timeline_view.py는 실제로 stdlib wave를 사용한다. 불필요한 무거운 의존성(LibROSA ~ 수십 MB)이 설치될 수 있음. 제거 또는 실제 사용으로 교체 필요.

  3. 외부 바이너리 버전 고정 없음: ffmpeg, ffprobe, yt-dlp에 버전 제약이 없어 업스트림 변경 시 필터 체인 호환성 문제가 발생할 수 있다. install.md에 최소 버전 명시 및 설치 시 버전 검증 스크립트 추가 권고.

  4. 단일 외부 API 의존(ElevenLabs): 트랜스크립션 전체가 ElevenLabs Scribe API에 묶여 있어 API 장애, 가격 변동, 할당량 초과 시 파이프라인이 완전히 중단된다. --offline 모드(로컬 Whisper)나 대체 공급자 인터페이스 추가를 고려할 수 있다.

  5. 보안/기여 정책 문서 부재: SECURITY.md, CONTRIBUTING.md, 이슈 템플릿이 없어 외부 기여자와 보안 연구자가 접근하기 어렵다. 오픈소스 생태계 성장을 위한 최소한의 커뮤니티 파일 추가 필요.

도입 권고 (Adoption Recommendation)

기술 도입 관점: AI 에이전트가 영상 편집을 대화로 수행하는 새로운 패러다임을 탐색하는 팀 또는 개인에게 적합하다. 토큰 효율 설계와 Self-Eval 루프는 에이전트 기반 멀티미디어 워크플로우의 우수 사례 참고 자료로 활용 가치가 높다.

아키텍처 벤치마킹 관점: LLM-as-Orchestrator + Immutable Cache + Self-Eval 삼중 조합은 AI 파이프라인 설계에서 재사용 가능한 패턴이다. 동일 원리를 다른 미디어(오디오 편집, 이미지 시퀀스)에 이식할 수 있다.

프로덕션 도입 주의사항: - 현 상태(v0.1.0)는 개인/소규모 팀의 실험적 사용에 적합. 엔터프라이즈 환경에는 테스트 자동화, API 폴백, 버전 고정, 컨테이너화 후 도입을 권고. - ElevenLabs 유료 API 의존을 비용 구조에 반드시 반영해야 함. - 컨트리뷰션을 위해서는 CONTRIBUTING.md와 CI 파이프라인 정비가 선행되어야 한다.

보안 검토 관점: subprocess 리스트 방식으로 커맨드 인젝션 리스크는 낮다. API 키 관리도 기본 수준은 충족. 그러나 공식 취약점 공개 정책(SECURITY.md)과 의존성 자동 업데이트 부재는 개선 필요.

종합 판정: ⚡ 탐색적 도입 권고 — 혁신적 아이디어와 실용적 설계를 갖춘 초기 프로젝트. 자동화 테스트와 커뮤니티 인프라를 보완하면 프로덕션 적용 가능성이 크게 높아진다.
